# 回放接缝精度与通道快照修复

## 根因与处理

- 通道刷新在异步查询统计前发布了新列表，读取其他尚未补全的条目会触发 recording KeyError。现在私有副本补齐所有字段后一次性发布；刷新失败保留旧快照。
- 录制起点曾被截为整秒，文件名也只保存秒；扫描器将此起点与毫秒媒体时长相加，会生成不足一秒的假缝和重叠。新文件名使用 YYYYMMDD_HHMMSS.mmm，记录内容时间映射得到的毫秒起点。旧名字继续兼容。重启后的重名检查仍保留，绝不覆盖旧文件。
- API 新增 startPrecisionMs，由文件名格式确定，不改历史数据库时间。前端仅对同一通道两个秒精度旧段、没有已知丢弃标记、间隔不足一秒的接缝作显示合并。新段只容忍不足两毫秒的舍入误差。大缺口和丢弃标记继续保留。
- 显示合并不修改跳转目标、文件时长或 SEI 范围。旧文件已丢失毫秒信息，无法从旧索引证明所有亚秒间隙是否真实，因此这是明确限定的精度容差，不是补造录像。绿色图例提示说明此规则。
