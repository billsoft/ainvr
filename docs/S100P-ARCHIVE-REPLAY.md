# AINVR prepared archive replay

ReplayPreparedArchive connects ArchiveSpool delivery with acknowledged ArchiveMongo upsert. A caller-supplied record limit bounds each pass; limit zero does nothing. A failed delivery throws and leaves the current/later records pending. One replay coordinator should own each spool; channel deletion/retention policy must be applied before replay. This helper deliberately does not hide retries, shutdown or scheduling in a background thread.

Run python3 test/ai_port/verify_archive_replay.py. The test uses an actual YOLO-produced JPEG and a new application-owned Mongo test collection. Four separate processes exercise: (1) durably stage and attempt delivery to an unavailable endpoint; (2) recover and write to Mongo, then call _Exit immediately after acknowledged commit, before the spool can unlink; (3) recover that pending record, verify the prior Mongo commit, replay once and ensure there is still exactly one record; (4) reopen again and confirm an empty spool and exact BSON metadata/binary images.

Evidence: test/results/archive-replay-20261011_181958_335695/summary.json. All four stages passed. Mongo collection test_replay_20261011_181958_335695 retains one test record. Stage 2 exits with the intentional code 23 without C++ destructors. Pending counts are 1,1,0,0 across the stages; the final database count is one. Source PTS includes a value beyond double exact-integer precision and survives the replay. Credentials were provided privately from the existing application secret, never put on the command line. Production collections and Mongo service availability were unchanged.

This verifies the prepared-record delivery/commit-removal boundary. Remaining work includes actual channel integration, pre-encoding recovery material, deletion epochs/retention, end-to-end acceptance/accounting and image enhancement. Physical power loss, arbitrary filesystem faults and a remote commit whose acknowledgement is lost were not injected. Duplicate-ID upsert is the intended protection for ambiguous delivery outcomes, but this test only injects exit after an observed acknowledgement.
