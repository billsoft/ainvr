# 逐帧识别归档

## 产品约定

归档开启时，每个有目标的推理帧逐目标接收，保留识别信息和截图，并按接收时的配置完成投影、亮度与适用的人脸增强。处理/存储压力通过本通道反压降低实际推理速度。用户关闭归档后不接收新的任务；已接收任务继续处理。历史上限仍采用滚动删除。

## 流水线与资源

推理循环先等待本通道队列空位及两帧截图额度，再选择最新源帧；在推理前根据源分辨率申请通道保留额度。所有保留额度之和最多 384 MiB，申请不足明确报错，不等待其他通道归档。已有帧对象保持额度所有权，正常关闭写线程后释放保留额度。

推理结果打入 SEI 后进入归档。后台工作池执行投影、亮度、人脸增强与编码；写线程批量写 MongoDB，并与下一批准备并行。每次重试保持原 ObjectId 和 image_id，写入使用幂等 upsert。GPU、CPU、磁盘仍是共享资源，额度隔离并不等于物理资源隔离。

旧 min_interval_ms 字段仅用于加载兼容，始终归一为 0；新 API 拒绝非零。运行路径没有采样分支和队列满丢弃分支。区域裁剪按输出大小限制每批目标数，大幅扩边的正方形直接映射到有限大小的输出，避免先分配超大的扩边图。

## 故障与持久性

MongoDB 断开时独立线程将任务暂存，只有文件和目录同步成功才释放其内存副本。暂存有容量限制，空间不足保持任务并反压。慢写保持现有批次，不自动对同一磁盘无限追加溢写。

截图下载失败会重试同一帧，直到恢复或操作员明确停止/关闭。无效坐标和不支持的配置单独报错。处理失败经过有限重试后，只有隔离保存成功才移出批次；隔离失败继续保留原任务重试。配置要求的亮度/增强失败不再假装已成功处理。

已落盘隔离文件保留原图及任务处理配置。修复原因后，在 AI 停止时由维护人员检查指定文件，再将有效 `.cbor.bad` 恢复为 `.cbor` 进行重放；损坏文件不能当成有效图片恢复。删除规则仍优先于重放，避免恢复被用户删除的历史。

正常停机保存待写任务；存储不可写时保留内存并告警。突然断电、强制终止以及停止超时会突破内存持久性边界，不能以本设计宣称绝对零丢失。

## 可观测性

delivery 账目按稳定 image_id 跟踪 queued、preparing、writing_mongo、pending_disk，并记录最老任务等待时长。终态区分 committed、quarantined、deleted。仅首次接收/载入计数，重试不重复接收；满足 accepted = outstanding + committed + quarantined + deleted。进程重启重新计数，旧隔离文件另外通过 quarantined_bytes 显示。

该账目覆盖已取得有效像素并接收的任务，不能替代截图失败、无效坐标的错误计数。MongoDB 确认与文件移除之间断电后仍可能重放，但 ID 不变，不产生重复记录。


## 故障可见性与源帧统计

- `archive_stats.faults` 按截图、图像处理阶段提供当前错误和持续秒数；首次失败即可查询，阶段恢复后清除该阶段错误。模型预加载失败也进入此状态。`healthy` 表示当前处理是否存在故障；`has_quarantined_data` 单独表示历史隔离文件待处理，不能用通道仍在推流推断归档健康。
- 识别历史页面显示归档错误、持续时间和隔离告警。已接收任务继续保留；不通过自动重启、降为抽样或超时丢弃来恢复帧率。
- `archive_backpressure_skip_count` 单独计数等待归档容量时被新帧替代的源帧，启动及序号变化按实际跳过数量封顶。这些源帧尚未推理，不是已识别结果丢失；总跳帧为抽帧、过载、归档反压三项之和。
- 裁剪批次超过输出预算时缩小同一帧的批次并重试，其余目标仍逐个处理；单目标异常保留故障告警和反压。存储永久不可写时不能同时承诺有限停机时间和内存任务无损；强杀/断电仍可能丢失尚未持久化任务。
