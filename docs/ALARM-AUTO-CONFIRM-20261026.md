## Policy

- Newest eligible unreviewed alarm first; existing waiting-validation alarms are
  re-inferred once for the new authorization, never bulk-relabelled from old scores.
- Current deployed Qwen3-VL package, target-crop-v1, caller prompt
  target-context-zh-v3-border, task alarm-review-zh-v1, and label `person` only.
- Balanced multi-frame policy: at least one required real keyframe must score
  0.99; every required frame must score 0.95. A rule with a stricter approval
  threshold raises both floors as needed. Single-frame evidence still needs 0.99.
  Scores are not calibrated probabilities. Without minimum_frame_score configured,
  the original every-frame 0.99 behavior remains the default.
- Automatic confirmation only. Suspected false positives, ambiguous results,
  incomplete evidence, unsupported labels/models stay unreviewed for humans.
- Geometry continues to use the production rule-engine proof. Model review
  verifies the target class, not physical collision or independent video reasoning.
- Human decisions and evidence-generation changes retain their atomic write fences.
- Operator authorization is checked again after inference. Revocation takes effect
  on the next check; a database commit already completed is not retroactively undone.
- No inference is added to the alarm-ingestion path; no recorder, AI detector or
  streaming service restart is required.

## Deployment authorization

The root-owned file `/etc/ainvr/review-authorization.json` has schema
`ainvr.review-authorization.v1` and fields: `enabled`, `mode: confirm_only`,
`model_sha256`, `layout`, `prompt_template`, `caller_template`, `labels`,
`approve_above`, optional `minimum_frame_score` (default: approve_above),
`authorized_by`, `authorized_at`. minimum_frame_score cannot be below 0.95 or above
approve_above; changing it changes the authorization fingerprint and rechecks pending
reference-only alarms once. Already reviewed alarms are preserved.

The worker reads it on each job. It must be a regular non-symlink file, no larger
than 16 KiB, owned by root and not group/world writable. On this board use root:
sunrise 0640 so the sunrise service account can read it. It contains no credentials.
Change it atomically. The authorization fingerprint is retained with each decision
and its audit log. Changes in model, input layout, prompts or label scope fail closed.

To stop all operator-authorized confirmations, set `enabled: false` atomically
or rename the file to a backup path. This does not delete any alarm or undo already
completed reviews. Disabling a trigger's AI-review checkbox controls subsequent
alarms from that trigger; it does not rewrite old alarm-policy snapshots.

The authorization file is deliberately not generated by the generic installer.
Other deployments stay in reference-only mode unless separately authorized or
qualified with a signed validation report.
