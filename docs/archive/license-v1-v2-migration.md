# 历史 v1 → v2 迁移记录

仅用于维护历史版本；不能用于当前 v3 的签发、升级或验收。当前步骤见 `docs/deploy/INSTALL-FROM-SCRATCH.md` 第 6 节。

### 历史 v1 → v2 迁移参考（不能直接作为 v3 部署步骤）

1. 维护窗口冻结旧业务和旧授权服务，保存旧二进制、配置、三份状态、签发记录和哈希；不停止 PostgreSQL/管理面。
2. 读取新版申请码。人工核对新旧申请码、旧 chip_uid、实物板卡、购买记录属于同一设备。
3. 厂内使用旧主密钥认证旧状态，按可信厂内当前时间和旧已用时间保守计算剩余完整分钟：

       python3 tools/license-keygen/migrate_v1.py --legacy-v2 --state <旧主状态副本> --chip-uid <旧绑定值> --old-code <旧申请码> --code <新版申请码> --legacy-secrets <旧厂内密钥目录>

   工具不会修改板端状态。按旧设备记录唯一迁移回执，重复调用返回原注册码，不能换一个旧状态快照重新领取时长。原格式没有可靠激活起点时只能按旧字段保守计算；损坏/已过期状态须人工核对购买记录后按授权流程处理，不能自动补发全部时长。
4. 把旧运行状态移到只读归档，保留原内容和哈希，完成 v2 供应及全链路更新后录入迁移码。不要直接将副本覆盖主状态，也不要混用 v1/v2 状态。
5. 保留回滚备份；已启用 v2 后直接回滚旧程序可能恢复旧授权，因此回滚须同时核对台账、用时和现场业务状态。
