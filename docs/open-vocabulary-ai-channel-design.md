# 开放词汇 AI 通道接入与重构设计

状态：部分实现。2026-10-10 已上线开放词汇高速（YOLOE-26x）与高级（LocateAnything-3B）两条路径，实际契约以 [实施文档](open-vocabulary-implementation.md) 为准。本文的模型能力目录接口、异步加载状态、逐帧结果集合、20 秒发布延迟（实际为 40 秒）等仍是设计，尚未实现。

## 1. 目标与范围

在现有 AI 通道中增加开放词汇模型，作为固定类别模型的低频补充：用户指定目标描述，得到标准检测结果、原图截图和按配置处理的截图，按需要通过带 SEI 的 AI 输出流播放/录像。识别素材可供后续审核、标注与训练使用。

产品统一使用“开放词汇”，它指通过文本描述查找目标，与“开源模型”不是同一概念。

本期范围：

- 模型分为固定类别（封闭词汇）与自定义描述（开放词汇），创建和编辑按能力显示不同控件。
- 一个开放词汇通道配置一个描述和一个稳定标签。多描述轮询、跟踪、分割和自动训练留作后续功能。
- 第一种开放模型为已经验证的 LocateAnything-3B，固定单图 448×448、慢速自回归、384 token 上下文。
- 支持小数 FPS 与“每 N 秒识别一帧”的等价交互；慢模型不积压无限的视频帧。
- 归档开启时，每个完成且有效的推理结果按契约保存，有目标的每个目标均截图归档；写不动时反压对应通道下一次推理，不改成每秒仅存一帧。
- 低频模型不直接替换现有高速检测器，未经共存测试不能承诺两路现有 AI 加 3B 同时运行。

## 3. 模型能力目录与 UI

### 3.1 目录作为能力权威

新增 AI 服务鉴权接口 `GET /api/v1/models`，控制台通过具名代理访问。每种模型返回：

- 模型稳定 ID、名称、`vocabulary_type: closed | open`、任务类型；
- 是否需要描述、是否提供 confidence/landmarks、是否允许 NMS 阈值；
- 输入尺寸/缩放策略、推理方式、可选频率范围、建议间隔；
- 安装/验收状态、资源需求与是否允许延迟输出；
- 模板版本、产物 manifest 验证状态；不向浏览器返回内部绝对路径或服务令牌。

分类由服务端模型描述符决定，客户端选择不能把一个封闭模型声明成开放模型。旧配置缺分类时，通过已知 adapter 映射为 closed，不更改原通道。

不存在引擎或 manifest 不匹配时显示“未安装/需要准备”，禁止启动；网页不得统一声称 3B 首次编译只需 1～5 分钟。3B 使用预构建的独立模型材料，不能在生产点击下一步时启动重编译。

### 3.2 向导第二步

| 控件 | 固定类别模型 | 开放词汇模型 |
| --- | --- | --- |
| 模型类型 | 固定类别 | 自定义描述 |
| 模型选择 | 现有预设 | 已安装且已验证的开放模型 |
| 识别描述 | 无 | 必填，例如 `a backpack` |
| 保存标签名 | 保持模型固有类别 | 必填，例如“背包” |
| 稳定标签标识 | 模型既有类别身份 | 首次生成或选择，例如 `backpack`；有历史后不可随意改变 |
| 推理频率 | FPS，包括小数及原来的 0 跟随 | 默认“每 15 秒识别 1 帧”，可切为 FPS；禁止 0 跟随源流 |
| confidence 阈值 | 按现有能力显示 | 3B 不提供，隐藏并说明“本模型不提供评分” |
| IoU/NMS | 按模型能力显示 | 本期不默认追加未经验证的 NMS，不显示无效滑块 |
| 最大目标数 | 原规则 | 与生成 token 上限、结果完整性限制一起校验 |
| 资源说明 | 现有描述 | “低频辅助识别；帧率由计算和保存速度共同决定” |

第三步输出区域增加“含识别信息的延迟输出”，明确源流仍保持直播，只有这个 AI 派生流延迟。显示预计延迟与缓存需求。普通快速模型保持现有输出默认值。

识别历史、AI 通道卡片、配置中心、导入/导出必须使用同一能力规则。开放模型没有评分时，不能让历史页面的评分筛选把所有记录排除；混合列表要显式区分“无评分目标”，不伪造 0 或 100%。

## 4. 描述与稳定标签：消除“背包/行囊”歧义

配置将三个概念分开：

```json
{
  "inference_fps": 0.06666666666666667,
  "grounding": {
    "description": "a backpack",
    "label_id": "backpack",
    "label_name": "背包",
    "revision": 1,
    "max_new_tokens": 64
  }
}
```

这是拟新增的配置片段，当前服务不能直接接受 `grounding`。模型 adapter 建议命名 `locateanything_trt`，类型由模型目录确定。

- `description` 是给模型查找目标的自然语言，使用已验证的定位模板拼装，不是任意聊天指令。
- `label_id` 是业务匹配键，跨通道复用同一语义时显式选择同一 ID；不依赖中文名称、模型输出 ref 或通道名。
- `label_name` 是网页和保存的展示名称。无论模型输出 backpack、背包或行囊，规范化检测记录都使用配置的“背包”。
- 原始 ref/text 单独保存，不能覆盖稳定标签。协议异常/多 ref 等需记诊断，不能悄悄当多类输出。
- 单查询第一期的 `class_id` 可用查询内索引 0，但它不代表 COCO 的 person；全局身份使用 `label_id`，消费者须认识模型/词汇类型。
- 修改描述产生新 revision，老素材保留原 description/revision；对标签重命名保留旧记录当时名称和稳定 ID。
- 改变真实语义，例如背包改成箱子，应创建新标签/查询版本，不能把旧背包样本悄悄算作箱子。

描述空白、协议特殊标记、过长输入、非法 token 预算必须在接收前拒绝。先设置合理 UTF-8 长度上限，再用实际 tokenizer 检查 `prompt_tokens + max_new_tokens <= 384`，不能只按字数估算。中文描述目前未验收，页面提示效果需验证；不自动引入在线翻译服务。

## 5. 频率与抽帧：一个配置、两种显示

### 5.1 语义

| 用户选择 | FPS | 两次取帧的目标周期 |
| --- | ---: | ---: |
| 每秒 2 帧 | 2 | 0.5 秒 |
| 每 10 秒 1 帧 | 0.1 | 10 秒 |
| 每 15 秒 1 帧 | 1/15 | 15 秒 |
| 每 30 秒 1 帧 | 1/30 | 30 秒 |

只持久化现有 `inference_fps`，UI 秒数换算 `1 / fps`，避免 fps 和 interval 两份配置互相冲突。支持浮点输入，格式显示保留有效数字；低频实际值优先显示“平均每 N 秒一帧”，不能 `.toFixed(1)` 把 0.067 显示成 0.1 或 0.00。

为间隔模式设置明确范围，例如 1～3600 秒；服务端和前端一致校验 finite/范围。开放模型不允许 0，封闭模型保留 0 的原语义。实际共存试验之前推荐 15 秒，0.1 是上限目标的例子，不保证 10 秒一定完成一帧。

### 5.2 调度规则

用单调时钟与可中断条件变量代替长 `SleepMs`，stop、授权失效、配置修改均 notify。醒来重读配置。热更新频率只改变下一次任务准入，不重载权重或重启推流。

每路最多一帧在执行；不能把直播帧排成需要几分钟追赶的队列。满足时间、推理资源及归档额度后才选最新帧。帧未进入推理的跳过属于计划抽帧/资源等待/归档反压，分别统计；已完成推理的结果不可用采样逻辑丢掉。

单帧超过目标周期时，完成当前帧后再选最新帧，丢弃过期调度债，不并发堆请求。目标为 10 秒，实际耗时 12 秒时大约 0.083 FPS；不能把 UI 目标值当实际性能。

统计保留目标/实际频率、完成数量、计划跳帧、计算/资源等待、归档反压跳帧。对低频模型扩大观察时间尺度，预热和一两帧样本不足时显示“统计中”，不能立即报警或显示 0 FPS 故障。

## 6. 推理边界与 LocateAnything 子类

### 6.1 统一任务接口

增加 `InferenceRequest` 与 `InferenceResult`，表达原帧身份、输入契约、查询 revision、模型输出和诊断。由模型能力定义预处理、输出解析，而不是通道 worker 继续增加 adapter 字符串分支。

旧适配器用桥接实现新任务入口，内部仍使用现有 GPU 预处理 + RunPrepared + Postprocess；先保持所有闭集模型像素/结果回归一致。

新增 `LocateAnythingTrtAdapter` 子类：

1. 验证 manifest、引擎/权重版本及 38 个推荐引擎和 embedding；
2. 声明固定 RGB、448×448 直接缩放、`pixel / 127.5 - 1` 的本轮输入契约；
3. 构造固定模板，注入查询描述与 256 个视觉 token；
4. 完成视觉、36 层缓存自回归、输出头与贪心 token 选择；
5. 检查 finite、EOS、协议和坐标，映射到原帧 xywh；
6. 以稳定标签封装公共结果，不使用不存在的目标分数；
7. 返回模型耗时、生成量、解析状态和原始回答供诊断/留档。

本期固定缩放沿用已验证原型，不擅自套用 YOLO 的 letterbox、`/255` 或 NMS。更换成保持比例、分块或高分辨率前必须和原处理器对照验证。2:1 全景图片经方形缩放会改变比例，框仍映射回原图；截图的 ERP 投影属于后续归档处理，不改变本期推理输入契约。

### 6.2 隔离运行器与常驻复用

第一期建议子类通过本机受限 Unix socket 调用专用 Python/TensorRT 运行器，复用本轮已验算代码；不在 C++ 服务里嵌入 Python，也不为每帧启动一次脚本。

运行器是实现组件，不是另一套通道管理/授权/归档服务。AI 主服务统一管理通道、授权、结果与生命周期，运行器只执行受限任务。单实例模型、一任务并发、请求大小限制、socket 权限、peer 校验、超时/取消、限速重连和停止行为必须实现。

第一版跨进程输入可用小图二进制 RGB（448×448×3 约 0.6MB），由运行器进行与基线一致的归一化；需核对 CPU/GPU 缩放像素差。GPU IPC 属后续优化，不能以未经验证的零拷贝实现阻塞本期。

模型尽量在任务间复用，但是否能同时常驻视觉、解码、输出头要测峰值后决定；保留按需加载视觉等分阶段策略。KV 缓存在每个新请求重置，不能串入上张图片。输出头归一化 FP32、对齐 FP16 的修复保留。

加载/预热状态异步返回，不能让创建通道 HTTP 等待 30 秒超时后误认为失败；现有 Start/init 30 秒路径要改为“初始化中→可运行/失败”。推理进度另报，控制平面健康不因 10 秒模型阻塞。

### 6.3 帧所有权与取消

准入时复制必要的小图和归档需要的原帧到通道独占、受额度限制的内存，释放解码/GPU 映射，再开始长推理。不能把 NVMM 解码池帧注册持有十几秒。

8K RGBA 原帧约 118MiB；多开同源通道会增加复制和缓存。必须纳入独立额度与总资源准入，不直接提高全局预算或占用其他通道已承诺的额度。后续可研究保留 NV12/压缩帧以降低原帧占用，需另验转换和解码开销。

归档接收独立 CPU 帧来源，复用现有裁剪、ERP、亮度、JPEG、原图保存与待重放逻辑；不得回头裁剪“当前最新画面”冒充十秒前的推理帧。

源重连/模型配置变化时，已完成结果仍按原 stream epoch、frame ID、query revision 保存；不能因源换了就丢掉有效识别素材。旧结果不打到新 generation 的视频上。取消未完成请求、截断/解析失败进入明确失败状态，有需要保留原图和失败记录；不得发出假的 `det:[]`。

## 7. 统一 JSON、Mongo 与素材

### 7.1 兼容扩展

公共结果升级 schema 1.3，保留既有 xywh、帧 PTS、模型与 timing 字段。Detection 的 confidence 改 optional/null（闭集保持数值）；新增稳定 `label_id`。`model_extra.grounding` 保存查询 ID/revision、描述、raw ref/response、模板版本、完成/解析状态，避免每个消费者独立猜测模型结构。

拟定结果片段：

```json
{
  "schema_version": "1.3",
  "task_type": "object_detection",
  "detections": [
    {
      "class_id": 0,
      "label_id": "backpack",
      "class_name": "背包",
      "confidence": null,
      "bbox": {"x": 110, "y": 82, "w": 75, "h": 102}
    }
  ],
  "model_extra": {
    "vocabulary_type": "open",
    "grounding": {
      "description": "a backpack",
      "revision": 1,
      "template_version": "locateanything-single-image-v1",
      "complete": true,
      "parse_status": "valid"
    }
  }
}
```

这是结构示例，坐标不是实测背包结果。观察时间（取帧）与完成时间分开，历史时间用原帧观察时间；不能用十秒后的完成墙钟冒充原图拍摄时刻。PTS、frame index、epoch/request ID 要贯通请求、归档与输出。

YOLO 数值分数原样保留；不能把 3B confidence 设置 1.0、0.0 或用 token 概率/生成速度假充目标置信度。排序、阈值筛选、Mongo 序列化、旧记录读取、UI/SEI 均先支持 null。服务端原“按名称猜人脸任务”的启发式对开放模型禁止，task_type 由模型能力明确声明。

### 7.2 不丢完成结果

归档开时：

- 所有完成且有效的推理帧保存规范结果/身份/描述版本；空目标帧保存帧结果，无需生成不存在的目标截图。
- 有目标时全部生成目标截图，按配置做投影、亮度及允许的增强，并保存原始图与处理图。
- 完整结果与目标图使用稳定 ID 幂等重放，逐帧与逐目标账目区分；无目标、失败、截断不能混成同一个成功状态。
- Mongo/处理慢时，在下一帧准入之前反压这一路；本地暂存仍有容量与错误上报，不无限占内存/磁盘。

现有库以每个目标截图为记录，不能直接把空帧文档混入同一查询导致计数/分页错乱。新增按帧的结果记录（建议独立 `frame_results` 集合，以 channel/request/frame identity 索引），与已有截图通过 frame_result_id 关联。分阶段幂等写入+完成状态，恢复重试时验证全部目标保存；不默认依赖本机 Mongo 副本集事务。

逐帧记录同样有限额和滚动删除，删除/清空/删除通道要覆盖帧结果、截图、待重放/隔离和可选素材，不能形成孤儿。旧历史保持原查询语义，PG 仅存配置和版本，Mongo 存结果与图像。

素材初期作为“待审核样本”，不能把生成模型输出直接当人工真值。原始截图供训练/复核，增强图供查看，两者区分；可选保留原帧以支持后续完整图像标注，但要单独计费空间和滚动清理。全景框、ERP 投影截图与普通目标训练坐标不能混用。

归档开关关闭后不接收新归档，已接收任务做完；推理/SEI 照常。已开始任务使用其捕获时归档约定与查询版本，避免关闭/热改时把结果消失在账目外。

## 8. 慢结果 SEI：时间对齐是必要设计

### 8.1 为什么原逻辑不够

现有默认 max delay 3 秒，结果约 10 秒后才到，原 AU 已发送，`stamp` 会 too_late。不能把延迟只改到 20 秒却继续使用 0.1 秒起步自适应控制器：第一批结果依然来晚，而且缓存年龄/容量/压力放行也要一起调整。

也不能把旧结果写到最新 AU 后按最新画面绘制。它虽然“有 SEI”，但框在错误的人/物上，违反原帧身份契约。

### 8.2 本期选用：独立派生流的有界固定延迟

开放通道启用推流时用 `delayed_exact` 策略：先加载预热，再启动该路独立派生流；压缩 AU 有界保存，选中的帧在结果完成后按原 PTS/generation 注入，所有 AU 按原顺序、DTS/PTS 发送，视频帧率和编码不变。

给慢模式单独配置推理 deadline、发布延迟、最大缓存字节/帧数/年龄及资源预留。发布延迟必须大于允许的结果时限和注入余量；初始工程验证可用 15 秒推理时限、20 秒输出延迟，最终值以热态/共存 p95 和尾延迟测量确定，不能从单图结果保证一定足够。

20 秒压缩数据的纯载荷估算：

| 源码率 | 20 秒纯载荷 | 说明 |
| --- | ---: | --- |
| 20Mbps | 50MB，约 47.7MiB | 还需突发/结构/SEI 余量 |
| 90Mbps | 225MB，约 214.6MiB | 默认 256MiB 缓存余量很小，不能直接批准 |
| 100Mbps | 250MB，约 238.4MiB | 同上，配合更大时限时需更多资源 |

使用真实峰值码率及安全系数准入，不只用平均。缓存也计入 3B/原帧/归档资源预算；超预算明确拒绝这个输出组合，不能通过丢 GOP 来维持名义上的“正常”。不得为了该模型修改全部快模型的延迟。

超过 deadline 的请求取消/报错并保留相应失败信息；派生视频按策略继续无检测结果地发送，不伪造空目标判断，不阻塞 SRS。极端磁盘/GPU/网络故障下无法保证任意晚的结果仍注入已发出的帧，必须显示 SEI 未送达计数，保存已经完成的结果，并对后续任务反压/熔断。正常验收范围要求注入失败为零。

发布启动缓冲期、停止 drain、源重新发布、PTS 回绕、GOP 与 watchdog 均需适配；现在约 5 秒的无产出判断不能把 20 秒正常初始化缓冲误当卡死。停止期间有截止时间且回报已接收结果交付状态，不能在 HTTP 管理锁里排空数十秒。

### 8.3 紧凑 SEI 与显示

扩展现有 UUID 内 JSON：检测 `p:null`、短稳定标签字段（例如 `l`），信封包含版本、query revision、是否完成/是否截断、源帧身份；不把整段 raw response 和长 prompt 放入 1024 字节默认载荷。

消费者先升级，再启用新模型。闭集旧数据继续解析；可空 p 不转为 0。SEI 超预算必须标示总数/已携带数/truncated，完整结果仍归档，不把完整 Mongo 数据的要求误当有限 SEI 必须装下任意数量的框。

实时、普通回放、360 回放共用现有解析/坐标逻辑。标注属于采样帧及现有短保持窗口，**不能为了十秒才检测一次就把静态框挂十秒**。页面增加“上次识别时间/结果截图”，让用户在低频下查看结果，但截图卡不冒充当前直播检测。

## 9. 热更新与生命周期

| 设置 | 生效时机 | 是否重载模型/重启推流 |
| --- | --- | --- |
| FPS / 间隔 | 唤醒调度器，下一次准入；执行中请求不并发补发 | 否 |
| 描述 | 新 revision 在下一任务生效；在途结果带旧 revision | 否，清该请求缓存并重新 prefill |
| 展示标签名 | 下一任务快照生效，历史旧值可追溯 | 否 |
| 稳定 label_id | 有历史后禁止直接改语义 | 通过新增标签/明确迁移 |
| 归档开关、亮度/投影等热参数 | 依现有门控，已接收任务保留自己的配置快照 | 不重启通道 |
| 模型/引擎版本、输入契约 | 正常停止/保留已接收结果后重建该通道 | 需要重新准备模型 |
| 延迟输出与缓存策略、输出目标 | 在安全切换点重建该派生会话 | 需要，清楚告知录像切换点 |

配置持久化继续走 PG 配置版本和现有 overlay 合并流程，校验/导入导出/脱敏一致。模型目录、工厂与前端 capability 不能各写一份不同的规则。

## 10. 资源准入与诊断

第一期一台板只允许一个 3B 模型实例和一个在执行请求；可增加通道订阅同一运行器，但要公平排队并保证每路至多一个已准入任务，实际总吞吐仍共享。

先测常驻/峰值 RAM、CUDA/TRT 内存、NVDEC/VIC/GPU 带宽、原帧副本、AU 缓存、归档与 swap，再决定同板共存数量。单次停服试验峰值 11.4GiB 不足以证明生产共存安全。GPU 流优先级不能保证任务隔离或抢占正在执行的 kernel。

资源不足拒绝新增任务/模型并给可读提示，不停掉既有高速通道来“自动腾位置”。提供加载中、等待资源、推理中、等待归档、正常、异常的可解释状态；后台重试有退避，控制平面独立响应。

诊断按事件变化立即记录，稳定期限频汇总：request/frame/epoch/revision、阶段时延、token 数、deadline、缓存峰值、SEI stamp 分类、归档 delivery、内存/排队。详细异常仅日志，网页用中文阶段提示。不要输出帧内容、敏感凭据或无界长描述。

## 11. 实施顺序与验收门槛

1. **协议与能力先行**：新增 catalog/配置/nullable confidence/label_id/revision；升级全部消费者和导入导出。旧闭集结果、旧 SEI 与历史回归完全一致。
2. **调度改造**：条件变量与小数/间隔 UI，单任务准入、分类统计。测 0.1、1/15、1/30、低频停止、授权失效、热改频率，不留下长 sleep。
3. **运行器与子类**：常驻、manifest、固定输入、模板、KV 重置、取消与错误分类；与已验证原型同图同描述比较 token/框，不能只看启动成功。
4. **原帧与归档**：独立帧、CPU 来源桥接、逐帧元数据、逐目标图、稳定标签、坏结果状态和幂等重放；验证关闭/打开与断库不丢已完成结果。
5. **延迟 SEI**：固定延迟缓冲/容量/watchdog/重连；H.264 与 codec12 H.265，实时、回放、360 均测试，注入在原 AU，无未来帧/旧框错贴。
6. **资源与素材验收**：先停生产做基线，然后逐路恢复做共存测试；压力样本覆盖目标数量、长描述、生成截断、90Mbps 8K 与 20Mbps 4K。
7. **部署与离线包**：业务包更新适配器/运行器/UI/协议；新 3B 模型材料独立发布，现有不变模型不重复打包。恢复并复查所有原业务产物。

关键失败测试：

- 模型输出“行囊”但配置标签“背包”：所有规范结果仍为 label_id=backpack、名称=背包，raw ref 留档。
- 提示超容量/无 EOS/格式坏/零面积框：不能伪造正常无目标，不丢已接受素材，状态明确。
- 无置信度目标：历史可查、无评分显示、阈值不误过滤、SEI 正常绘制。
- 每 30 秒一帧时停止/改频率：调度等待在 200ms 级唤醒；该指标仅针对等待，不代表 GPU kernel 能立即取消。
- 源重连发生在 3B 推理中：结果仍绑定原图归档，不进入新流缓存；epoch 不串线。
- 推理耗时 10 秒、发布延迟 20 秒：全部采样结果注入原 AU；正常缓冲期不触发无输出 watchdog。
- AU 超容量/推理超时：有限错误与计数，不让 SRS 收流停顿、不错误画框，不无限加延迟。
- 暂存满/磁盘不可写：只反压对应通道，关闭归档能放开下一次准入，已接收任务账目可追踪。
- 显式空结果清框、没有推理的 AU 不假装无目标；低频框不延长到下一次采样。
- 两路现有 AI + 3B 共存：分别测实际帧率、延迟、录像缺口、授权落盘及内存，无系统 OOM；不满足就限定运行组合。

每阶段有独立验证记录；本文件列的是计划，不把尚未运行的测试写成通过。产品目标是“可信低频补充、稳定标签、完成结果全部留存、正确时间对齐”，不是给界面增加一个模型选项就算完成。
