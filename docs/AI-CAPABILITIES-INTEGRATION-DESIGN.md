# AINVR 多模型业务能力融合设计

日期：2026-11-12。设计基线：190 开发仓 `2cfb109`。本文现已进入实施和联调；第2节保留开工时事实，第12节记录实现与验证。模型文件可加载、接口测试通过和现场准确率认证是三种不同结论。未获得本轮提交授权，不自动提交或推送。

## 1. 产品结论与取舍

沿用 AI通道 → 识别/跟踪 → 触发器和计数器 → 告警/历史 → 统计 的现有路径。新增的是业务能力，不是每个模型一个页面或一个微服务。

- 第一批：通用检测轻量/均衡档、人脸抓拍、安全帽、烟火候选事件。通用检测换档不增加同类模型重复运行；保留现有高精度档。
- 第二批：有效观测下的区域占用/人数、无人持续、禁停。先补区域状态与恢复机制，再承诺业务功能。
- 第三批：姿态适配与疑似倒地；人脸比对、关注名单和以脸检索分别按需求交付，不捆绑成一次大改造。
- 暂缓：睡岗、攀爬、排队时间、跨镜唯一人数、车辆细分类别、抽烟、反光衣。不能仅用一个姿态阈值或三个像素的香烟框冒充成熟功能。
- 不新增左侧一级导航。不增加“安全帽平台”“烟火平台”“人脸平台”。不为统计重复采集视频。
- 并发方式、采样节奏默认由运行时预算决定，复杂参数放高级配置；默认值有测试依据后才固定，不凭单模型延迟承诺多路容量。

## 5. UI融入：保持原入口，减少人工设置

实际只读查看190当前页面：1366×900的AI通道/告警触发/统计/配置，及768×1024的AI通道。内置浏览器初始化失败，改用本机Chrome自动化；未保存配置。截图在本机 `D:/rdk/ai-capabilities-20261112/`。这些截图证明现状，不是新UI验收。

### 5.1 AI通道

四步向导不变。第二步用一个统一列表，避免外层“识别模型”与列表中第一行重复编辑。用户可添加、移除、排序任何检测模型；删除被依赖的节点时显示具体影响及处理方案，不能静默删规则。

```text
模型与推理                               预计负载：待测 / 已验证档位
[通用目标·均衡] [人脸] [安全帽] [烟火] [姿态·试用]  添加能力
1 通用目标检测   均衡档       配置  ↑ ↓ 移除
2 安全帽检测     待场景验证   配置  ↑ ↓ 移除
3 人脸抓拍       质量优先     配置  ↑ ↓ 移除
  └ 人脸比对：关闭 / 选择已有人脸库（需要嵌入模型）
同标签框按列表优先级；姿态等附加信息在匹配明确时保留。
[高级：每节点频率上限、阈值、执行策略]       上一步 / 下一步
```

“能力”只是现有节点配置的友好名称，不另存一套独立开关。模型技术名、文件散列在详情中。轻量/均衡/高精度是同一行档位选择，避免用户把s+m+x都添加。允许高级用户显式多生产者实验，但提醒重复计算及当前去重策略。

人脸比对是同一能力的串联步骤，不把无框嵌入输出伪装成独立检测标签。依赖图自动生成，可查看，不能要求用户连线。初期保留最多4个显式检测节点，内置派生步骤也计入硬件预算，不绕过容量限制。

通道卡片保留名称、输入/输出、运行状态和查看结果。第二行显示“通用目标 · 安全帽 +1”；统一状态行显示“检测正常 / 人脸比对排队”，不要把整个通道显示不可达。耗时p95、丢帧、路径移到“运行详情”。服务不可达时保留最后采样时间并标为历史值。

保存反馈分为已保存→加载中→已生效；失败显示具体节点、原因和重试入口。保存前展示受影响计数器/触发器名单，取消不影响线上；旧配置和新配置的结果不得混入同一分析会话。

### 5.2 告警触发与布防

保留“告警触发”页面与现有定义→实时监看布防流程。顶部现有四种行为筛选不无限追加按钮；改为“全部 / 空间行为 / 区域状态 / 安全事件 / 名单”，子类型用下拉。旧行为和旧URL仍能定位。

新建触发器：选择对象/业务模板→条件→生效计划和审核。模板只预填同一规则结构，不另造引擎。未安装能力显示“需在通道添加安全帽检测”，链接原AI向导；不偷偷添加模型。区域仍只在原布防编辑器绘制，定义中不画第二份区域。

条件摘要必须可读：“作业区内明确检出未戴帽，持续满足条件后触发；连续恢复后允许再次告警”。不要向值班员默认展示模型ID或规则执行版本。缺能力绑定、区域变更、模型删除均显示具体受影响规则。区域人数为0与人数≥N使用不同提示，观测无效不能满足0。

安全事件阈值默认来自经过现场验证的策略包；没有验证时提供明确标注的试用模板，不把0.35写成通用标准。持续时间以毫秒与有效观测覆盖计算，界面不要求用户填写“连续几帧”。

### 5.3 告警列表与证据详情

不加第二个待办列表。原未审核/人工/AI审核页签保留，类型筛选补新业务。卡片只展示位置、事件、时间、状态、简短依据。展开详情依次为：规则/触发标准→原图及区域→目标/关键点/轨迹图层→观测时间线→审核结论→原录像。

原图与标注图可切换；区域边框及轻填充不遮挡目标；关键点层只在相关事件显示。火/烟必须显示连续图或片段，不能只给局部裁剪。人工确认/误报始终可用，AI没有该类别审核能力时明确显示“暂不支持自动复核”，不能套人员提示词。

### 5.4 识别历史与智能搜索

识别历史保留原目标列表和车辆通行；人脸抓拍通过对象筛选/子视图呈现，不新增一级导航。列表信息：最佳图、时间、通道、质量、关联告警/录像；有权限才显示身份候选。识别记录和业务事件互链但不重复创建事实。

智能搜索保留文字搜索，增“以图查找→人脸”模式。只在人脸特征索引就绪时可选。搜索范围、时间组件、结果列表和证据抽屉复用。图库未匹配、特征不可用、范围未覆盖分开显示。

### 5.5 统计分析与热区

保留客流/告警/车辆主题，第一批安全帽、烟火、倒地都进入“告警分析”的事件类型筛选，不新增一排主题和重复大屏。以后区域占用指标丰富到确有必要时才新增区域状态主题。

总览仍是紧凑KPI+趋势+大地图，地图占主空间；信息标签可开关、碰撞避让；明细通过点击下钻，不恢复右侧常驻排名表。布防区几何和统计平面图位置分离，底图居中等比缩放。多个区域的告警仅有区域归属时显示“区域事件分布”，不画虚构的区内像素热点；有真实目标坐标映射才能画点密度图层。

安全帽筛选：事件数、待审核、已审核误报占比、有效布防小时；不把未检测到帽子的人数当违规人数。烟火统计：事件数/累计持续时间/区域分布；持续事件每次只计1。人脸：抓拍次数、可用特征次数、名单命中事件；未经验证不显示“独立访客人数”。

### 5.6 系统配置

复用配置分类：AI服务内增加只读“模型能力与运行状态”；车辆关注名单保留，人脸功能上线后增加同级“人脸库与关注名单”。不要先将两者统一成万能名单表。模型版本、状态、占用、依赖、失败原因在现有运行中心集中查看。

人脸库包含库名称、成员、有效期、允许使用的通道、权限、审计、保留策略；导入图质量失败必须能纠正。更换嵌入模型显示迁移计划，不能隐式重解释旧特征。普通操作员不能从SEI或公开结果API获取人脸向量/名单全集。

### 5.7 PC / Pad 操作规范

沿用现有蓝色主按钮、白卡片、浅灰背景、字体层级。PC紧凑筛选栏，Pad自动换行；编辑/排序/删除触摸区域至少44px，拖动之外保留上下移。侧边栏Pad收起，表格变信息卡但保留同一操作顺序。弹窗右上角关闭、取消、Esc遵循相同草稿策略，保存错误保留输入。颜色之外使用图标和文本区分“未知/异常/就绪”。所有新页面不得依赖hover。

## 6. 后端架构：最小必要重构

```text
已有源解码帧/租约/PTS
  → 现有硬件缩放及模型单例池
  → 多个检测节点（同帧结果、各自能力状态）
  → 同类目标去重 + 姿态/头部/车牌等附加观测关联
  → 原跟踪器（一次）→ 原观察流与SEI
  → 原规则/计数/状态评估 → 原证据交付 → 原告警与审核
  ↘ 按事件/质量采样的嵌入等派生任务 → 原事实附加结果/检索索引
```

### 6.1 能力目录与契约

扩展现有预设、runtime label catalog和模型sidecar校验，不新建独立模型注册服务。后端返回已安装、契约匹配、适配支持、场景验证、运行就绪五种独立状态。前端可选项取“预设定义∩当前设备能力”，不可仅凭一个文件名展示已可用。

sidecar现有形状有数组和对象两种表达，适配器入口规范化再严格校验，不能给所有模型硬套YOLO输出格式。增加能力描述（产生目标/关键点/属性/特征，需要哪些输入），校验SHA、输入通道顺序、输出布局、标签语义映射。物理文件路径变化不自动改变业务label_id；模型hash变化也不自动继承精度批准。

### 6.2 融合、跟踪与调度

先做已知person/face/helmet/plate/pose的有限策略，不建设通用任意DAG编辑器。

- 检测生产者：同帧同一语义类别先由优先级选权威框；其他生产者通过有门控的一对一空间关联提供附加观测。跨类别head↔person、plate↔vehicle是归属关系，不做NMS同类合并。
- 匹配需同通道、session、帧身份、坐标变换及空间门限；有歧义时保留未关联观测，禁止把旁人姿态或车牌附到当前目标。没有权威框但辅助检出时，仅在显式回退策略下产生目标，来源可见且需回归去重。
- 调整列表顺序不能改变语义label_id。新增/删除可能改变数字class_id，旧规则继续按稳定ID；模型变更重新建分析会话并声明连续性中断，禁止跨代关联track_id。
- 目标跟踪只消费一次合并框；姿态/颜色/人脸特征不各自再计人。现有低帧率跟踪和gap机制保留。
- 低频节点有自己的observed_at、valid_until和not_scheduled状态。未运行不等于“本帧没目标”；到期不能继续作为触发证据。规则只使用满足该能力覆盖的时间区间。
- 关键检测与计数优先，嵌入/OCR等质量采样低优先且有界排队。配置引用维持单例驻留，无引用释放，去掉任务后取消在途采信。模型复用不等于输入/输出缓冲零增量。
- 单模型延迟不能相加取倒数当整机FPS。要测试同解码帧多缩放、GPU/JPU、BPU等待、Mongo持久化、录像与并发复核共同负载。当前190数据库竞争须先处理再宣称多能力容量。

### 6.3 结果与SEI

兼容现有FrameResult公共信封。新字段通过版本化可选扩展加入：pose包含17点(x,y,score)、坐标系、来源；属性包含value/unknown、质量、来源版本、观测时间、关联目标。缺失、未运行、不可判定、明确否定各有语义，不能统一用空字符串。

五点landmarks仍只表示原人脸五点。SEI只带绘制所需精简骨架、属性和证据引用；512维人脸向量、名单原文、完整审核日志不进入视频。保持总帧/单目标字节上限，超限明确记录省略哪些显示扩展，不能使检测主结果消失；归档保留经授权的完整业务证据。旧客户端忽略新字段仍能播放。

### 6.4 规则状态与审核

沿用原触发器定义、绑定、快照、证据交付和episode去重。新增区域级状态评估作为原引擎的策略类型，不再开一个定时查库告警系统。

统一状态：normal→pending→active→recovering→normal；unknown是观测不可用状态，不能表示normal。事件ID在active期间固定；短暂缺测进入unknown/宽限，不反复新建。通道重启后以已有持久检查点恢复；无法证明连续时记录证据间断，不编造持续时长。长期unknown终止旧episode应标“观测中断”，不是“风险已解除”。

时间条件采用源PTS/单调可验证时间；跨会话重置，允许宽限有上限。阈值按有效时间/检测覆盖和场景策略定义，按帧率变化调整需要的样本支持；不同帧率不能通过固定帧数改变业务持续时间。合格观测下零目标才支持无人规则。烟雾不能依赖传统目标ID稳定，不适用人员越线规则。

AI审核输入固定规则版本、区域、目标归属、真实前后帧/时间线、有效观测覆盖、触发值和阈值。区域相交状态可单帧证明，穿越/跌落过程/持续违规需时间证据。VLM不得凭文字轨迹确认画面中不存在的目标；低质量保留人工。人员三分类策略不能推广到所有类别；按业务类型注册审核能力及独立评测阈值。通知可基于触发事实先行，审核结论后补，不因慢复核隐藏风险。

### 6.5 PG / Mongo / SSD 分工

PG继续存配置、名单、版本与权限；Mongo沿用观察/behavior_events/alarms及必要的派生任务、元数据；增长证据在现有SSD证据存储，复用固定帧、ACK、清理及配额。不得把人脸照片/特征全集放参数PG或SEI。

人脸模板确有需求才新增集合/索引，归属版本绑定PG库定义；检索复用已有搜索服务接口/存储机制但使用独立模型空间，绝不与Qwen文本向量混算。不为小图库先引入第二套向量数据库。模型空间迁移需要重提特征和验证；未迁移部分显示覆盖不足。

派生任务沿用已实现的识别/投递分阶段、幂等、版本CAS、人工结果优先；名单版本仅保存一次，事实引用版本/命中项。告警证据失效不能无限重试。配置切换禁止自动追溯生成历史告警。

## 7. 统计口径与查询

| 指标 | 口径 | 不可混淆的分母/未知 |
|---|---|---|
| 告警数 | occurrence落在范围内的唯一episode ID | 不按每帧检测数或通知数计数；跨区去重必须声明scope |
| 事件持续时间 | active且有有效观测支持的时间交集 | unknown单独汇总，不填为0；跨日按日截断 |
| 区域人数 | 合格观测的同时存在唯一track数 | 不是累计进入减离开的强行余额；遮挡与重启可未知 |
| 区域占用率 | 有效占用时长/有效观测时长 | 同时展示有效覆盖率；低覆盖不排名为优秀 |
| 违规占比 | 可评估的人员轨迹中明确违规比例 | 先需验证人员关联、质量和去重；首期只显示事件数 |

按时间、通道、规则、类型、区域同一过滤契约查询列表/统计/导出，下钻带原范围。未关联热区的事件单列，不能丢掉。比率和基线按同一时区/布防时段/有效覆盖计算；样本不足不显示趋势异常分数。

先扩现有聚合端点，不新建平行统计库。只有实际慢查询且无法索引解决时才增加可重建、幂等的按小时汇总；从原事实生成，不重复采集。索引以真实查询explain及I/O验证，不能照搬列名强制hint。

## 8. 典型操作用例与失败分支

1. **安全帽**：原通道编辑→添加安全帽→保存并确认生效→新建未戴帽模板→原监看绑定作业区→现场回放验证→告警详情确认→告警统计按安全帽筛选。缺模型/标签时阻止有效启用并保留草稿。
2. **移除模型**：删除安全帽节点→显示受影响的2条规则及1个统计筛选→用户选择取消或明确停用绑定后保存→人物计数继续。绝不悄悄把helmet规则映射为person。
3. **烟火**：添加检测→定义场景阈值和排除区→单帧灯光不形成持续事件→稳定烟雾形成一个episode→间歇漏检不重复告警→恢复后重新出现形成新episode。暂停模型时显示未知，不显示已恢复。
4. **人数为0**：区域空且视频有效持续满足→触发；拔网线/遮挡导致观测失效→数据缺口，不触发无人；重连重新积累有效窗口。
5. **姿态+通用检测排序**：交换顺序后同一人不变成两次计数；可关联的17点仍存在；多人重叠无法关联时只显示未关联姿态，不触发指定人的摔倒。
6. **人脸名单**：有权限管理员建库→导入合格图→选择允许通道→新观测匹配→原告警列表；模糊图不自动报陌生，换模型不混旧特征；普通用户看不到受限身份和向量。
7. **统计下钻**：在地图点烟火区域→保留时间/类型/区域跳告警列表→详情录像→返回恢复筛选。图上显示事件分布而非虚构火焰轨迹热图。
8. **故障与资源不足**：BPU忙仅派生任务排队且有截止时间；依赖故障显示受影响能力；原检测是否继续由能力依赖判定。不会每秒创建新告警或无限排队。

### 11.1 分层事实的最小方案

覆盖按具体能力/规则的有效观测区间派生，同一时段检测可用但姿态未运行时，人物计数可有效、姿态覆盖可未知；不能共享一个整机coverage百分比。后端提供kind、behavior、review_origin、review_decision、semantics_version和coverage状态的有界过滤契约，前端按可用字段逐步启用，未就绪不显示示例数字。
