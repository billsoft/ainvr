# 单通道多模型分析：执行契约与实施记录

更新：2026-11-12；开发与试部署目标为 .190。未授权提交、推送或更新 .189。

## 1. 本次实现的边界

沿用同一 AI 通道、源流、解码器、分析会话、发布输出、归档与告警服务。通道包含 1–4 个平级帧级 BPU 模型，没有用户层面的主次。各适配器拥有自己的硬件预处理、输入输出契约与后处理，统一输出源帧坐标下的 Detection 和可选类型化属性。

执行方式为顺序执行或最多两节点并发。所有参与检测的节点共用同一抽样帧及同一个推理节拍；一个帧的全部必要结果完成后，合并一次、跟踪一次，再写识别结果、证据和 SEI。多模型同帧在途上限为一，保留原单模型双帧流水的快速路径。模型权重仍通过现有 BpuModel::Acquire 和配置驻留登记共用，不创建第二套模型管理服务。

车牌能力在一个适配器内串联检测、角点矫正、单双层处理、字符与颜色识别；实时路径保留符合阈值的检测框（模型最多 300 行），每帧 OCR 最多 4 个高分候选。超出读牌额度仍输出检测框与空属性/明确状态，不伪装成未检测或无牌；低分检测不强制读牌。原事件复核仍维持最多 4 个候选的预算。输入是真实 NV12 视频帧，颜色空间随帧传入。既有 JPEG 通行复核路径继续使用自身 JPEG 色域，不混用。

本次不是任意 DAG 编辑器。慢速生成式 LocateAnything 继续单独运行，不加入同帧检测屏障。独立节点频率、异步 OCR 后补、独立跟踪域和动态算力调度并非本次已实现的能力；不能以之前的设计提案描述替代验证事实。共同帧钟是本次保证帧、目标、轨迹和规则一致性的执行契约。

## 2. 配置与兼容

保留已有 `model`、`preprocess`、`postprocess` 作为兼容存储槽，槽内只是列表中的一个普通成员，不是主模型。`root_id` 记录该成员的稳定 ID（旧配置默认 `primary`），`nodes` 保存其余成员，`order` 保存全部成员的优先顺序。UI 展示一个平级列表，顺序和删除不受存储槽限制：

```json
{
  "analysis_pipeline": {
    "execution": "serial",
    "order": ["primary", "plate"],
    "nodes": [
      {
        "id": "plate",
        "model": {
          "name": "plate-recognition", "adapter": "plate_bpu",
          "path": "models/derived/s100p/plate-detect-yolo26s.hbm",
          "provider": "bpu", "input_size": [640,640], "stride": 32
        },
        "preprocess": {"rgb_order": true, "mean": [0,0,0], "std": [255,255,255]},
        "postprocess": {"conf_threshold": 0.25, "iou_threshold": 0.45, "max_detections": 300}
      }
    ]
  }
}
```

- `id` 是节点稳定身份，编辑阈值、切换执行方式不能重建 ID。
- 空 `nodes` 显式保留，表示列表只有一个模型，不能因省略空数组重新启用历史配置。
- 删除原兼容槽成员时，将剩余一个成员移入该槽并保存其原 ID、模型路径、预处理与阈值；删除旧的 `primary` 不改变其他成员身份。
- `order` 必须是所有成员 ID 的完整排列，不能重复或漏项。配置更新时整个 `analysis_pipeline` 原子替换，不深合并旧的 root/order。
- 顺序只改变标签所有者及执行顺序；类别目录按稳定成员身份生成，不因拖动改变标签 ID。模型集合或标签语义变化仍可能改变目录版本，应检查计数器和触发器绑定。
- 保存时至少保留一个模型，最后一项的移除按钮禁用；可先添加替代模型再移除。
- 未含此字段的旧通道维持原执行路径。只改名称或 FPS 不自动改模型路径。
- `analysis_pipeline` 在通用配置合并层整体替换；省略的旧顺序和旧成员标识不会残留。仅修改其他配置则保留原模型列表。
- 结构变更按既有通道重启协议执行；会有分析会话切换，不伪称无损热切换。
- 保存前检查节点 ID、数量、适配器、模型文件/契约、输入尺寸以及合并标签目录；最大 128 个有效标签。
- 非法模型配置不能覆盖已经保存的配置；运行时模型载入失败仍如实显示异常。
- 旧 PG 车牌开关只为未迁移通道保留读取兼容。新界面不再提供独立写入口；显式 `analysis_pipeline` 优先，不能被旧开关重新打开。既有事件型通行复核和名单服务继续工作，复用相同 BPU 权重。

## 3. 标签、跟踪和规则

不能把各模型本地的 `class_id=0` 当成同一类别。例如 COCO 的人、人脸模型的人脸和车牌模型的车牌分别具有不同标签。

合并采用明确的权威来源：固定类别按类别名去重；同一类别由配置顺序中靠前的模型负责。开放词汇只按稳定标签 ID 和一致的描述合并，同一 ID 不同描述直接拒绝，不凭中文名称或近义词推断语义相同。它不是把不同模型的置信度放在一起比较，也不是跨模型置信度校准。

旧单模型导入成员保留原标签 ID，新增成员使用 `node:<节点ID>:<原标签ID>`。每个检测保存 `source_node`、`source_class_id`、`model_name`、`task_type`。合并后分配不冲突的全局 class_id，再进入原 ByteTrack 和规则链路。

显示检测与跟踪恢复候选使用独立方法。ByteTrack 可读取低置信候选，显示、归档及告警仍使用各模型自己的发布阈值；不能通过 `max_detections` 猜测调用目的。

添加模型导致标签目录变化时，原单模型目录以兼容目录随观测一起提交。告警服务逐项核实 ID、类别名、描述都仍存在且未变，才接受原目录对应规则；兼容范围不包含新增标签。改变描述、类别或来源几何不能借兼容目录绕过失配保护。

任何必要节点失败、取消、旧视频代际返回时，不输出一份假装完整的空检测。此次失败交由原通道错误/间断机制处理。单个慢节点会影响组合的完成帧率，实际低于跟踪节奏时仍沿用已有降级提示和规则保护。

## 4. 结果、SEI、存储与证据

FrameResult 保留既有 1.2 字段；单模型兼容字段保留在原位置，各目标的真实模型来源以 source_node/model_name 为准，多模型执行信息放入 `model_extra.analysis_pipeline`。完整配置和标签目录只保留在本地结果/观测协议，不重复塞入视频。

检测的 `model_extra.attributes` 保存类型化属性，如：

```json
{
  "plate_text": {"type":"string", "value":"京A12345", "status":"candidate", "score_semantics":"uncalibrated"},
  "plate_color": {"type":"enum", "value":1},
  "double_row": {"type":"boolean", "value":false}
}
```

无可用字符时是 null，不能解释为无牌。颜色索引对应模型契约中的黑、蓝、绿、白、黄。车牌读数仍是模型候选，通行记录可另外做原分辨率 ROI 多帧核验和人工校正，不能直接把一帧文本当作已确认名单结论。

紧凑 SEI v1 增加 `src`（节点来源）、`a`（有界属性），保留原 PTS 和检测框格式。沿用原载荷预算与省略机制；实时播放、录像读取同一个解析器。现有无属性帧照常渲染。

归档保持原框坐标与原始帧：混合人脸与通用检测时，裁剪、任务分类和增强按每个目标的实际模型类型处理；不能把全部对象按兼容槽内的模型当成人脸。Mongo 的识别记录及 SSD 原始任务保存完整 model_extra，已检测轨迹的属性随同帧观测传入后续证据，不能复制给丢失或预测轨迹。

新增模型不创建第二套车辆计数。通行数仍来自已绑定车辆计数器，名单任务仍沿用既有队列、版本、重试与人工校正保护。

## 5. UI 操作契约：PC 与 Pad

复用 AI 通道现有四步向导，不增加页面或侧路开关：基本信息 → 模型与推理 → 目标跟踪 → 输出与推流。

1. 一张平级模型列表，显示已选数量、顺序、类别类型和阈值，不显示“主模型”。
2. 从“待添加模型”选一种能力，点击“添加模型”；同一预设不重复添加，最多四个模型。
3. 模型按行展示，常见固定模型默认收起参数；“配置”展开阈值，开放词汇新增后直接展开必填标签。
4. 每行支持拖动、上移、下移、配置、移除；PC 拖动与 Pad/键盘箭头操作等效。移除原来的第一个模型不受限制。操作只改草稿，保存后才生效；关闭和 Esc 不隐式保存。
5. 顺序/限量并发是资源选择，不承诺并发必然提高 FPS。所有模型共享抽样时刻，页面显示实际完成帧率。
6. 置信度与最大检测数放在各模型的配置中，输出步骤只配置输出。通道卡按保存顺序显示模型组合；模型筛选同时匹配附加模型。“查看结果”显示属性候选和完整 JSON。
7. 车牌候选直接随对应帧画在视频上；通行、名单入口仍在原识别历史和系统配置中。
8. 不依赖 hover。新增、配置、移除、关闭、上一步、下一步和保存使用至少 44px 触控目标。对话框限制到视口，内容区滚动，底部操作栏固定；横竖屏无需横向拖动。
9. HTTP 设备控制台不依赖安全上下文专用的 randomUUID；节点 ID 使用 getRandomValues 生成并保存。

## 8. 2026-11-12 提交前边界修复

本轮不增加模型预设或业务功能，沿用上述平级模型列表与统一结果链路。

- **检测预算提前校验**：组合中各模型的 `max_detections` 合计不得超过 1000，保存、启动与配置中心加载使用同一校验。每个模型先获得配置的可见检测额度，剩余候选容量均分，余数按模型顺序分配；例如 300+300+300 对应 334/333/333 个跟踪候选。四个模型可各设 250。单模型仍保留 1000 个候选，不降低旧跟踪能力。不同模型的分数不跨模型排序截断。
- **源尺寸约束**：车牌输入最小 16×16、宽高为偶数、像素总数不超过 8,388,608。控制台已知本地源几何和原生当前帧均参与保存前校验；未知/离线源允许保存，实际帧到达时在入队前检查，不支持则明确报通道错误。运行中源尺寸改变同样检查，不反复对每帧执行必然失败的车牌推理。3840×2160 可用，7680×4320 不可用。
- **配置运行一致性**：组合模型的顶层兼容槽 postprocess 修改需要重建适配器，避免配置已更新但节点阈值/候选额度仍旧。模型初始化与捕获错误并发时不得把错误覆盖为运行中。
- **任务类型**：不再凭模型文件名包含 `face` 推断人脸任务。明确的人脸适配器或全部类别为 face 的配置仍为人脸；helmet/no_helmet 等类别不得误走人脸归档增强。
- **测试夹具维护**：码率测试的模拟 SRS 接口按 pathname 匹配，并断言 start/count 分页参数；没有放宽业务结果断言。车辆浏览器脚本改走现有多模型向导，不再查找已移除的独立开关。
