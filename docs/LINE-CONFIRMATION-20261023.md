# 单边计数真实观测确认（2026-10-23）

目标：减少线附近短命检测/跟踪框造成的额外通行记录，不合并紧挨的不同目标。

在共用 traversal.mjs 的单边分支实现，计数方式、方向、底边中点及原关联保持不变。线前稳定侧需要至少 2 个真实有效观测；跨有限线段后暂存候选，线后需要至少 2 个已确认目标的真实有效观测且间隔至少 120 ms，再产生一个行为事实。边界模糊区不构成线后稳定证据，回到原侧取消候选而不是生成一进一出。单边分支允许同位置的后续真实观测完成确认。

推算和低质量框不能累计确认时间；短时漏检保留身份后，线后确认重新计时。编号/会话更换、输入中断和超时继续走原统一连续性策略。未确认跟踪上下文可以证明原侧位置，不能完成线后确认。所有状态保存在既有检查点内，每目标仅一个有界候选；不增加逐帧轨迹。

确认后真正返回可再次独立计数。事件时间为确认完成时刻；traversal.entry/exit 保留实际越线观测，并附 confirmation.policy/before_samples/after_samples/stable_ms/confirmed_at/confirmed_frame_id，区分越线和入账时间。历史记录不重算。

区域穿过与双边穿过算法本轮不变；未将用户单边计数自动改成区域计数。已有计数器方式切换仍须重新定义和布防，不在本轮隐式转换方向。

边界：120 ms 是工程初值，不是现场标定结论。按帧率，实际等待通常需一到数个后续有效观测。线后没有可见空间、刚跨线就遮挡或快速往返且未满足确认条件可能少计。持久的双编号不能由此可靠区分，不能通过时间/区域合并抹掉两个真人。
