# 告警审核与证据契约

更新：2026-10-30。本文件描述当前产品行为；旧的逐次发布记录不作为当前配置或审核资格的证明。

## 审核状态

审核状态只有“未审核、已人工审核、已 AI 审核”，结论为“确认、误报”。内部排队、参考分析、取证失败不是已审核。人工决定优先；模型回写必须同时匹配告警证据代次、领取令牌和处理版本。

告警先持久化并及时通知，图片和模型通过数据库异步处理，不阻塞检测或告警接收。模型优先领取最新未审核告警，有积压时连续处理；空队列才等待。大模型搜索复核已关闭，告警审核不与它争抢推理。

正式资格文件与用户授权的仅确认策略分开管理。前者必须匹配模型、输入布局、提示词和标签；后者允许在现行阈值下自动确认，不赋予自动判误报资格。没有资格或授权时只记录参考分数。高分不是经过校准的概率，也不是准确率验证。

## 行为证明与视觉核对

唯一的确定性行为引擎验证出现、接近、侵入、穿过。计数与穿过告警继续共用几何核心；审核不另写一套较宽松的越线算法。历史规则、标签、几何版本、帧身份及真实观测被冻结，当前配置不能重新解释旧事件。

模型负责核对指定目标的视觉类别，不能从坐标猜类别，也不把单图冒称为完整视频行为理解。提示词说明当前告警、关键时刻与指定目标；标记热区和轨迹的上下文图用于人工理解，不能代替真实像素或完整行为证明。

| 可用证据 | 自动处理边界 |
| --- | --- |
| 行为证明完整，要求的全景关键帧齐全 | 逐帧核对；全部达到现行确认条件才确认；自动误报另须有效资格 |
| 行为证明完整，部分全景帧缺失，但触发时刻有精确同目标原图或保留的原始特写 | 保留所有可用关键帧，逐张核对；仅可确认，不能自动判误报；记录缺失帧及来源 |
| 无触发时刻图像、身份不符、字节损坏、行为证明不完整或帧间结论冲突 | 保持未审核，说明原因；不以旧参考分数或文字盖章 |

保留特写必须匹配当前告警阶段的行为 ID、通道、会话、目标、精确 PTS、原帧号、源尺寸及标签。只使用 original，不使用增强后图、别人的图或邻近时刻图片代替。Mongo 图片读取校验字节数与 SHA256；数据库暂时繁忙不等于图像永久缺失。

有限视觉审核记录 `evidence_mode=verified_behavior_available_visuals`、要求/实际审核的帧 ID、缺失帧 ID、输入摘要、逐帧分数、模型、提示词与授权来源。即使模型具有资格，有限视觉分支也不能自动隐藏告警。人工可改判并保留审计。

## 取证、缓存与录像回补

- 推理线程只提交有真实检测目标的帧；纯推算框不产生视觉证据。缓存工作异步，不在推理路径读 SSD 策略文件。
- JPEG 普通保留 30 秒，指定保护帧 60 秒；JPEG 总额 128 MiB。队列最多 8 项，排队与正在处理的原始 NV12 合计最多 256 MiB。达到任一边界明确计数，不能无限占用内存。
- 状态分别报告队列满、原始像素预算不足、处理失败、无效输入及保护帧淘汰。不能仅凭失败时间分布断言历史上一定发生了队列溢出。
- 实际告警图片统一存入 MongoDB 的有界证据池；候选帧与实际告警分池，保留期限、字节配额和清空边界均生效。
- 回补只从对应 AI 输出录像读取。使用录像内 SEI 的通道、会话限定目标、PTS 和原帧号证明精确身份，不以墙上时间相近代替。
- 录像尺寸与检测尺寸不同，必须有完整画面轴向缩放证明，并核对 MP4 实际编码尺寸、原始尺寸、原帧号和宽高比。缺证明、裁剪、拉伸、冲突身份或已清理录像均拒绝。回补结果保存尺寸变换与原始片段/包位置来源。
- 保留特写恢复写 `visual_completed / retained_evidence`；真正录像回补才写 `completed / recording_exact_sei_v1`，不在界面宣称不存在的录像恢复。
- 新告警优先在缓存保护期内准备证据，缺失后有界回补；缓存、存储或硬件仍可能失败。发生了真实行为但图像无法恢复时保留告警并明确交人工，不能为维持“图片齐全”而静默漏报。

JPEG 解码、裁剪、缩放与补边由 JPU/GLES 完成；模型推理只用 BPU。合法奇数尺寸 JPEG 必须按可见尺寸处理，不能把 MCU 填充当作画面、拉伸边缘或启用 CPU 像素回退。普通视频解码契约保持严格。

## 故障、重试与生命周期

临时模型不可用和数据库故障走有界重试。失败自动重排只处理 `review_unavailable / storage_busy / storage_unavailable`：每十分钟最多 50 条，每条最多自动重排五次，失败至少冷却五分钟。身份错误、缺证据、模型结论或人工决定不进入该重排范围。

数据库超时不消耗模型尝试次数；达到存储重试上限后保留可诊断失败。服务关闭等待正在执行的模型任务和自动重排扫描结束，再释放数据库。模型调用和审核回写之间重新检查授权，撤销授权或人工处理均优先。

取证准备与模型调用分开计数：明确的轨迹、标签、身份或图像错误立即进入可见的人工处理状态；未知准备异常最多重试三次，之后标记 `evidence_preparation_failed`。准备重试设独立的到期时间，尚未到期的旧任务不占据每轮 100 条的处理批次。存储繁忙单独退避，最长五分钟一次，诊断计数有界，不把暂时存储故障误判为缺少像素。异常详情不保存可能包含凭据的原始错误文本；列表和详情提供明确说明。

## 界面

列表局部更新并按当前筛选移入/移出记录，不要求点击“新告警”按钮，不打断正在打开的详情或确认操作。

详情区分完整画面、原始目标特写、模型输入和标记上下文。特写使用自己的宽高比，不叠加全景坐标中的热区或轨迹；切回全景时才恢复对应标记。有限视觉明确提示缺失内容与仅确认边界。录像入口定位对应 AI 输出及原事件时刻。

## 验收与发布边界

回归覆盖：精确身份与哈希、无图拒绝、所有可用图保留、有限视觉不能自动误报、人工并发优先、阶段/代次变化、存储暂时故障、自动重排上限、退出等待、真假录像恢复来源，以及畸形和奇数尺寸 JPEG。

软件测试、隔离数据库、实际 JPU/GLES 和生产模型调用分别报告。当前真实推流为 1920×1080；模拟或软件的异尺寸变换测试不冒称 8K 真机通过。现场新告警和历史告警审核应观察真实 handling 变化，不用手工改成 AI 已审核代替验证。

部署保持 main、设备/布防/计数器及模型配置。回滚包仅在已挂载 SSD 的 `/mnt/ainvr-ssd/ainvr-rollback/<服务>/`，每服务最多三份。未取得有效模型准确率资格，不宣称对全部场景完成准确率认证或零漏图。
