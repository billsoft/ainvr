# 里程碑问题修复设计

对应 `milestone-code-review-2026-10-05.md` 的九项问题。范围是修复可复现的故障边界，保持授权算法、视频协议、推理模型和归档策略不变。

## 控制台边界（WEB-01～04）

- 已配置 PostgreSQL 时，它是访问密码的权威来源。初始化重试耗尽即拒绝启动，由现有进程监督机制重新拉起，不能启动一个无密码且缺失配置路由的后台。
- 运行期密码查询不可用用异常表达，HTTP 返回 503。错误状态不再作为字符串凭据参加比较；恢复后重新读取密码。
- 单条图片删除与其他 AI 代理使用同一个 PG 密钥来源。启动、停止分别使用 35 秒、15 秒代理期限。期限到达不代表远端操作取消，应刷新通道确认状态。

## 录像文件所有权（REC-01）

在启动写入进程之前登记文件占用，切段关闭 stdin 不释放占用。只有进程退出才释放。扫描器不能将仍被占用的文件标记为完成，配额清理也独立检查占用；文件年龄和播放保护继续保留，但不替代写入保护。占用查询只查内存，不访问 NAS。

## 配置持久化（AI-01）

统一使用安全临时文件、完整写入、检查文件 fsync 和 close、原子 rename、检查父目录 fsync。任一步失败都不能报告持久化成功。目录同步失败时文件可能已替换，调用方收到的是结果未完全保证的错误，不能假装旧文件一定未改。

## 配置事务（PG-01）

发布版本、快照、期望版本和发布审计使用同一个事务连接；审计失败则提交前回滚。文档和敏感值 CRUD 的审计同样加入事务。下发后的补充结果审计失败只记录诊断，不把已经应用的配置报告成事务回滚。

## 历史删除协议（MDB-01～02）

1. 每个截图任务携带接收时的 `archive_epoch`；Mongo 文档及 pending 文件都保存此值。旧数据没有该字段时按 0 处理。
2. 删除操作持有通道操作锁，避免和实例替换/通道删除并发；再持有历史写入锁。将新代次及删除条件持久化到该通道 pending 目录的 `deletions.json`，之后才删除 Mongo。
3. 删除规则只匹配比规则代次更早的任务，按 image_id、时间范围或全部匹配。新接收的帧使用新代次，即使墙钟回拨，也不属于旧的清空操作。
4. 写入前再次检查规则，匹配的已准备批次、重试批次及 pending 重放都不再 upsert。启动或连接恢复时先补执行持久化删除意图，再恢复写入。
5. Mongo 删除需要确认和日志落盘。不可用或执行失败返回 503，不再伪装成“零条”或 404。若持久化意图已成功、数据库应答失败，恢复后仍完成该意图，用户可安全重试。
6. 完整清空合并此前所有删除规则；其他墓碑保留，防止旧 pending 文件重放。删除整个 AI 通道继续先停推理及写入、再 drop 集合、最后移除 pending 目录（包含墓碑）。

删除日志只在管理员执行删除时同步落盘，不在每个推理帧或每个写入批次上增加 fsync。当前不为每张截图创建额外 Mongo 文档或新的数据库服务。

## 验证与交付边界

验证针对鉴权失败和恢复、发布审计故障回滚、代理使用正确密钥和期限、旧写入进程保护、文件/目录 fsync 错误、删除代次重载和待重试批次过滤。构建使用独立 out/build 目录，不覆盖生产执行文件。

本次不提交 Git；编译成功也不等同于已经部署生产。测试结果及部署状态在完成记录中单独列明。

### 升级与回退

旧 Mongo 文档和 pending 文件无需批量改写，新程序按代次 0 兼容读取。应保留各通道的 `deletions.json`，它是删除一致性记录，不能作为普通缓存清除。旧程序不认识这个协议，不能在有待重放数据时直接回退到旧程序；需要先停接收并用新程序完成补写/删除，再安排回退。
