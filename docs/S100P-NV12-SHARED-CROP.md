# AINVR S100P：NV12 直读与共享裁剪流水线（2026-10-13）

## 实际实现

1. 解码器的不可变 NV12 所有者通过别名 shared_ptr 交给截图队列。没有借用已归还的 VPU 缓冲，也没有新增源帧拷贝。每通道仍最多保留两张归档源帧。
2. GLES 裁剪直接采样 NV12，在插值前保留旧 RGBA8 中间值的舍入。省去 ROI RGBA 的 GPU 读回、CPU 中转和第二次 GPU 上传。ERP 仍是 1.5 倍超采样及三次插值；普通裁剪的面积缩放、边界处理和尺寸保持原规则。
3. NV12 目标使用独立的单线程 GPU 裁剪执行器，队列容量 4。四个原有归档工作线程仍处理后续亮度校正、人脸增强和 JPEG，等待的是另一执行器，不能向自身线程池递归提交。等待 future 完成后才释放帧引用。普通 RGBA 提供者保留原有路径。
4. 共享上下文按不可变源 tag 和尺寸缓存上传，连续同帧目标复用源纹理。同一帧被其他帧/通道穿插后仍可能重新上传，不能宣称绝对“每帧一次”。精确 ERP 映射缓存仍有 64 项/32 MiB 上限。
5. 临时诊断可在启动环境中设置 `AINVR_ARCHIVE_SHARED_CROP=0` 对照独立裁剪；默认开启。不要把这个开关当作动态网页配置。
6. 健康数据新增进程范围 JPEG 拷贝、入队等待、颜色转换排队/执行、编码排队、编码器准备、JPU 执行七段计时及创建/复用计数；通道新增 `timing.archive_admission_wait`。原跳帧原因计数明确标注为启发式。

这不是端到端零拷贝：VPU 仍将帧复制到主机 NV12，源仍要上传 GPU，最终小幅 RGBA 仍需读回用于原图/增强图及恢复处理，JPEG 转换和 JPU 输入仍有拷贝。未重编任何 HBM，未修改检测阈值、截图尺寸、质量、目标数量或两帧上限。

## 已完成的可重复实验

- 原“先批量裁剪再编码”方案实测回退约 5.5%，已撤出产品代码，仅保存失败实验，不部署。
- NV12 直读单独对照：同一二进制，4K 八目标、A/B/B/A；原路径约 35.0ms/帧，直读约 23.7ms/帧，裁剪阶段耗时降低约 32%。这不等于整链路提升 32%。
- 共享裁剪对照：`test/ai_port/run_shared_crop_experiment.py`，相同 3840×1920 NV12、八目标、两张源帧、四归档线程、真实 GLES/JPU/Mongo，六次 A/B/B/A/A/B。无亮度校正中位数 170.455→203.539 目标/秒（+19.4%）；有亮度校正 63.013→67.085（+6.5%）。测试包含目标数、图像读取、原图/处理图和归档账本验证，不包含 VPU 解码或检测模型推理。
- 证据：`test/results/shared-crop-ab-20261013-145435/summary.json`，每轮 XML/日志在同一目录。测试脚本自动恢复原先运行的 AI 和录像服务，MongoDB 本身不停止。
- NV12 对照覆盖 BT.601/BT.709、全/限范围、258×130、3840×1920、7680×3840、边缘、ERP 接缝/极点、不同尺寸以及 RGBA/NV12 切换。容差是每通道最大 1/255、平均不超过 0.05/255，不冒充位级一致。
- 原 NV12 直读版本通过 24 个 GPU、12 个硬件归档、62 个归档逻辑测试。真实 GPEN 测试使用独立 RGBA 人脸夹具，36 对原图/增强图均保存，24 对预热后约 76.75 对/秒；这验证真实 GPEN BPU/JPU/Mongo，不能冒充真实人脸检测或 NV12 全流程速度。

## 诊断结论与边界

上线前分段统计约 93% 的 JPEG 需要新建编码器；旧路径编码器准备约 1.9ms、JPU 执行约 2.5ms，还存在编码排队。MongoDB 约 5–9ms/批不是当时的主要瓶颈。共享裁剪不会消除所有 JPU 成本。

保留 SDK 对非对齐截图使用单编码器的已验证行为。没有通过改变截图尺寸分档或同时保留多个奇数尺寸 JPU 上下文换取速度；此前存在像素兼容问题。

旧测量脚本的 `healthy` 只判断归档，不能说明 SEI 全部成功。本次修正为同时检查发布区间计数，并保留历史证据：基线观察中 SEI 迟到 3 次；独立上下文 NV12 最终观察中 1 次。没有对应录像丢帧或归档丢失，但不能将该轮宣称为完全无异常。参见 `test/results/nv12-publisher-audit-20261013.json`。

完整 GPU→JPU 缓冲共享、VPU DMA-BUF、检测模型 NV12 输入重新编译仍是后续独立研究，不能由本次结果推断已完成。BPU 利用率不是唯一验收指标；同时观察有效目标吞吐、推理帧率、尾延迟、丢失计数和内存。
