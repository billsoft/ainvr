# 维护性整理

## 行为边界

归档仍逐帧处理，有界容量不足时反压对应通道。锁、线程数量、写入顺序、停机保存规则、数据库结构和授权协议保持原契约。本次不增加新微服务。

## 模块职责

- snapshot_store.cpp：归档生命周期、配置、容量及统计。
- snapshot_crop.cpp：裁剪、投影与像素处理规划。
- snapshot_pending.cpp：本地暂存、隔离、重放文件及清理。
- snapshot_pipeline.cpp：接收、反压、准备和写入队列协调。
- snapshot_processing.cpp：逐目标亮度、增强和编码。
- snapshot_repository.cpp：Mongo 批量写入、查询和历史删除。
- snapshot_internal.hpp：仅供以上实现单元使用的资源管理工具；共享初始化和捕获预算仍为同一实例，不允许拆成每个编译单元一份。

控制台配置校验、设置接口、配置备份传输分别归属 configPolicy/settingsShared、settingsRoutes、configTransferRoutes/settingsTransferRoutes。原路径继续提供必要的兼容导出；权限检查随原接口保留。

实时和回放的工具条为纯展示组件，连接与媒体事件仍由各播放器管理。两者继续共用全景和全屏实现；协议名称只有一个定义。

录像文件系统探测独立到 storage_probes，仍通过原来的隔离 I/O 车道调用。SMB 挂载与恢复生命周期不变。

## 兼容与清理

删除仅由旧测试调用的 TrimToMax；滚动删除由实际归档路径的用例验证。无效的预算/队列丢弃内部计数删除，旧 API 字段恒为 0 保持兼容。旧采样间隔只作配置迁移兼容，普通前端测试夹具使用 0。

处理故障与历史隔离数据分开表示。页面显示中文阶段提示，具体异常留在诊断数据和日志中。历史隔离文件继续告警，绝不虚记为已写入数据库。

## 验收与回退

编译主程序和受影响测试目标，使用独立 Mongo 测试库验证归档、恢复、删除及状态；运行控制台与录像回归测试。部署前保存原 AI 二进制及前后端镜像标识，部署后验证授权、通道、归档账目、录像和日志。验证失败恢复对应产物，不回滚业务数据库。
