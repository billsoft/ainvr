# 组合触发与审核

每个选用关系只使用该 AI 通道、视频会话、规则版本和布防时段的观测。旧规则默认按单目标匹配任一标签。复合配置存于现有 PG 触发器定义的 group 字段，由配置编译器发布到告警服务。需要确认态、真实检出的跟踪目标；预测框不计数。

| 配置 | 判定 |
| --- | --- |
| 猫或狗 | 单目标，任选两个标签。各目标独立触发。 |
| 同框有人和包 | 组合，全部类别，最少 2，同时保持 0 秒。仅证明共现，不推断归属。 |
| 三人同时在场 | 人，最少 3，同时保持 0 秒。设为 1 秒则同一批目标必须连续满足 1 秒；单个目标的连续出现时长是独立条件。 |
| 多目标接近、侵入 | 接近须同帧处于指定外侧带；侵入须各自观察到合法入区且仍同时位于区内。 |
| 3 秒内两人穿越 | 按源视频 PTS 的闭区间计算，按跟踪 ID 去重，完成路径才入窗。0 秒要求同一帧完成。重复消费同一观测不重复落库。 |

数量指不同轨迹，跟踪器换 ID 会影响物理目标的计数。AND 要求每类至少一个，数量约束为所有所选类别合计。一次连续达标只生成一次同框告警；数量跌破门槛后须持续至少 1 秒（及配置的时间，取大者）才会重新允许告警，单个目标漏检一帧不会重复告警。闯入类目标合法入区后漏检一帧可重新计入。穿越每次达标消费当前一批完成记录，参与的轨迹在各自窗口内不重复使用。冻结当时符合行为的候选数和最多 16 个证据成员。超过上限时记录截断，仅足够的正证据可确认，禁止自动判误报。单组最少数 1–16、时间 0–60 秒。输入中断、镜头切换、规则或布防窗口变化会清除组合状态。

告警保存当时的规则与热区、成员的轨迹、框、源帧号、时间、穿越入口和出口等数据。每个证据成员引用自身的行为事实和原帧目标裁剪，沿用现有证据保留和容量政策；图片取得失败明确显示不可用。新告警冻结第二版候选清单，摘要绑定规则、成员、会话与触发帧。审核从原始全景按当时的检测框取证，样本以通道、会话、PTS 和源帧号定位；精确画面缺失时可用录像的精确帧身份恢复。详情显示实际取到的画面、区域与成员位置。旧版告警缺少候选全集，保留参考与人工审核。

确认要求足够多的已授权目标逐帧通过，类别组合满足配置，能在至少一张共同真实画面里区分这些目标（不同类别的框可以重叠，同一类别两框交并比超过 0.5 视为同一目标），并通过额外的全景数量核对。侵入与穿越还要求生产引擎保存了完整行为证明。先后穿越但无共同可核对画面时，触发正常，自动确认保守地留给人工。

自动判误报须有完整候选集合。先核验目标特写、扩大范围和明确排除该类别的反向询问，三者满足门槛才排除一个成员。把所有未排除成员（包括看不清的成员）都算上后，若仍达不到人数或必需类别，才可判定整组误报。模型结论不一致、授权变化及人工已先处理均有保护。结果记录每个成员的原帧、模型、实际提示词与分数，支持人工改判。

授权沿用板上受保护的 review-authorization.json。默认沿用已有 labels；可选 group_labels 仅用于组合审核，可显式设置允许的类别名，例如 ["person","backpack"]；在“确认或排除”模式下只能包含 person，因为排除路径只对人员验证过。必须匹配实际模型标签，模式和模型摘要等约束仍生效。配置变化会改变授权摘要。单目标授权不因 group_labels 扩大。2026-11-04 使用板上的真实模型、独立 Mongo 和本地标注图验证。两个人员候选的正对照经全景模型核对后自动确认；两个车辆框模拟人员误检时，一个明确排除，一个不确定，人数上限为 1，系统自动判“两人”告警为误报。另在测试进程中临时允许 person 与 backpack，人员分高，背包分约 0.852，整组保持待审。使用的是带标注的静态拼接图和注入的轨迹身份，未测量现场视频准确率。生产授权未扩大。

启用顺序为告警引擎、参考审核、配置编译器，最后开放界面。降级到不认识 group 字段的旧引擎之前必须先停用所有组合规则并确认执行快照生效，否则旧引擎可能将组合规则按单目标执行。
