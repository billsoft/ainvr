# 告警活动、录像导航与审核标定补齐

## 判定边界

- 同一来源会话、同一编号缺席后保留 3 秒活动宽限。宽限内回归保留已触发锁存，
  不重新产生“出现”；几何位置、未完成持续计时及穿越证据在缺席时立即清空。
- 超时、来源会话变化、规则修改及生效时段改变仍结束原活动。不同编号不接续。
- 穿过共用引擎暂存每条规则最多 3 个、最长 1 秒的真实待确认观测；整通道最多
  64 个待确认规则状态。相同编号确认后才能使用；低置信、推算、丢帧、消失、
  超时均不能补成穿过。完全发生于未确认阶段的穿过不产生事实。
- 计数和告警保留显式缺帧策略；没有把编号保留时长直接当作几何证据有效期。
- 接近仍表示处于外侧接近带，不偷偷改成只能向内运动。展示分组不合并审核身份。

## 人工复核

录像窗口优先包含行为开始时间和已保存关键帧；旧记录缺少这些字段时回退到活动
开始时间。每张审核关键帧增加“查看此刻录像”，使用原来源、原时间前后 15 秒。
没有录像或缺失帧并不会被伪造。人工结论按钮统一为“确认”，与“误报”并列。

## AI 提示与资格

生产 Worker 与离线评分共用 review-prompt.mjs，版本 target-context-zh-v2。
提示只加入行为和关键帧角色，明确行为由几何引擎判定，模型核验指定目标。
资格额外绑定调用方提示版本及已验证标签，旧资格不自动继承。本发布不安装资格。

## 标定工具操作

1. 在设备私有目录准备 alarm-ids.json，内容是需要导出的人工审核告警 ID 数组。
2. `node test/llm_service/review_alarm_dataset.mjs export alarm-ids.json 新目录`
   只读导出原关键帧和条件；过期/没有证据的记录列出跳过原因。目录权限 0700。
3. 人工逐图填写 manifest.json 的 visual_label（指定目标是否确为该类）、
   split（development/test）及 group（同一次拍摄/目标必须同组）。
   **告警误报不等于目标类别错误**，不能直接把人工误报结论当成视觉负样本。
4. `node test/llm_service/review_alarm_dataset.mjs score manifest.json 新报告.json`
   串行使用生产 BPU 图片准备接口；保存逐图分数、实际输入图和哈希，不改告警状态。
   同组和同图禁止跨数据集；缺少独立现场样本时只可作功能测试。
5. 固定开发集参数后，再评估未参与调参的独立测试集。标签、模型、图片布局、
   提示或阈值改变都需要重新验证。导出的同一视频多帧不算独立样本。
6. 签发工具 `node deploy-package/sign-review-validation.mjs 报告.json 验收.json 私钥.pem 新资格.json`
   验收文件必须包含 approved:true、dataset_independent:true、reviewer、
   report_sha256 和 expires_at。签发要求每标签至少 100 组正例、100 组负例、
   无错误自动结论、没有失败请求且版本一致；这是最低技术门槛，不替代现场验收。
   工具不生成私钥、不自动安装。私钥和样本不得入库。资格最多有效 90 天。
7. 经实际样本验收后，由运维把资格和对应 Ed25519 公钥安装到
   /etc/ainvr/review-validation.json、/etc/ainvr/review-validation.pub，root 所有且
   不允许组/其他用户写入。Worker 自动恢复待验证任务，并逐请求校验模型及标签。

现有样本没有通过之前的准确率关口，不能因为工具完成就启用自动审核。
本次短测仅验证新提示请求和工具链，不替代长测、双独立相机或现场准确率标定。

## 发布

先运行告警引擎/审核/真实隔离数据库与前端测试。前端编译到 dist.review-followup，
使用 deploy-package/deploy-review-followup.py 发布。只重启告警服务、替换前端，
不停止 AI、录像、推流、大模型或控制台后端；验证运行配置哈希及这些进程不变。
回滚程序与前端备份保存在 deploy/s100p/rollback-followup-时间/，不提交二进制。
历史证据读取、旧迁移、长测工具继续保留。test/results 是设备私有测试输出，
部署入口在 deploy-package，不依赖将这些输出提交 Git。
