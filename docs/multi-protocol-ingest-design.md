# 多协议视频输入重构设计

## 目标与边界

支持 RTMP、SRT、WebRTC 发布、RTSP 拉流的 H.264/H.265 输入，统一进入已有录像、AI、SEI 和识别归档链路。协议转换默认只转封装，不解码、不重编码；解码只发生在 AI 推理分支。归档开启时继续保存每个已识别目标，积压反压对应通道，不改成间隔采样。

协议支持不等于任意编码参数、任意浏览器、任意通道数量都支持。验收先覆盖当前相机的 8 位 H.264/H.265；分辨率、profile、level、位深和并发解码能力由探测结果及 Jetson 能力约束。10 位和其他 profile 必须单独验证，不能默默转码。

WebRTC 首期指发送端通过 WHIP 向本机发布；不是粘贴任意网页地址后自动拉流。若需要拉取外部 WebRTC 源，应增加独立的 WHEP 适配器，要求源提供标准 WHEP 接口，并另行验证；私有 WebRTC 信令不能用一个通用 URL 自动兼容。

## 设计开始时的代码核实（历史基线）

| 部分 | 当前实现 | 必要改动 |
|---|---|---|
| 接入管理 | upstreamProtocol 已含 rtmp/srt/webrtc/rtsp | 改为按运行时能力显示选项，不允许生成不可用地址 |
| RTSP | routes/channels.ts 创建及修改时返回 422 | 受控拉流服务完成后再解除限制 |
| SRT | channelService.ts 生成 streamid 地址 | 开启 SRS srt_server、vhost srt_to_rtmp，部署 UDP 端口 |
| WebRTC | SRS rtc_to_rtmp 已开启，nginx 代理 /rtc/ | 增加正式 WHIP 发布地址、设备发布凭据及会话管理 |
| AI 输入 | source.cpp 只接受 RTMP / HTTP-FLV；发布分支要求 RTMP | 保持内部 RTMP 输入；不让 AI 重复实现四套协议 |
| 录像输入 | channels.py 获取内部 RTMP 地址 | 保持统一地址，增加有效视频进度状态 |
| 页面在线状态 | 发布连接可使零视频输出显示在线 | 连接状态与视频状态分开；录像状态使用实际写入进度 |

## 隔离试验事实（2026-10-09）

> 以下是设计阶段的历史记录。实现完成后的四协议 H.264/H.265 全链路验收见 `multi-protocol-ingest-acceptance-20261009.md`，以验收记录为准。

使用生产相同镜像 ossrs/srs:7.0.162，独立容器、仅绑定回环地址，CPU 上限 1 核、内存上限 256 MiB；未停生产服务。测试容器结束后已删除。

1. 128×64、10 FPS、短视频的 H.264 和 H.265 MPEG-TS 经 SRT 输入，SRS 分别识别为 H264 / HEVC。
2. 用生产录像所使用的 FFmpeg 8.1.2 读取转换后的 RTMP，两路均成功复制视频包并结束。此项验证转封装，不代表解码、AI 或高码率性能验收。
3. 向同版本 SRS WHIP 接口提交 H.264/H.265 SDP，均返回 201 且应答含相应编码。没有建立真实 DTLS/SRTP 视频会话；不能宣称 WebRTC 全链路已通过。
4. RTSP 尚未进行真实摄像头拉流验证。

试验文件位于 out/protocol-design-20261009/，包含 srt-results.json、rtc-negotiation-results.json 和读流日志。结果是一次实验记录，不是运行时能力来源。

## 架构

```text
RTMP 发布 ──────────────────────────────┐
SRT 发布 → SRS 解 MPEG-TS/转封装 ────────┤
WebRTC WHIP → SRS RTP 重组/转封装 ───────┤→ SRS live/<stream>
RTSP 拉流 → 独立 FFmpeg 转封装进程 ──────┘       ├→ 录像
                                                ├→ 实时观看
                                                └→ AI 解码/推理 → SEI 输出
                                                               └→ 按配置截图/增强/归档
```

只增加确实缺失的拉流监督服务。RTMP/SRT/WHIP 原生处理沿用 SRS，不加一层重复转发。RTSP 转封装在独立进程执行，不放在后端 HTTP 请求、SRS 主循环或 AI 推理线程中。

## 统一通道契约

- 保留现有 channel id、streamName、app 和历史数据关联，旧 RTMP 通道无需迁移 ID。
- 增加 input.mode：push / pull；input.protocol：rtmp / srt / webrtc / rtsp；编码默认 auto，H.264/H.265 来自视频参数探测。
- push 返回 publishEndpoints；pull 保存 sourceUrl 和受保护的凭据引用。普通列表、日志、导出不得回显密码。
- 增加 inputGeneration。配置变化时所有异步结果必须匹配当前代次，旧进程、旧探测不得覆盖新状态。
- 统一内部输出为 RTMP；每通道至多一个有效输入拥有者，重复发布明确拒绝并记录原因。
- 能力接口按协议、编码、部署开关、完整链路验证分别报告 supported / disabled / unverified / unsupported 和原因，前端不能仅依据类型枚举宣称支持。

## RTSP 拉流监督

- 新增独立 ingest-service：控制台保存配置后通知它；它按通道启动 FFmpeg，使用参数数组而非 shell 拼接。
- 默认 RTSP TCP，提供 UDP 选项；视频使用 -c:v copy，内部输出采用支持 H.265 的 Enhanced RTMP。复用已有 FFmpeg 8.1.2 安装资产，启动前验证功能。
- 首期以视频完整链路为验收目标。音频有独立兼容性状态；需要转成 AAC 时只转换音频，并显式展示，不能因不支持音频隐藏丢失。
- 重连采用有上限的指数退避和随机扰动；首次有效帧、关键帧等待、连续无帧有独立超时。超时停止该通道旧进程组，再启动新代次。
- 最大并发拉流数、进程内存、缓存、stderr 日志都有上限。stderr 持续异步读取，不能让日志管道填满卡住子进程。
- 热更新显示名不重连；源地址、传输方式或凭据改变只切换对应通道。停用及删除通道先终止进程并确认退出，才释放流名。
- 随授权业务权限停止和恢复；授权未知、注销、到期等规则复用既有契约，不创建另一套授权算法。
- 允许必要的局域网摄像机访问，但限制到视频协议及批准的目标；禁止访问本机管理接口、云实例元数据和非视频协议。日志脱敏。

## SRT 与 WebRTC

### SRT

- 部署 srt_server 和 srt_to_rtmp，开放明确配置的 UDP 端口，streamid 绑定 app/stream。
- 接收缓存按码率与延迟测算并设总量上限；不无限扩容掩盖拥塞。高码率与受限网络分别验收。
- SRS 配置的 passphrase 不能假装是每通道独立凭据。若首期使用服务级 passphrase，应明确其范围；每通道访问控制通过可验证的接入鉴权机制实现，先证明现有版本的扩展能力再决定实现。
- 错误流名、未登记流、重复发布、错误凭据有明确拒绝及诊断。

### WebRTC

- 提供 WHIP HTTP 发布端点，分开发布权限与网页观看权限。设备发送端使用专用、可撤销凭据，不依赖管理员浏览器 Cookie。
- 保留 WHIP Location / DELETE 会话语义；控制台代理不能破坏路径、请求方法和内容类型。支持必要的 ICE 更新能力需按实际 SRS 版本测试。
- H.264/H.265 协商使用发送端支持的 codec/profile，记录实际选择；H.265 不可用时明确失败，不能自动换 H.264 却仍显示 H.265。
- ICE 候选随访问地址/实际网络配置生成，验证有线、无线、切换网口。跨公网需要 TURN 时单独配置，局域网不强制增加 TURN。
- 浏览器采集发布需满足浏览器的 HTTPS/安全上下文要求；接收 H.265 不意味着所有手机浏览器都能采集、编码或播放 H.265。
- GOP、B 帧、RTP 分片和 SEI 的完整性必须用真实媒体验证；SDP 成功不能作为支持完成的证据。

## 业务状态与诊断

- input：waiting / connecting / streaming / stalled / reconnecting / error；分别记录传输连接和最后有效视频包/帧进度，不能用控制包流量判断有画面。
- 录像：waiting-source / recording / draining / backlog / error。正在重试 FFmpeg 不显示“录像中”；有连接但没有有效录像产物也不显示正常。
- AI 输出：等待源、发布连接、有效视频三者分开。xmai 零帧和少量控制流量不算视频在线；编码未知则显示未知。
- 记录单调时间下的首包、首个参数集、首个关键帧、最后视频包、重连次数、错误阶段、缓冲用量、代次、子进程退出码。
- 所有耗时采用单调时钟；日志另带墙钟用于事故关联。归档 delivery 账目继续独立验证。

## 配置页面与交互调整

页面复用现有接入管理及配置中心，不另建第二套通道管理。输入协议、观看协议、视频编码必须分开展示，避免用户把播放选项误认为接入能力。界面只显示用户需要的设置和中文故障原因，底层组件名称及原始报错留在诊断日志。

### 接入管理：新建与编辑通道

| 配置项 | 界面规则与设置目标 | 生效时机及范围 |
|---|---|---|
| 输入协议 | RTMP / SRT / WebRTC / RTSP；读取后端能力，未启用及未验收选项显示原因，不能仅凭前端枚举放开 | 已有通道改变协议需要重建该通道输入会话；其他通道不重启 |
| 接入方式 | RTMP、SRT、WebRTC 首期为设备主动推送；RTSP 为本机主动拉取。不提供尚未实现的 WebRTC 任意地址拉流 | 跟随输入协议，不生成与当前模式矛盾的字段 |
| 视频编码 | 默认自动识别；允许限制为 H.264 或 H.265。限制用于接入校验，不表示自动转码 | 下一次输入建立时检查；变更限制时仅重建本通道并重新验证 |
| 通道名、备注 | 复用现有字段；与底层流标识分开 | 热更新，无需重连 |
| 流标识 | 唯一且经过校验；修改时检查重复，说明内部地址及录像关联影响 | 重新建立本通道输入，沿用 channel id，不抹掉历史记录 |
| RTMP 输入 | 显示可复制发布地址及接入凭据，不要求输入相机拉流地址 | 创建后等待设备推流 |
| SRT 输入 | 显示发布地址、流标识、接入凭据；提供经校验的延迟/缓冲选项，默认值由服务统一生成 | 协商或连接参数改变时仅重新建立对应会话；当前服务若只能全局配置则标明全局范围，不能伪装成通道设置 |
| WebRTC 输入 | 显示 WHIP 发布地址及发布凭据；发送端按标准接口连接，不把 webrtc:// 展示为唯一可用的发布操作 | 建立新发布会话后生效；候选地址和全局服务变动另按配置中心规则处理 |
| RTSP 输入 | 源地址、用户名、密码、TCP/UDP（默认 TCP）；凭据可单独填写，保存后不回显密码 | 保存配置后异步切换本通道拉流进程；页面显示连接进度，HTTP 请求不等待首帧 |
| 启用输入 | 与录像启用、AI 启用、归档启用分开，明确关闭输入会使下游等待源 | 停止/启动本通道输入；关闭时排空已接收的录像及归档任务 |
| 测试连接 | 用受限、短时的探测任务检查协议、编码和参数；已运行通道优先读取当前探测结果，不抢占同名发布 | 不保存配置、不停现有生产源；取消和超时必须清理探测会话及子进程 |

通道编辑有配置版本，异步保存、测试及重连结果绑定版本；旧结果不能覆盖新选择。操作失败保留编辑内容并明确显示是否已保存、是否已生效，不能把“配置写入成功”当成“收到视频”。

### 配置中心：流媒体与接入服务

| 设置组 | 新增或调整内容 | 生效规则 |
|---|---|---|
| 协议接入能力 | 展示 RTMP/SRT/WebRTC/RTSP 的启用、组件就绪、已验证编码范围；不可用时给出修复提示 | 来自运行时状态和版本能力，不由页面本地推断 |
| SRT 服务 | 开启接入、监听端口、对外发布主机、服务级加密设置；高级参数有合理上限 | 改显示地址无需重启；新增 Docker 端口映射或监听变化可能需重建 SRS，保存前显示所有流短暂中断的影响 |
| WebRTC 服务 | 发布主机、信令地址、候选地址沿用现有配置；按需要增加 TURN 配置和连通性检查 | 发布地址生成规则可热更新；候选地址影响新会话，现有会话是否需要重建按实际版本验收结果明确说明；端口变动可能需重建服务 |
| RTSP 拉流服务 | 展示服务就绪、最大并发、连接超时、重连上限及资源限制；优先提供安全默认值 | 全局限制不直接强杀运行通道；降低并发时限制新启动，其他变更明确适用于新会话或安排受控重连 |
| 接入安全 | 设备发布凭据创建、撤销、轮换；SRT 服务级密码明确标为全局；权限与管理员登录分开 | 撤销后禁止新接入，正在使用该凭据的会话是否立即断开必须落实服务端并显示影响；不假装已具备不存在的强制踢出能力 |

全局参数只有一个后端配置来源；配置校验、保存、生成部署文件、应用、验证和回退形成同一事务。界面展示“待应用/应用中/已生效/失败”，保留最后可用配置。需要重启或重建时由用户明确执行应用操作，不在修改字段时自动中断全部流。配置恢复和导入复用同样校验，不能绕过端口、凭据及能力约束。

### 录像、AI 与识别历史页面

- 录像及 AI 仍按 channel id 选择来源，不要求用户再次选择输入协议。页面显示探测到的编码、分辨率、有效视频状态和源异常原因。
- 观看协议保持独立；输入 WebRTC 不代表观看一定要 WebRTC，输入 SRT 也不要求浏览器直接播放 SRT。
- 保持既有归档开关热更新：关闭后不接收新截图任务，已接收任务继续处理；AI、SEI、推流和录像继续运行。开启后逐帧归档，不引入采样间隔选项。
- 列表不再把零视频的控制流量标为正常在线，也不把等待源的录制进程标为“录像中”；源断开时 AI 输出显示“等待输入”。
- 码率与分辨率分列显示：4 kbps 不能用“4K”样式造成分辨率误解。优先采用明确的 kbps/Mbps 单位。

### 页面验收

新增配置字段有前后端契约测试；协议切换后不残留其他协议必填字段；旧 RTMP 通道打开编辑后可直接保存；密码不进入日志、普通配置导出或列表响应；已运行源的测试按钮不会顶替生产发布。验证保存失败、应用失败、回退、重复点击、旧轮询响应，以及每项设置仅影响声明的通道或服务范围。

## 开发顺序与失败测试

1. 状态契约：先复现零视频输出误报在线/录像中；补视频进度判断及共享状态类型。
2. 能力契约：先测试 SRT 未部署时禁止创建或明确不可用；添加配置、地址、安装和离线包一致性校验。
3. RTSP 监督：先测试断流退避、旧代次结果失效、配置改变和删除后的进程清理、日志管道拥塞、进程启动失败，再实现服务及接口。
4. WHIP：先测试发布鉴权、错误编码、会话删除、候选地址和 H.265 协商，再做真实媒体全链路试验。
5. UI：按 push/pull 展示字段，分别提供发布端点或拉流地址；配置保存不在请求线程等首帧。
6. 打包：新服务、依赖、配置迁移、开机启动、卸载和部署文档全部进入离线包。旧 RTMP 数据及原生产配置保持可迁移、可回退。

## 验收矩阵

四种输入协议 × H.264/H.265 共八组，每组分别验证：真实视频包、编码及尺寸探测、内部 RTMP 连续读流、录像文件可解码且时间戳连续、AI 有效推理、SEI 可解析、归档开启后 delivery 平衡、关闭归档不影响推流。

WebRTC 必须真实完成 DTLS/SRTP；RTSP 必须覆盖 TCP/UDP 和相机断开。每组覆盖首启、断流恢复、删除和重建、分辨率变化、服务重启。重复流名和不支持 profile 必须明确拒绝。

小流量功能验证后，用当前 4K 与 8K 源做受控压力试验；比较 SRS API 延迟、内存、CPU、录像积压、AI 帧率与归档反压。八组协议全支持不承诺八路 AI 同时满帧运行。

部署先备份、再按组件逐步替换。SRT 端口变化可能要求重建 SRS 容器，只在最终部署阶段安排一次停机并记录影响；开发期使用独立实例。新版本不通过验收，不切换既有相机生产通道。

## 设计阶段结论（历史记录）

设计阶段仅完成 SRT 转封装及 WebRTC 协商试验，当时未完成代码开发和部署。后续实现与验收以本文“实现契约与部署边界”和 `multi-protocol-ingest-acceptance-20261009.md` 为准，不把最初的协商试验当成完整媒体验收。

## 实现契约与部署边界

- 新的 `ainvr-ingest` 服务只负责 RTSP 拉流监督；每路一个独立的视频转封装进程，不执行视频解码或重编码。默认 TCP，可按通道改成 UDP。
- 原有 RTMP 通道和 ID 保留。H.265 输出默认 CodecID 12；输入先沿用原 RTMP 读取路径，本机 HEVC 连接持续未收到视频时才在重连时回退到本机 HTTP-FLV，支持读取 Enhanced RTMP 对应的 FLV 数据。外部主机及非默认端口不会被自动改写。
- 当前部署契约为本机 RTMP 1935、HTTP-FLV 8080、SRT UDP 10080。修改监听端口需要同步调整部署配置，不能只改页面中的对外显示地址。
- WebRTC 输入使用 `/ingest/whip/<channel-id>`，发布凭据与管理员登录会话分开，凭据只在创建时显示一次。会话控制记录加密保存到参数库，后端重启仍能撤销；轮换、停用和删除会先确认旧会话停止。停止失败时明确失败并保留凭据，不宣称撤销完成。
- 本版 WHIP 要求发送完整 ICE 候选，PATCH 返回 405；不是任意网页地址拉流。H.265-only offer 明确选择 HEVC，不能悄悄协商成 H.264。浏览器采集/播放能力和服务器接入能力是不同边界。
- RTSP 密码加密保存在参数库，普通列表、导出及日志不包含密码；进程参数也不包含密码。普通配置导入不带凭据，导入的 RTSP 通道默认停用，重新配置凭据后启用。
- RTMP/SRT 首期保持可信局域网发布方式，没有宣称每通道独立密码或公网认证。SRT 服务级加密和监听参数属于部署级配置，不是页面热配置。需要对公网开放时必须先增加相应接入权限控制。
- 编码自动探测。功能验收范围是 8 位 H.264/H.265、闭合 GOP 和定期 IDR；其他位深、开放 GOP、其他 profile 不纳入兼容承诺，不自动转码。视频接入首期不带音频。
- 页面提供协议能力、WHIP 发布凭据、RTSP 地址/凭据/传输方式/启停、并发限制和连接超时。独立的未保存地址探测、编码限制选择、SRT 监听与加密在线应用不属于本版已实现页面功能；不能仅凭设计表格认定已有这些按钮。
- 归档开启时每个有目标的推理帧都按配置保存，积压反压对应通道，关闭后排空已接收任务；本次不引入间隔采样。
- 完整构建使用干净编译，避免跨机器文件时间或旧缓存造成新旧对象混用。离线包包含拉流服务、系统服务单元、配置工具和本设计，实际验收数据另行记录。
- 重复的 HEVC 序列头按实际 VPS/SPS/PPS 及 NAL 长度比较，封装附带字段变化不重建 AI 解码器；录像参数摘要去除相同参数集的重复与排列差异。真正参数变化仍触发重建/换段，不忽略分辨率或编码变化。
