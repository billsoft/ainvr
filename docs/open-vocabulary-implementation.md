# 开放词汇通道实施与验收

## 开发计划

1. 备份现有通道配置，停止原有 AI 通道；其他业务继续运行。
2. 将已验证的 448×448 视觉引擎、36 层解码引擎、对齐输出头接入持久执行器。
3. 新增适配器与描述、固定标签配置，支持 10–3600 秒采集间隔。
4. 识别前复制原图并释放解码缓冲；生成结束按原始 PTS 保存结果和截图。
5. 开放词汇输出采用 40 秒固定压缩包缓存、768 MiB 上限，按原 PTS 写 SEI。
6. 页面区分固定类别与开放词汇；提示词、标签、间隔统一保存。未知置信度保持为空。
7. 编译与契约测试，试运行“小门 / adult woman / woman / 成年女性”，检查归档、SEI 与缓存连续性。

## 当前实现契约

- `model.adapter=locateanything_trt`，`model.path` 为本机私有执行器套接字。
- `model.description` 是模型识别描述；`label_id` 是稳定检索 ID；`label_name` 是显示名称。
- 描述和标签变更为热更新，从下一次推理取配置；正在处理的图继续使用旧配置。
- `inference_fps` 保持统一单位；页面把开放词汇频率显示为秒间隔，15 秒对应 `1/15` FPS。
- 执行器独占；只接受同一服务用户；任务有 25 秒生成期限，客户端有 28 秒请求期限。
- 输入仍是原视频，无二次编码；开放词汇输出固定延后约 40 秒。普通模型输出策略保持原状。
- 首次启动先填满压缩缓存，再建立输出连接，避免填缓存期间空连接被断开。停止/替换通道属于维护中断，不能宣称维护期间也连续输出。
- 768 MiB 可容纳 100 Mbps × 40 秒约 477 MiB 的压缩内容，保留额外余量。容量有限，必须监控 `publish.buffer.dropped/too_late`；持续超过容量不可宣称无损。
- 每个有目标的完成帧继续走既有截图、投影、亮度和可靠归档链路。女性身体检测不是人脸检测，不调用人脸修复模型。
- API/Mongo/SEI 中未知置信度为 `null`。标签 ID 和原始描述进入截图记录及暂存文件。
- 空结果仍写入结果缓存和原帧 SEI；识别历史目标集合只保存有目标截图。新增独立逐帧结果集合属于后续扩展，尚未实现。
- 模型的 `<box>None</box>` 是正常的无目标结果；残缺坐标、无效坐标仍报错，原始生成内容限长写入日志。失败也遵守采集间隔，恢复后自动清除本次错误提示。
- 达到生成长度上限时，完整且有效的坐标仍进入 SEI 和截图归档，原始输出与 `grounding.complete=false` 一并保存，页面明确提示未完整生成。末尾未完成的坐标不伪造成目标；没有任何完整目标时仍报错，不伪造成空结果。训练素材可按完整性标记筛选。
- 448×448 会压缩 4K/8K 图像中小目标的有效像素；检测性别描述不能视为身份或性别真实性认证。

## 模型与运行环境

首次交付需提供本机编译并验证过的引擎目录、tokenizer 目录及兼容的 Python/TensorRT/PyTorch 环境。
运行代码位于 `ai-service/runtime/locateanything/runtime.py`，不依赖实验脚本；已验证的引擎移入 `ai-service/models/locateanything-3b/trt`，分词器位于同级 `tokenizer`。原实验目录保留符号链接，避免重复占用模型空间。
`ainvr-grounding.service` 使用 `/etc/ainvr-ai/grounding.env` 中的 `GROUNDING_PYTHON`、`GROUNDING_MODEL`、`GROUNDING_ARTIFACTS`。执行器建立接口后报告就绪，并在 AI 服务之前启动；模型在通道启动时加载，停止后释放，不与另一开放模型同时常驻。Python 环境位于 `ai-service/runtime/locateanything/venv`。离线安装与动态描述契约见 [执行器部署](open-vocabulary-runtime-deployment.md)。
执行器的地址为项目内 `ai-service/data/grounding/worker.sock`；AI 服务的工作目录是 `ai-service`，通道里填写 `data/grounding/worker.sock`。运行目录权限为 700，套接字为 600，两边使用同一个服务用户。
不自动下载模型、不重复编译权重。执行器命令与部署验收数据另行记录，避免把私密通道配置写入文档。
