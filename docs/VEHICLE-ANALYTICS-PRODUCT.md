# 车辆识别、名单告警与统计实施说明

更新：2026-11-11。本文替代前两阶段 Demo/适配探针进展，作为当前实现的一条说明路径。

## 范围与入口

在原系统内增量接入，不新建车辆平台或视频输入。

| 入口 | 当前功能 | 数据来源 |
|---|---|---|
| AI通道卡片 | 折叠车辆能力，保存启用/关闭、查看实际运行状态 | PG配置、原生模型状态 |
| 识别历史→车辆通行 | 计数器、位置、方向、时间、车牌片段、读牌状态；原图证据、人工校正、关联录像、导出已加载记录 | 原behavior_events通行事实，补充vehicle字段 |
| 系统配置→车辆关注名单 | 普通/新能源精确车牌、备注、最多500条、版本冲突保护 | PG参数表 |
| 告警列表 | 多帧整牌一致且命中关注名单产生告警，复用人工确认/误报；详情显示通行原图与校正入口 | 原alarms集合 |
| 统计分析→车辆 | 原车辆计数器的趋势、规律、覆盖率、热区布局与下钻 | 原flow统计接口 |
| 告警触发/布防 | 原车辆标签的出现、接近、相交、穿过、数量规则保留 | 原规则引擎 |

不将车牌颜色当车身颜色，不新增品牌、细分车型、驾驶行为和跨镜识别。车辆统计中的位置告警沿用原位置口径，并非仅车牌告警。通行数不等于唯一车辆数；车辆经过不同位置可以有多次通行。未检出车牌不等于无牌。

## 配置与运行

1. 在流量统计创建仅含车辆类别的计数器，绑定原AI通道的布防区域。历史混入非车辆标签的计数器不进入车辆页面。
2. 打开AI通道卡片车辆能力，启用车牌识别并保存。保存成功表示PG已持久化；状态轮询确认模型加载，不以保存成功冒充已运行。
3. 模型加载完成后，后续通行按原计数器生成并识别。历史记录不伪造补牌。
4. 可设置关注名单；名单修改只作用于满足当前版本的新识别任务，不追溯伪造旧命中。
5. 停用后撤销在途任务并释放此功能持有的模型；计数、普通告警和录像继续工作。

BFF每10秒同步有界的45秒授权：通道集合、模型SHA256组合、车辆计数器、名单版本。原生侧单一线程拥有GPU上下文，BpuModel::Acquire共享模型，最多一个识别任务在途；无使用者或授权到期释放。模型改变、通道撤销、设备授权失效或任务过期均禁止继续采信结果。服务故障由有限重试与状态展示处理，不无限重算。

## 图像与模型契约

位置：ai-service/models/derived/s100p/。运行采用plate-detect-yolo26s.hbm与plate-recog-color.hbm；LPRNet为独立对照，不在正式通行路径中重复推理。

- 检测：RGB、640×640、/255、letterbox114，输出300×14，框/四角/单双层。
- 识别：BGR、168×48、(x/255−0.588)/0.193，字符21×78、blank0、颜色5类；按固定契约字符表解码。
- JPEG由硬件解码；GPU处理原图车辆ROI、透视、双层拆拼、归一化；BPU执行模型；无CPU推理回退。
- 每图最多4候选，JPEG最大8MiB、图像最大8Mi像素（覆盖常见4K），奇数或异常尺寸拒绝。更高分辨率不能宣称已支持。
- 运行前核对模型大小、散列、输入输出形状。softmax分数不是准确率或校准概率。

## 可靠证据与数据流程

原观察流→原计数器→在交付ACK前固定真实帧、源尺寸、车辆框、规则快照→原SSD持久证据与Mongo图像池→vehicle_recognition_jobs→原通行事实vehicle字段→可选名单告警。

启用车辆的通道保留原始分辨率证据，不沿用审核图1280长边缩放。证据池复用原配额/保留与故障机制；数据库与增长文件仍在SSD。没有另建抓流或计数服务。

单任务取最多3个不同真实帧，只处理对应车辆ROI。一个ROI中存在多个车牌时不凭最高分猜归属。不同帧至少两次整牌一致且不存在有效字符串冲突才是consistent；不拼字符，不把重复图片调用当独立投票。其余状态明确为单帧候选、冲突、不可读、未检出、证据失败或识别失败。

队列最多约1000待处理任务（并发摄入最多额外一个通道批次），任务保留7天、真实推理错误最多3次；预热、繁忙、传输和存储故障独立退避（2秒至60秒），总等待上限1小时；已完成帧保存检查点，重试不重复推理。失效授权/证据不合要求终止并保留通行事实。运行状态报告待处理、失败和最近工作器错误。

名单只匹配整牌，使用事件发生时的不可变版本，交付前再次检查通道及模型授权，幂等键固定通行ID+名单版本。保留原计数规则快照/证据摘要，不篡改为另一个空间规则。车牌名单告警不送普通人员VLM复核；在既有告警列表人工审核。

人工校正保留操作人、时间、旧版本和最多100条变更记录，不改通行次数。CAS防止覆盖他人修改，同一事件自动处理与校正串行；人工结果不会被迟到推理覆盖。已有名单告警保留发生时读牌与名单版本，改判在告警列表操作。

## API与文件地图

- ai-service/src/adapters/plate_{decode,hardware,runtime}.hpp：解码/硬件/生命周期与授权任务门控。
- 原生 /api/v1/vehicles/status、configure、recognize：沿用内部鉴权，图片不通过公开匿名接口。
- alarm-service/src/vehicle-recognition.mjs：持久任务、融合、幂等名单、校正；vehicle-transport.mjs调用原BFF内部鉴权通道。
- srs-web-console/backend/src/services/vehicleRuntime.ts：配置同步与能力状态；vehicleArtifacts.ts：契约完整性校验缓存。
- backend/src/routes/vehicleRoutes.ts与store/vehiclePreparation.ts：原控制台身份、PG配置版本、证据代理。
- /api/flow/records扩展plate、vehicle_state，仅用于明细；过滤进入游标作用域，不改变统计总数。
- frontend/src/features/vehicles：原入口内的通行记录、证据、配置；地图继续使用既有Analytics组件。
- 原vehicle-demo是显式示例入口，正式路由不引入模拟数据。

## 2026-11-12 可靠性重构与试部署

- 识别结果先持久化，再更新通行事实、投递名单告警。投递失败独立重试，不清空车牌、不倒退版本、不重做已完成帧。结果幂等键由通行ID和固定模型版本生成，避免BSON往返改变结果序列化导致版本重复增长。
- 人工校正优先；自动重试不会覆盖人工车牌。停止通道或更换模型会终止旧任务采信。超过等待时限显示失败；证据仍有效、原配置恢复时可在证据面板“重试未完成处理”。原通行次数不变。
- PG迁移029按名单版本归档一次配置，规则/任务只保存版本与摘要，不再复制500条名单。历史版本保留在参数库，不随任务TTL删除；未来清理须先检查所有未完成任务和告警审计引用。旧任务的内联名单仍可读取。
- 启用前检查真实视频尺寸；不支持超过8388608像素或奇数尺寸。未知尺寸显示等待视频，暂不授权识别；运行中再次检查原图尺寸。常见3840×2160可用，8K不可用。
- 前后端统一普通/新能源车牌及挂、学、警、港、澳后缀的格式范围；其他牌制不猜测。新增等待服务、证据失败、队列已满筛选；通道状态显示队列数和最老等待时间。
- 使用已有BPU模型、原始证据、计数事实和原页面，无新模型、第二套计数或采集服务。此轮未修改原生二进制。

本轮验证结果另见test/results/vehicle-hardening-20261112。现场精度、189硬件验证及8路繁忙车流吞吐仍未认证，不能用开发样例推断。仅在190试部署，不提交Git、不更新189。

### 逐项复核后的补修（2026-11-12 上午）

复核发现上一轮不能视作P0–P2全部验收。本次已修复：

- 授权配置区分authorized_channels（用户仍启用）与channels（当前尺寸核验通过）。暂时读不到视频或授权同步过期时保留任务等待，不当作主动撤销；主动关闭/模型更换仍终止。即使没有有效授权，也按任务绝对等待期限结束，避免永久等待。
- 409/429透传实际错误码；证据过期、通道关闭、队列满、版本冲突显示不同处理建议。
- 名单页面补充新旧通行生效边界；不支持牌型的原始候选单独展示、不用于名单。
- 证据面板每3秒串行刷新等待中的任务，保留未保存校正；单张图不再占双列布局，降低图片高度。请求失败显示错误和重新载入入口。
- 原运行中心告警服务行内增加折叠车牌状态：队列、失败数、最老等待、最近单帧推理/投递耗时、最近失败原因。没有额外高频日志；指标为进程内最近样本，不是分位数或吞吐保证。调度仍保持单任务、每次启动至少间隔1秒，不通过增加硬件并行抢吞吐。
