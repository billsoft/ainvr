## 1. 目标与范围

把现有 /analytics 演示页接成可信的真实统计页：用户围绕计数器和热区查看数量、时段规律、区域分布及数据缺口，能够下钻到已有通行记录、告警与录像。

首版交付：
- 统一的计数器、热区、时间及比较筛选。
- 真实进入/离开次数、峰值、趋势、排名、近四周规律、覆盖状态。
- 与所选热区对应的时段告警数及告警列表跳转。
- 区域通行量分布、服务器保存的平面图、真实 CSV。
- 三种横屏尺寸的一屏总览与触屏操作验收。

后续按阶段补停留、区域内时间热力；属性统计、跨镜去重、排队、自然语言报表和长周期报表不作为首版前提。不为填满面板放入示例数字，不承诺未经测量的识别准确率或竞品优势。

### 1.1 必须遵守的复用边界

沿用 React、TypeScript、Tailwind、现有图表组件、react-konva、Fastify、alarm-service 的 Node.js、ai-service 的 C++、PostgreSQL、MongoDB、SSD 存储及现有鉴权。

不新增统计微服务、第二套计数引擎/跟踪器/布防模型、另一个指标平台、独立状态管理框架、数据库、消息队列、向量服务、播放器或坐标变换框架。首版不新增模型推理任务。

优先顺序：
1. 使用现有接口和数据。
2. 接口不够时在其归属模块增加向后兼容字段或查询能力。
3. 已有观测足够时，只增加消费侧派生计算。
4. 确实缺少原始字段时，才扩展现有观测协议；复用原采集与传输，不再拉一路流。
5. 实测证明查询不够快时，再增加可重建汇总；不预先建设汇总平台。

## 3. 产品口径：沿用对象，不新增平行概念

### 3.1 唯一归属

| 对象 | 唯一归属 | 统计页的权限与职责 |
|---|---|---|
| 计数器定义 | 现有计数器库 | 选择、查看；管理跳回原入口 |
| 热区检测形状、名称 | 现有布防文档 | 引用、展示；修改进入同一布防保存会话 |
| 热区×计数器选用及方向 | 现有 counter_bindings 和版本 | 作为统计位置，不另存关系副本 |
| 通行事实、进出分类、覆盖 | 现有流量统计链路 | 查询、筛选、展示、下钻 |
| 告警及复审/处理状态 | 现有告警服务 | 查询聚合、跳转原详情 |
| 平面图、装饰图形、热区摆放 | 现有 Plan 模型扩展服务端存储 | 编辑展示布局，不改变检测范围 |
| 录像及证据定位 | 现有回放/取证链路 | 传递稳定来源、时间和事件身份 |

不新建“统计热区”“统计计数器”“统计摄像机”。首版不增加场所树、组织树、计数器组等并行管理概念；平面图名称已可满足基本空间组织，确有业务需要再扩展。

### 3.2 计数器与热区关系

默认保留现有关系：计数器可用于多个热区；热区可选用不同计数器；同一对不得重复选用。一个入口同时数人和车，不要求画两份重叠热区。

统计行以 binding_id 为依据，携带 counter_id、source_id、processor_id、zone_id。核实 zone_id 的全局唯一约束；若没有约束，用现有来源/处理器/热区组合消除歧义，不另造一套业务身份。

“按计数器”和“按热区”只是同一结果的分组方式，不产生新事实。不能把计数器合计与其热区分项再相加。一个热区出现在多张平面图，也只计一次。

### 3.3 数值含义

- 人类目标使用“人次”；车辆使用“车次”；混合目标使用“通行次数”或按现有标签分项。
- 多个计数器目标类别、方向名称或判定方式不一致时分组展示，不默认合成“进入人数”。
- 首次打开优先恢复上次有效选择，否则选列表中首个可查询计数器；可显示其全部历史有效位置。无计数器显示创建入口，不默认加载全部不兼容指标。
- 同一目标多次往返、多位置经过分别计次；不承诺独立人数。
- 只统计进入的计数器：离开为“不支持”，不是 0。
- 进减出仅称“本期净流入”，保留负数；不推断实际在场人数。
- 0 表示查询成功且覆盖完整、确实无事件；未知/无覆盖/失败不以 0 填补。
- 部分覆盖已有事件可显示“已记录 N 次”，同时标记不完整，不估算漏掉的人数。
- 告警数按 alarm_id 去重，依据 occurred_at 落入查询时段；不是行为阶段数，也不是待处理库存。处理/复审分项是同一集合的状态切片，不能重复相加。

## 4. UI 与交互计划

### 4.1 顶部统一筛选

替换“通道”为：
- 计数器选择（名称搜索、多选、兼容性提示）。
- 热区/位置选择（限制在选中计数器的绑定范围，历史已解绑但本期有数据的位置仍可选）。
- 现有今天/昨天/近7天/近30天/自选、对比开关。
- 摄像机作为位置的辅助来源信息，不作为主要统计维度。

URL 保存计数器、位置、时间、对比和标签页；解析时验证 ID、范围和长度。选择失效时明确提示并移除，不悄悄改成“全部”。

所有主面板共享一次解析后的范围。切换条件时丢弃旧请求；错误不保留为新范围的数字。关闭比较不查比较期，隐藏页面暂停轮询。

### 4.2 四个标签页保留

| 页面 | 内容与行为 |
|---|---|
| 总览 | 进入/离开或配置的方向、峰值、告警；趋势、区域分布、覆盖；规律缩略 |
| 客流 | 趋势/排名、计数器/位置分组；支持显示人次或其他目标单位，不强制改动已有导航名称 |
| 热区 | 平面图、区域通行量、方向、排名；选中区域和列表双向高亮 |
| 规律 | 固定“近4个完整自然周”的星期×小时图，与当前计数器/位置筛选一致，明确独立时间窗 |

近四周窗口按设备配置的 IANA 时区确定；从本周周一零点向前四周，不含本周未完整时段。接口仍校验真实时间跨度 ≤31 天。若产品最终选择滚动28天，应统一文案和算法后再实施，不能两者混用。

### 4.3 数字下钻

- 点趋势柱：固定该桶时间并打开既有记录入口。
- 点合计：若包含多计数器/位置，先明确选择位置；不能只展示第一处记录并冒充合计明细。
- 点热区：显示计数器分项、覆盖及位置入口；点具体分项数字复用 RecordsDrawer。
- 点告警数：进入现有告警列表，携带时间、处理器和热区范围。列表暂不支持多热区时扩展其原筛选，不能只带第一个热区。
- 回放沿用现有来源映射与播放器；记录抽屉冻结打开时的范围，后台刷新不移动它。

### 4.4 区域分布的表达

按用户 2026-10-30 最新设计确认，规划区域框保持透明，数据使用底图上独立热力图层，不能用整块填色和数字替代；恢复原型的平滑分布、冷区筛选及排名。热力图由所选计数器的区域通行量生成时，显著标“按热区计数生成的相对分布示意”，不称真实轨迹热力。浏览时底图、规划框、数据图层按同一坐标居中等比例自动适配，保留已规划内容；编辑器只修改布局，支持不保存的展示预览。主页面贴近原型的留白、比例和下划线页签，功能及交互按真实数据调整；以多尺寸实际浏览器截图验证。

- 图例写单位、方向及时间；未知区域使用灰色/斜纹，完整零值使用低强度色，两者不同。
- 比较期使用相同色阶上限；单期相对色阶标“本范围相对强度”。
- “隐藏冷区”只改变显示，不改合计、排名分母和导出。
- 切换平面图默认只改变展示布局，不改变全局统计范围；明确提供“只统计本图热区”操作才更新顶部位置筛选。
- 同一区域多个不同计数器并列显示，不能按 zone_id 把人、车或重复口径盲目相加。
- 未布置区域保留“未放入本图”入口；无底图可用网格示意，不阻塞统计。

### 4.5 一屏、触屏与状态

1920×1080、1366×768、1180×820 横屏总览无整页滚动；窄屏把规律缩成摘要、长排名放详情页，不靠 overflow:hidden 裁掉内容。手机允许纵向滚动。弹窗长列表可受控滚动，不为了“无滚动”隐藏操作。

加载、空数据、无配置、无覆盖、查询失败、历史过期分开表达。首版外观属性不占大块空面板，放能力说明中，验证后再进入总览。

触屏主要操作区≥44px；不依赖 hover；图表可点选读数并提供文字等价。所有编辑窗口提供右上角×、取消、Esc、一致的未保存确认和焦点返回。

## 5. 数据来源重构：一个页面数据入口

### 5.1 最小结构调整

保留 AnalyticsSource 和 analyticsSource.ts 作为页面适配边界，不建设通用指标 DSL 或数据源注册平台。

- AnalyticsScope：channelIds 改为 counterIds、可选 bindingIds、现有时间范围与时区、compare 开关；分组模式只是显示条件。
- ChannelSeries 改为计数位置序列，保留反查记录需要的身份与单位；不把新计数器 ID 塞进旧 channelId 字段凑兼容。
- 数值支持 null；单独携带支持状态、覆盖状态、查询状态和 asOf。partial 是有结果但覆盖不全，error 是读取失败，两者不能共用一个数值标记。
- 逐桶需要覆盖状态；旧接口暂不能提供时显示未知，不依据整段覆盖推断所有桶完整。
- 告警和计数可独立失败；总览不因单个告警接口失败而整页清空，出错面板不显示旧范围数字。
- 示例源只用于明确的开发预览/测试，生产失败禁止回退示例。
- 使用一个页面级 hook/加载器调用 liveSource，组件只消费结果。热区不再自行重复查一次流量。
- 保留 useRealZones 的布防元数据拼装能力，拆开“元数据加载”与“计数请求”；计数只由统一来源供应。
- 布防配置在进入页面、配置变化或用户刷新时更新，不每30秒遍历全部通道。定位部分布防失败的具体来源和可重试原因，不能长期把兜底当正常。

继续复用 totalsOf/peakOf/insightsOf，但修正其缺失值、单位和覆盖规则；不是原样套到真实数据。首版洞察使用确定性计算，不调用 LLM。95% 作为演示阈值移出“质量保证”；任何已知缺口都可提示，未知需单列。

### 5.2 请求与范围

首版计数使用一次本期 /flow/query；开启对比时加一次比较期；规律页/缩略需要近四周小时桶时另查一次并在范围不变期间复用。并发有上限，相同查询合并，不按面板重复请求。

优先在返回的 zones 分项过滤 bindingIds，再从筛选后分项重新算合计；不能过滤位置后继续使用原 counter 合计。数据量实测过大才向 /flow/query 增加可选 binding_ids，下推同一过滤规则；旧调用方不变。

现有 counter_ids 最多50个，单次区间≤31天；达到上限明确提示，不无限拆请求绕过上限。时间冻结到同一查询截止点，UTC存储、指定时区分桶，[from,to)边界沿用 flowRange 和 DateTimeRangePicker。

asOf 只表查询截止，不承诺跨服务事务快照。数据写入延迟时显示最后消费时间/待更新，避免把聚合截止时间当实际覆盖末尾。

### 6.1 覆盖算法

在原流量服务/版本分段处理处扩展，而非浏览器反推所有历史配置：
- expectedMs：查询范围内，该绑定及相关版本应当执行统计的区间长度；未创建、暂停、不适用时段不算预期覆盖。历史配置不够时 expectedMs=null，并说明未知。
- coveredMs：观测证明覆盖区间与 expected 区间的交集长度。先裁剪和合并重叠区间，再计算，不累加重复 gaps。
- ratio=coveredMs/expectedMs，expectedMs=0 显示“不适用”；未知显示“未知”。
- 沿用现有 JOIN_MS 和实时尾部容忍契约，区分容忍延迟与已证明观测，页面注明数据延迟；不另写一套不同的缺口合并算法。
- 跨多个位置的总比例按绑定-时间加权，明确是所选位置的采集覆盖；方向共用同一绑定覆盖不重复计权。
- 覆盖比例不是模型准确率，不按 1/ratio 放大计数补偿。

原接口字段保留；新增 coverage 的 expected_ms、covered_ms、ratio、逐桶状态等可选字段，Flow旧页面兼容。新增字段真正可算后才显示百分比，否则先显示既有四态。

### 6.2 对比与周规律

默认只对同一位置、同一统计口径且两期完整覆盖的数据给精确增减百分比。部分覆盖展示两期已记录量和缺口，不输出“增长19%”这类确定结论。基期完整但为0时写“本期新增N次”，不显示无限增长。

近四周每格默认显示有效同星期同小时样本的平均通行次数，注明有效日数；不足四次明确标记。无有效样本为空，不能是零。DST重复/缺失小时按时区明确合并并显示实际覆盖时长，不默认一天永远24个等长小时。

峰值根据实际桶显示；无覆盖不选峰值，完整全零显示“暂无通行”，不把零点冒充高峰。配置改变或按新计数线重算时给出口径变化说明。

### 6.3 告警查询

在 alarm-service 的 repository.mjs/http.mjs 及现有 Web alarm 路由增加范围统计，复用原列表过滤构造和来源校验。具体路径命名跟随原路由风格，不建立独立“统计告警”API体系。

- 输入：时间、去重后的处理器/热区范围，以及原有允许的告警状态筛选。
- 输出：总量及需要的处理/复审分项、查询截止。
- 所选计数器仅用于确定位置，不等于告警规则；页面标“所选热区告警”，不用计数器标签条件偷偷筛掉其他告警。
- 一个告警包含多个阶段/命中多个已选位置，按 alarm_id只计一次；历史缺热区身份的记录不能按通道猜测，标范围关联不完整。
- 查询权限、超时、索引与列表一致。按实际执行计划增加必要复合索引，避免全库扫描。
- 首版若无法正确映射范围，显示“暂不可统计”，不临时用全设备告警数代替。

### 6.4 CSV

首版只支持既有小时/天粒度和31天范围，不增加与后端不匹配的月统计入口。
导出包含：时间区间、时区、计数器、热区/位置、方向、单位、已记录次数、覆盖状态/比例、查询截止及口径提示。

按CSV标准转义逗号、双引号、换行；对名称等用户文本处理 =、+、-、@ 等表格公式注入风险。未知留空并输出状态，不写0。导出冻结当前查询快照。数据量超过前端预算后才在现有后端扩展流式导出，不引入报表服务。

## 7. 平面图保存：最小持久化，不重复存业务关系

### 7.1 PG结构

优先每张平面图一份版本化文档：id、name、version、image_ref、document(JSONB，现有shapes和placements)、created_at、updated_at及现有审计身份。
placements沿用现有热区引用与摆放，不另建一份统计绑定。首版无需同时维护JSON placements与独立摆放表两份权威数据；确有跨图检索瓶颈再评估拆表。

迁移编号在实施时取最新序号，不在计划中固定025。schema校验沿用 Plan 模型约束：最多20张、坐标与尺寸边界、图形数量/文档体积有限；服务端必须再次校验，不能只信前端。

### 7.2 底图与保存过程

底图存现有配置指向的SSD受控目录，PG只存不透明引用、校验和和尺寸。不把base64长期存PG，不硬编码盘符作为挂载判断。

复用存储服务的卷身份/在线检查。上传仅允许明确的栅格图片类型，校验真实格式、大小和像素上限；不接收客户端文件路径。读取走现有鉴权HTTP接口，不暴露SSD绝对路径。

写文件临时名→完整校验→原子发布→PG版本条件更新；PG失败留下的未引用文件按有界保留期清理。跨文件与PG不声称原子事务；失败可重试，旧引用仍有效，先保留再清理旧文件。

CRUD放现有Fastify后端与store，保存使用expected_version和现有幂等操作模式。冲突保留本地编辑，提供重新读取/另存选择，不静默覆盖或自动合并。现有系统是何种权限模型就用何种模型，不为地图单独建设RBAC。

### 7.3 本机草稿迁移与编辑

- 登录后检测现有 DRAFT_KEY，用户主动选择导入；不自动上传私人草稿。
- 预览图数、大小和失效引用，校验通过后以稳定导入操作标识幂等保存。
- 成功核对服务端版本后标记该草稿已导入；失败保留草稿，不自动清空。
- 刷新/另一台浏览器可读同一布局。选中图ID可继续作为个人浏览器偏好，不需要因此新增一套用户配置表。
- 热区删除后保留可见的失效摆放提示，由用户清理；不能静默消失。
- 编辑器常驻“只改变展示位置；检测范围、名称与计数关联在布防中修改”。
- 布防跳转使用来源+处理器的原入口；需要直达时扩展原监看页入口，共用保存会话，不新增布防编辑器。
- 先保证保存、冲突与取消；撤销/重做只作用当前草稿，后续添加，吸附/CAD能力不列首版。

## 8. 停留与真实热度：先复用观测，再补派生量

此阶段在首版真实统计完成后实施，不以“需要热图”为理由再拉流、再检测、再存一份截图。

### 8.1 先做能力核对

沿 observation-pump.mjs → ingestion.mjs → engine.mjs/episodes.mjs/geometry.mjs 检查：
- 是否有真实检测的bbox、track_id、会话、时间、来源尺寸与几何版本。
- 跟踪是否稳定，detections-only/预测/低置信状态如何标记。
- 未启用告警但启用统计时观测是否仍进入同一链路。
- 现有规则筛选、no_active_monitor和source_binding检查是否支持该统计订阅。

复用已有规则快照、区域几何和调度；需要新增统计能力选项时扩展原配置及观测资格，不创建隐藏告警、平行规则库或第二个消费者。

### 8.2 单一实现位置

区域进入、退出、停留和累计时间统一在现有 alarm-service 分析链路扩展。AI仅在已有观测缺字段时补输出，不同时计算另一份停留。模型推理仍在BPU；基于既有坐标和时间的业务计算无需新模型。

按“处理器+会话+track_id+热区及几何版本”保存有界访问状态。开始于区内的目标只能得到观测停留下限；预测帧不补真实停留，长缺口截断，重连不冒充同一人。无跟踪输入不得启用目标级停留统计。

### 8.3 最小持久数据

不能只保存不可重放的加一累加器：
- 复用当前prepare/materialize/checkpoint，在同一个已准备结果中持久化新增派生结果，稳定键防重放重复。
- 优先扩展现有行为/活动记录承载语义匹配的区域访问结果；若无合适结构，才新增一种有界区域访问事实集合，说明原结构不足，禁止同一访问再写另一份镜像。
- 保存访问起止、真实观测时长、完整/截断原因、来源和版本、必要证据引用；不长期保存逐帧全量轨迹。
- 若需按小时拆分停留，从同一访问状态生成有稳定键的时间片，跨桶按真实观测时间分摊。不能把整段时长都放在退出桶。
- 5/15/60秒阈值由原始访问时长查询得到，不再独立采三套计数。

图像网格热度复用同一次观测，按时间积分，不按帧数叠加。只保存限定分辨率、限定周期的网格摘要和覆盖，超限明确降级并记录缺口。历史未采网格不能从区域总次数伪造恢复。

### 8.4 空间和资源边界

首版停留图可在原摄像机画面坐标展示；平面图继续显示区域级数值。真实落到地面图必须有校准、版本和误差验证；复用项目已有全景/坐标变换能力，ERP不能直接套普通四点透视。

派生状态有区域数、目标数、内存、写入频率和超时上限；沿原租约与恢复机制，无独立无限队列。记录统计缺口与故障，不能拖垮告警、归档和录像。任何旁路丢弃仅针对新增派生量，不能删改原有识别归档。

## 9. 查询性能与数据保留

首版直接复用现有Mongo聚合与索引，不提前新增小时表或PG事件副本。先测1天、7天、28天和50计数器边界，记录耗时、返回体积、CPU、内存以及录像/检测影响。

建议初始验收目标（需在板端实测，非现有性能承诺）：常用1天查询P95≤2秒；28天规律P95≤5秒；范围不变重复刷新无重复面板请求。达不到先检查过滤、索引、投影、查询限制，再考虑汇总。

如必须预聚合：
- 在原统计模块增加可重建Mongo汇总，不新开数据库或独立调度服务。
- 汇总带来源区间、规则/绑定版本和构建进度；处理迟到、重放、清空、删除与“按新计数线重算”。
- 修改历史映射后失效相关桶，重算完成前不显示旧口径为新结果。
- 只有原始事实仍保留时才承诺可重建；过保留期的历史显示不可重建。
- 同一画面供多个计数器查询不重复保存图片；引用现有证据生命周期，过期显示不可回放。
- 历史及重建临时文件落SSD，SSD不可用不回退eMMC。

## 11. 分阶段实施与验收

## 12. 必测矩阵与发布门槛

### 数据正确性
- 同一event重放不增计数；同一轨迹真实往返分别计数。
- 多计数器/多位置、不兼容目标、同一热区多个计数器、同一热区多张图。
- 历史解绑、方向版本修改、重新统计、删除和清空后明细/汇总一致。
- [from,to)边界、跨日、时区、DST、本期未结束、比较关闭与基期零。
- 断流、积压、无覆盖、未知、过期、暂停、只有进入、接口失败。
- 快速换筛选旧请求不能覆盖；同一范围没有重复面板查询。
- 告警多阶段、多热区命中、pending与时段发生量严格区分。

### UI与地图
- 三种横屏尺寸逐页记录根容器scrollHeight/clientHeight，并检查关键面板实际边界、按钮可达和文字可读；截图与尺寸测量同时保留。
- 在1366×768及1180×820验证真实长名称、多位置、错误提示出现时仍可操作。
- 地图与排名联动、方向和色阶明确；无覆盖与完整零值可区分。
- 真实浏览器验证Konva；jsdom替身测试不能替代画布验收。
- 并发保存、超时重试、导入重复、无权限、失效热区、SSD缺失和底图读取失败。

### 资源与发布
- 记录统计查询/派生计算前后CPU、RSS、Mongo响应、录像连续性、AI吞吐；首版不新增BPU推理负载。
- 执行相关前后端及分析服务测试，git diff --check；完整构建与类型检查结果单列。若按操作者约定类型检查由用户执行，应注明“待执行”，不能用vite成功代替通过。
- 仅发布已验收的任务范围；构建到隔离目录，核对并发改动。HTTP 200和脚本字符串只证明资源发布，不证明业务或UI正确。
- 备份遵守AGENTS.md：SSD /mnt/ainvr-ssd/ainvr-rollback/<服务>/<时间戳>/，每服务最多三份；PG迁移向后兼容，保留可回退程序版本。不得沿用交接中的系统盘五份dist备份模式。
- 未经明确要求不提交、不推送。文档、代码和实际部署状态分别汇报。
