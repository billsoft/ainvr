# 发售前访问控制与首次安装契约

## 用户鉴权与服务身份

- 管理密码以控制台的密码存储为唯一权威，录像配置里的旧 `console.token` 仅用于兼容读取旧配置，不再参与权限判断。
- 录像服务用 `CONFIG_SERVICE_TOKEN_RECORDER` 获取通道和 AI 目录。后端只对该服务放行这两个精确 GET 路径及原有受限配置接口，不授予修改用户密码的权限。
- 录像用户请求向控制台内部鉴权接口校验；请求异步执行且有 3 秒超时。缺少服务凭据或权威不可用时返回 503，不把故障解释成“未设置密码”。
- 浏览器登录或恢复已有登录状态时取得 HttpOnly、SameSite=Strict 的播放专用 Cookie。该值不能作为管理员令牌使用；修改密码后旧 Cookie 失效。退出登录清除 Cookie。
- 新录像播放/下载地址不再携带管理员 token。旧 query token 仅作兼容，仍由当前控制台密码实时校验。
- 原有局域网产品允许管理员主动关闭密码。关闭密码表示允许匿名访问，不是故障回退。

## 流媒体边界

- 对外 Web 入口提供 `/media/`、`/live/` 和 `/rtc/`，通过控制台校验播放凭据及业务授权。
- 1985 管理端口、8080 直连媒体端口只绑定宿主机回环地址；容器内部仍可访问。公开 `/srs/` 调试代理返回 404。
- 不通过 Node 缓冲大视频：鉴权是独立小请求，视频和 Range 仍由 nginx 直通流媒体/录像服务。
- RTMP/SRT 摄像机接入属于受信任摄像机网络；现有 RTMP 端口仍用于相机推流和内部读流。本设计没有把控制台密码扩展成所有第三方 RTMP 客户端的鉴权协议，不能宣称公开 RTMP 网络也受网页登录保护。正式部署必须通过网络隔离限制摄像机协议端口，禁止直接暴露互联网。
- 改密码拒绝之后的新 HTTP 请求、媒体分段和 WebRTC 建连；已经建立的长连接不会仅因改密码立即断开。需要强制断开已有会话时应执行管理断流，不伪称 Cookie 能撤销已经完成的 WebRTC 协商。

## 首次激活与管理员停服

离线安装器仅在首次创建 `ainvr-srs` 时登记 `start-pending`。执行器在获得可信有效授权后启动一次并消费该标记；未授权期间保留标记，不启动业务。因授权停止仍使用独立的 `stopped-srs` 标记。

普通升级不创建首次启动标记，执行器不能因为授权有效就反复启动管理员主动停止的容器。标记位于 systemd 的持久状态目录，执行器重启不会丢失首次启动意图。

## MongoDB 读取语义

图片和热力图查询须在销毁游标前检查错误。数据库不可用统一报告服务暂不可用；成功查询且没有图片才返回 404，成功聚合且无记录才返回空热力图。列表、图片和热力图遵循相同错误语义。

## 定版验收

1. 设置、修改、关闭密码；检查录像播放、目录同步、旧凭据拒绝、无效服务身份拒绝。
2. 检查公开 SRS 管理入口被关闭；登录后 WebRTC、FLV/HLS、录像 Range、360/SEI 仍工作。
3. 空白容器状态下首次安装与首次激活；管理员手动停服；到期后续期恢复。
4. MongoDB 不可达时图片和热力图返回 503，而不是图片淘汰/空数据。
5. 发布包需从定版源码重新构建，保留源状态清单、哈希和配套模型清单。构建机验证不能替代全新板离线安装。
6. 在承诺的相机码率、AI 模型和归档配置下做持续运行、磁盘满/网络中断恢复及目标浏览器验收；不得用短时间功能测试替代容量承诺。
