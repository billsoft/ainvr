# 跟踪身份与计数稳定性修复（2026-11-11）

## 问题与可复现证据
190 登船测试视频没有真实反向通行。原 4 FPS 四次反向集中在同一时段的不同采样相位。
第 3442 帧的两个人员检测框几乎重合（分数约 0.682、0.270），分别接续新旧 ID；旧 ID 之前在计数线右侧，之后被接到左侧另一个人，计数器据此发布反向事件。
不能把 ID 相同视作必然同一人，也不能禁止所有反向来迎合单向测试视频。

## 本次算法边界
在公共 ByteTrack 适配器入口将同类别 IoU >= 0.90 的近重复测量只保留最高分项：
- 原始检测框与候选数组不改写，原始 observation 索引保持稳定；
- 类别隔离，普通重叠、同位置不同类别不抑制；
- 同一 eligibility 掩码用于 ByteTrack 正常输入和 unmatched recovery；
- 被抑制的框不能通过恢复阶段再次接走旧身份；
- 继续支持低分接续，不允许低分新建身份；
- 保留已有真实折返、有限线段、两侧稳定样本、毫秒间断上限规则。

增加身份恢复的有界合理性检查：保留最近 >=0.25 的参考位置和运动（最多既有 gap_ 秒）。低于 0.25 的候选可续接显示身份，但不更新该参考。
弱观察之后，只有“此前位移超过框尺寸噪声、接续位移与参考运动相反、跳移超过参考框对角线”三条件同时满足，才拒绝沿用旧身份。
此检查同时覆盖内部 ID 的直接别名路径和丢失恢复分配路径；不改变正常连续高分关联。参考状态随身份过期或 Reset 一起释放。
0.25 是恢复参考分数下限，不是模型概率或准确率。此路径仍可能误拒绝完全遮挡下真正的大幅折返，不能把不可见过程当作已知事实。
旧别名被拒绝后，仍需达到既有 0.60 门限才能创建新身份，不能让弱框通过别名失效旁路新建轨迹。

## 帧率变化与超参数
运动预测与速度使用真实源 PTS 差；框跳移和噪声按目标自身尺寸归一化，不固定为某个像素距离。
低帧率并不自动扩张用户设置的毫秒间断上限，也不恢复已撤回的整帧取整策略。
IoU、分数下限等无量纲参数不随 FPS 机械变化。越线仍需真实样本数与稳定时长同时满足，不能低帧率下只凭预测确认。
原生回归增加混合 1/6、1/2、1/4、1/3、0.8 秒间隔，含弱观察后的真实转身，确保不依赖固定帧节拍。

这是基于实测根因的有界修复，不新增模型、副本、数据库或 ReID 推理。
原始检测展示仍保留检测器输出；本次约束的是跟踪候选身份，不能宣称所有原始画面重复框都已消失。
复杂遮挡下两人几乎完全重合仍可能被抑制，需要多场景验证，不能宣称通用跟踪准确率 100%。

## 没采用的改法
仅把 passage-continuity 中 reversal 检查应用到所有短时遮挡：隔离实验虽消除四次反向，但正向总数减少十次。
不把该实验当作生产修复，也不扩大全局间断时间、降低检测阈值或禁用反向计数。

## 时间轴修正
旧探针按 i/30 写 PTS，而源视频是 25 FPS，旧 2/3/4/6 FPS 表不能作为正确帧率的验收依据。
test/ai_port/align_replay_pts.py 使用 ffprobe 的逐帧 presentation timestamp 与实际 time_base，验证源时间单调、缓存顺序与帧数一致后生成新缓存。
输入缓存不覆盖，输出存在即失败；支持变帧率时间轴，不再硬编码 25 或 30。
新增测试覆盖实际 25 FPS、可变间隔、非单调时间和帧数不匹配。
本次抽样按精确源时钟重跑 2、3、4、6 FPS，各 25 相位；6 FPS 不再用每 4 帧一次的 6.25 FPS 冒充。

## 验收标准
- 问题视频修复后反向数降至零；正向匹配与额外计数不能被反向过滤掩盖。
- 参考 74 为全帧率算法结果，不是人工逐人真值。匹配在三秒窗口内按一对一时间匹配，不能当作身份准确率。
- C++ 测试覆盖真实折返、低分接续、遮挡恢复、不同类别、普通重叠和近重复恢复竞争。
- 保留计数器正反向与间断规则回归。
- SSD 串行构建，部署前保存二进制与来源校验；发布后核对服务、通道、帧率、重启和错误日志。
