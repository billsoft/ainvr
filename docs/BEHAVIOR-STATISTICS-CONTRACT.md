## 数据流与存储

检测/跟踪结果 → 独立告警分析服务 → 行为事实 → 统计查询；同一事实也可产生告警。
行为事实不依赖是否开启告警、是否确认告警或是否未来通过 VLM 复核。
PG 保存区域、监控规则、标签版本与参数；MongoDB 保存不可变行为事实及告警；SSD 保存原帧证据。
不逐帧将轨迹全量长期入库；保留事件所需轨迹片段及证据引用，实时轨迹保留有限窗口。

## 事件字段

| 字段 | 语义 |
| --- | --- |
| schema_version / event_id | 协议版本、重放稳定唯一 ID |
| event_type | appearance / region_approach / region_contact / region_enter / region_traverse |
| channel_id / input_stream_id | AI 处理器与输入流身份，不能混用 |
| stream_session_id / track_id | 视频会话与跟踪身份；不承诺跨会话真实人员识别 |
| label_id | 稳定标签 ID；目标协议还须绑定 label_map_version，不能只存显示名称 |
| zone_id / zone_version | 警戒区及其几何版本；全画面出现可以无区域 |
| rule_id / rule_version | 产生事实的规则及版本 |
| episode_id | 同一次活动过程；未建立关联时为 null |
| started_at / occurred_at | 已知开始时间、行为确认发生时间；UTC |
| source_pts_ns / frame_id | 原始帧绑定；大整数时间戳用十进制字符串 |
| direction | 进入/离开方位和运动朝向分别记录，未知为 null |
| evidence_refs / analysis_evidence | 原帧引用、必要轨迹及判定依据 |
| quality | 观测或预测依据、轨迹完整性；不将未知当已确认 |

二维接触不代表真实物理碰撞。完整区域穿越必须有可信的外→内→外观测。不能因为穿越就补造未实际观测到的接近事件；也不能用预测跨越补造确认事实。

## 次数、目标数及去重

1. 同一 event_id 只入库一次，重试、重放不增加次数。
2. 每帧仍位于区域内，不等于每帧发生一次侵入。使用状态转换、边界滞回和重新触发条件；离开并满足重新触发条件后再次侵入才是新次数。
3. 同一目标一次活动可各产生接近、侵入、穿越事实。这三项不能相加称为人数。
4. 跟踪目标数按 channel_id + stream_session_id + track_id 去重。断轨换 ID 会影响数量，界面应称“跟踪目标数”，不能宣称真实独立人数。
5. 区分规则命中次数与区域行为次数。当前实现按规则产生事实，多条重叠规则可能重复描述一次行为；跨规则归并尚未实现前不得标为区域客流总量。
6. 告警确认、合并及屏蔽不改写事实。将来人工排除统计应有独立审计和明确筛选口径。

## 时间统计与界面

默认按 occurred_at 查询 [from,to)，UTC 存储，用户时区显示。跨桶事件只在确认发生的桶计一次；停留时长是另一指标，不能与发生次数混算。

目标页面提供时间范围、通道、区域、标签、行为筛选，显示“发生次数”和“跟踪目标数”，并能下钻到对应事实。当前时间/通道/行为入口及事实下钻已实现，区域/标签筛选已在 API 支持，页面选择器仍需补齐。分钟/小时/天分桶与 UTC 边界裁剪已实现；查询方向过滤及规则/区域版本拆分仍待补齐。

输入断流、积压、未启用分析、数据已过保留期均不能解释为零事件。结果需同时显示覆盖状态；只有确认覆盖完整的空桶才能显示为零，其他显示“数据不完整/未知”。

事实是可追溯来源，汇总是可重建结果。后续按数据规模增加汇总表；不使用不可重放校验的累加计数器作为唯一依据。

## 规则方向筛选与统计查询的区别

监控器的 behavior_settings 可为每种行为设置 direction_filters。规则引擎先产生观察到的行为候选，再根据参考方向和角度扇区判定；只有命中者物化为该规则的行为事实，并参与统计及告警。没有设置过滤条件时不限方向；设置后未知方向不匹配。多个条件取 AND，例如穿越需同时满足左侧进入、右侧离开。

此设置不是历史统计查询的方向过滤器。修改规则会产生新规则版本，不能重解释或删改既有事实。direction 仍保存实际进入/离开/运动角度，供后续查询和其他消费者使用。协议及示例见 ALARM-DIRECTION-POLICY.md。
