# 统计分析产品设计与实现契约

版本：2026-10-31。适用 `/analytics`，当前开发基线 `36ecc7e`。本文是后续客流/告警统计的产品设计入口；历史实施记录用于追溯发布，不替代本文的交互和口径定义。

## 1. 目标与边界

给值班人员看哪里、何时、何种告警需要关注；给管理员看哪些规则产生审核负担；让所有图表能回到同范围告警证据。统计页不承担逐条审核，复用已有告警列表、审核和录像链路。

不建立第二套采集、事件库、图表库或播放器。沿用 React/TypeScript/Tailwind/Konva、现有 backend BFF、alarm-service、MongoDB 事实及 PostgreSQL 配置。告警统计不以计数器为前提，未关联计数器的规则也必须进入统计。

## 2. 信息架构与视觉

同一路由顶部增加“统计对象：客流分析 / 告警分析”。客流保持现有总览/客流/热区/规律；告警使用总览/热区/规律/审核质量。URL 保存对象、时间、页签、告警位置/触发器/主类型；刷新、后退和复制链接可恢复。切换对象保留时间；从客流转告警携带已选位置，明确“沿用客流位置，可切换全部”。告警特有筛选不影响客流，返回时恢复客流原选择；不隐式把所有告警映射为某个计数器。

沿用原型紧凑工具栏、细下划线页签、白色圆角面板；主色仍蓝色操作色，告警图表采用琥珀色，危险/错误提示才用红色。标题、图例和单位必须足以区分口径，不能只靠颜色。小屏可换行、面板内滚动；1366×768、1180×820 的四个页签在说明折叠时主要信息一屏且无横向溢出，1920×1080 比例自然。长排名在面板内滚动，展开说明允许页面滚动；不通过裁切核心内容、缩小字体或锁死溢出来达标。

告警总览四个 KPI：范围内新增告警、其中待审核、人工确认、人工判为误报。下方左侧时间趋势与触发器排名，右侧平面图与数据说明。全部积压入口独立链接到既有“待审核/全部时间”，不混入选定发生时段 KPI。

热区页：共享服务器平面图，独立告警数量相对热度层，透明规划框，只显示位置名称，读数在排名表和选中说明。复用 PlanCanvas/heatCells/底图编辑器；不是摄像头真实坐标投影。没有规划图时临时排布并明确未保存；未布置位置及未知/重复 zone_id 明确列出，禁止把相同 zone_id 的不同通道静默相加到一个规划框。告警色带由共用 Canvas 可选 palette 支持，默认客流样式不变。

规律页：星期×小时原始已记录告警数量矩阵，键盘/点击可下钻，标注时区；不以四个稀疏样本自动标“异常”，不把无采集的零解释为安全。审核质量页采用专属 KPI 与两组明确分母的分布，详见下节；禁止用线性漏斗误导 AI/人工为必经流程。

### 客流总览地图优先（2026-10-31用户修订）

总览以查看完整底图和多个热区分布为主：右侧地图约占主内容70%宽度并贯穿高度；左侧依次为紧凑趋势、四周规律预览、可展开的位置覆盖明细。保留顶部KPI；完整客流和规律页承接深入分析，不改变计算口径或新增采集。

移除客流地图右侧热区排名表。进、出、当前方向占比随热区作为独立屏幕标签层显示，与底图和热力层使用同一等比例居中变换；规划框仍透明，标签不能替代热力。名称、方向和未知值可辨，长内容提供完整辅助名称和选中明细。

标签先在对应热区附近避让，再用连接线标明位置；密集时显示紧凑标记，点击优先展开该热区的数据。提供“数据标签”开关以查看无遮挡全图。标签只在浏览模式存在，不能写入规划图或改变布防范围。同一热区多个统计位置不静默相加，显示位置数并在选中明细中分别列出；不同计数器不混合。未摆放位置保留单独可展开入口，不能因为移除排名表而丢失。

验证需包含真实单热区和隔离多热区布局；隔离示例不能当作真实采集数据或模型效果验收。告警模块现有口径和排名不随本次客流调整改变。

### 审核质量页设计（2026-10-31复核修订）

质量页的任务是判断审核覆盖、样本结论与等待负担，不重复总览四个数量卡。顶部依次显示：

1. 人工明确结论数及其占范围告警总量的比例；称为样本占比，不是随机抽检覆盖或模型质量。
2. 人工样本误报占比，始终伴随“误报数 / 人工明确结论数”；分母零显示“—”。非随机样本、不是AI误报率的短提示保持可见，不因样本超过20而隐藏。
3. 发生至首次人工审核中位数，伴随有效样本数量；P90和无可靠时长数量在质量内容中可查。不是首次响应或处置完成时长，包含入库延迟，仅反映已审核样本。
4. 至少1小时待审核数量；这是描述性年龄分段，不是未经业务定义的SLA超时。零值中性展示，非零温和强调，不直接使用故障红色。

内容分为审核主体分布、人工结论分布、规则审核质量与待审核年龄。主体分布以范围内总量为分母，人工结论分布以明确人工结论为分母，各自展示数量、分母和占比；不能让两组柱长暗示相同绝对数量。AI与人工数量差距较大时，保留清晰的数字，不使用对数或最小柱宽伪造占比。

规则排名默认显示业务名称；编号、执行版本移入可键盘展开的详情，提供编号复制和失败提示，不仅依靠鼠标悬浮。无历史名称时显示明确的历史引用提示，完整ID仍可追溯。长列表有界滚动，不挤占整页。

所有零值待审核年龄项保持中性。查看待审核的入口明确表示“范围内全部待审核”，现有API不支持年龄过滤，因此不将年龄卡包装成准确下钻。人工总样本数也不擅自映射到仅人工确认的过滤；具体结论可分别下钻。

复杂算法解释合并到页面的“统计说明”展开项；读数旁保留分母、样本偏差、非处置完成时长等直接影响理解的信息。折叠时三种验收尺寸需同时记录页面与工作区的scrollHeight/clientHeight，并查看截图；无横向溢出不能代替一屏验收。

## 3. 交互操作用例与验收

| 用例 | 操作 | 预期 |
|---|---|---|
| 对象切换 | 客流选择时间和位置→告警分析 | 时间与位置携带，显示可清除的范围提示；计数器控件换成位置/触发器/类型 |
| 查总量 | 点击新增告警 KPI | 告警列表携带准确发生时段及过滤条件，显示同口径范围，不只前端筛已加载50条 |
| 查审核负担 | 点击其中待审核/人工误报 KPI | 同一发生时段叠加审核过滤，状态不是模型准确率 |
| 查高峰 | 点击趋势柱或键盘选择时段 | 带该桶实际裁剪的起止时间下钻；结束时间不含 |
| 查规则 | 点击触发器排名 | 使用触发器稳定 ID，下钻包括合并告警的历史阶段，不只最高阶段字段 |
| 查位置 | 地图框/排名行选择→查看告警 | 选中态与读数同步；按 channel_id+zone_id 配对，不跨通道串联 |
| 查规律 | 点星期×小时格子 | 列表与统计使用同一时区、weekday/hour 条件，不把一个星期几当连续日期范围 |
| 看质量 | 切人工/AI或点击结论数量 | 独立分类，不把 AI 自动确认记成人工确认；样本不足显示数量和说明 |
| 编辑布局 | 编辑→预览→Esc→继续或放弃 | 与现有窗口一致；右上×；无隐式保存；只改布局，不改布防 |
| 刷新/导出 | 修改筛选后刷新或导出 CSV | 导出当前已成功查询范围及口径；失败不显示旧结果为新数据；CSV处理公式注入 |
| 错误与边界 | 断网、无告警、超过查询容量、无平面图 | 分别显示重试、零已记录/覆盖未知、缩短范围、临时布局；不降级成演示数据 |

筛选变化取消/作废旧请求；打开日期窗口和编辑器时不自动刷新。查询结果显示截止时间，当前审核状态可能在查询期间变化，标明非事务一致快照。所有按钮键盘可操作，触屏目标不小于44px；读数应有文字替代，不能仅依赖Canvas。

## 4. 数据来源与统计口径

| 指标 | 来源与算法 | 禁止误解 |
|---|---|---|
| 新增告警 | Mongo alarms，occurred_at∈[from,to)，alarm_id唯一事实 | 不是人数、触发次数或通知次数 |
| 其中待审核 | 上述发生时段内 handling.state=unacknowledged，排除已标误报 | 不是当前全设备所有积压 |
| 人工确认/误报 | acknowledged 且 reviewed_by_kind=human；明确 disposition | 主体不明的旧记录不能推断为人工 |
| 人工误报占比 | human_false_positive / human_reviewed且结论明确；分母0为null | 不是模型总体误报率；非随机样本存在选择偏差，超过20也不能证明模型质量；少于20另提示样本偏少 |
| 主类型趋势 | 使用告警当前最高阶段 behavior 作互斥分类，各类型相加=总量 | 多阶段不是多条告警；历史报表可能随升级变化 |
| 触发器/热区排名 | 每条告警提取去重的阶段关联，再按ID分组 | 分组可交叉，排名和可能大于去重总量；不是触发次数 |
| 规则版本 | rule/rules 快照版本列出 | 不混作规则改进效果证明 |
| 星期×小时 | occurred_at 转请求IANA时区，周一=0，小时0..23 | 原始数量，不是异常基线或每小时风险率 |
| 未关联 | 所选发生时段且其他筛选相符、没有任何有效区域归属 | 选位置后不应声称这是全设备未关联总量 |
| 发生至首次人工审核 | 明确人工主体的 handling.acknowledged_at−occurred_at；现有流程保留首次人工结果，不能被AI或更高阶段覆盖；非法/缺失/负时长排除并计unknown | 含采集入库延迟，不是处置完成时间；不能还原AI重开周期 |
| 待审核年龄 | 本次查询时刻−occurred_at，分<10m/10m—1h/≥1h | 选定发生时段内当前待审核，不是历史积压快照 |

业务配置与名称优先复用 PG 下发的现有 Mongo 执行快照，不直接让前端连数据库。历史名称来自事件快照；缺失时显示稳定ID/历史引用，不把当前规则名字伪装成历史名称。不新增观测。现有有效布防/采集分母尚不能覆盖所有告警规则，因此第一版不输出每布防小时率、每千次通行率或覆盖修正总量；显示覆盖未知，并保留服务/通道状态入口。

## 5. 前后端契约（先UI、后接线）

新增有界只读聚合 API `POST /alarms/events/analytics`，BFF转发至alarm-service `/v1/events/analytics`，复用登录、服务令牌和错误处理；不改变已有statistics契约。前端开发测试使用显式fixture，生产service只请求真实API，不提供随机或静默示例回退。

请求：`{from,to,timezone,bucket:'hour'|'day',locations?:[{channel_id,zone_id}],trigger_id?:string,primary_type?:string,audit?:'pending'|'human_confirmed'|'human_false_positive'|'ai_reviewed'|'unknown',weekday?:0..6,hour?:0..23,association?:'unassociated'}`。最长31天；locations不传=全部，空数组非法；ID/字段/时区严格验证，禁止任意Mongo语法。组合位置和触发器必须落在同一个实际阶段关联中，不允许A区与B规则交叉拼接。

响应：`{schema_version:'1.0',from,to,as_of,timezone,bucket,total,pending,human_confirmed,human_false_positive,ai_reviewed,unknown_review,trend:[{from,to,total}],zones:[{channel_id,zone_id,name,total,pending,human_reviewed,human_false_positive}],triggers:[{trigger_id,name,total,pending,human_reviewed,human_false_positive,rule_versions:number[]}],types:[{id,total}],week:number[7][24],quality:{human_reviewed,false_positive_ratio,wait:{samples,median_ms,p90_ms,unknown},pending_age:{lt10m,lt1h,gte1h}},association:{unassociated},catalog:{zones:[{channel_id,zone_id,name}],triggers:[{trigger_id,name}],types:string[]},consistency:'non_transactional',coverage:'unknown',issues:string[]}`。

目录由所选时间范围内事实和已应用的规则快照提供，包含有历史数据但已停用的引用；禁止把现有计数器列表当告警目录。输出排序确定、范围有界，超量查询明确拒绝并建议缩短范围，不静默截断。日期分桶遵守请求时区和夏令时，小时桶保持真实绝对时间。

下钻链接 `/alarms?status=all&analytics_scope=<JSON请求>`。扩展现有告警列表的严格scope解析及服务过滤；后端聚合和列表共用同一filter构造，cursor绑定完整scope。旧locations链接保持兼容，非法scope不回退全量。保留列表逐条审核、录像和分页，不另造第二套操作界面。

## 6. 开发与发布次序

1. 文档与契约先落库；审计现有日志，必要时收紧时长定义。
2. 前端实现对象切换、告警四视图、筛选、导出、下钻和共享地图；组件fixture测试覆盖成功/空/错误/竞态，浏览器检查布局。
3. 后端实现共用过滤、聚合、目录和时间口径，真实独立Mongo测试跨阶段去重、跨通道位置、未知主体、时区、容量及分页一致。
4. 接线后全链路测试，真实页面三尺寸截图、类型检查和构建；不把fixture截图冒充真实数据验收。
5. SSD每服务最多三份备份，发布清单记录source/build摘要，检查readyz和受保护服务PID；只更新必要服务。提交范围独立，不自动commit/push。

## 7. 明确后续能力

需要可靠有效观测区间后才增加风险发生率；需要足够周样本和基线稳定性验证后才增加异常提示；需要人工复核关联完整后才增加AI改判分析。第一版的事实数量、当前审核质量和证据下钻必须真实完成，不用“待开发”卡片填满界面。

## 8. 统计验收算例

- 同一告警经过 A、B 两个热区：全局总量为1，两区各为1；图例说明排名不可相加。选择A区和仅发生在B区的触发器时，这条告警不入选。
- 通道甲和乙都有名称“入口”：关联键仍为各自的 channel_id + zone_id；名称和重复 zone_id 都不能作为跨通道合并依据。
- 20条明确人工结论中4条误报：人工误报占比20%；另有80条AI审核不进入这个分母。未审核、主体未知、结论不明均不能当作人工正确样本。
- 发生在范围起点的告警计入，恰好在范围终点的不计入；前后两桶相加不得重复计数。星期和小时以指定时区的发生时间计算。
- 首次人工经过时间排序后，中位数取中间值（偶数取中间两值均值），P90使用最近秩法，第ceil(0.9×n)项。n=0显示“—”；n<20提示样本偏少。负值、缺失、非法时间排除并展示排除数量。
- 无告警显示“0条已记录告警”，同时保留“采集覆盖未知”；不能显示“零风险”或“100%正常”。
- 某规则升级后同一告警最高阶段变化，主类型可能变化，但总量仍为1。报告采用查询时当前状态，不伪装成不可变的历史快照。

所有查询只读取现有事实；查询容量、超时和输出大小均有边界。当前上限为所选日期范围50,000条事实、1,000项排名、5,000项目录、1.8MB结果；Mongo聚合限时5秒。目录保留同日期的其他位置供切换，因此事实容量按整个日期范围判断，缩小位置不会绕过此上限。超限提示缩短日期；不能截取前N条继续展示为完整统计。
