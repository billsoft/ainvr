# AINVR GDC 与 CPU 后备路径

2026-10-11 板端实测：GDC CUSTOM 映射可完成完整 ERP（经度 360°、纬度 180°）到普通透视画面的变换。它与鱼眼到 ERP 是不同方向的映射。本接口不把原始鱼眼或裁切后的局部 ERP 当作完整球面输入。

## 已接入的处理顺序

统一入口为 `ai-service/src/platform/image_preprocessor.hpp`，输入紧密排列的 NV12，输出 RGB/BGR float32 CHW。

- 普通缩小：符合条件时 PYM → GLES 颜色转换/归一化/补边。
- ERP 透视：符合条件时 GDC → GLES 颜色转换/归一化。
- 专用硬件不支持或运行失败：GLES 执行完整操作。
- GPU 不可用：CPU 执行剩余操作，保留投影、采样、颜色范围和归一化语义。

`backend` 明确区分 `pym+gles-color`、`gdc+gles-color`、`gles`、`pym+cpu-color`、`gdc+cpu-color` 和 `cpu`。硬件异常保存在 `fallback_reasons`，失败后不在同一个实例里逐帧重试；恢复设备后需重建实例。非法参数直接报错，不以切换后端掩盖。实例的调用与析构必须在所属线程。

相同输入/输出尺寸与视角复用一份 GDC 映射；视角改变时重建，`gdc_configuration_ms` 报告本次建立成本，复用时为零。目前仅缓存最后一个视角，不代表多目标每帧重建可达到实时要求。

## 能力边界

目前 GDC 包装层保守限制输入/输出宽 ≤3840、高 ≤2160，宽按 16 对齐、高为偶数，最小 96。这是当前已验证路径的范围，不是硬件最大尺寸的结论。8K 输入转 GLES。跨越 ERP 左右接缝或极点附近的视角也转 GLES，避免网格跨经度跳变插值错误。最近邻采样不改用 GDC。

当前采用显式 NV12 输入/输出拷贝及缓存同步；没有声称零拷贝。GDC/PYM/VPU 共用 SDK 内存模块生命周期。CPU 路径使用普通 C++，没有 CUDA 或 OpenCV 依赖；该后备实现尚未进行实时多路性能验收。

## 测试结果

`test/results/gdc-integration-20261011/ctest.log` 保存完整执行证据。GDC 输入 1920×960，输出 640×360，三个 yaw 为 0、0.7、-1.2 弧度，pitch 为 0.15；每个视角实际执行 12 帧，并与独立 GLES 投影对拍。测试图包含非恒定 Y、U、V。

| 项目 | 本次短测结果 |
|---|---|
| 映射计算、生成配置及启动 | 约 26–30 ms/视角 |
| 固定映射下拷贝与 GDC 处理 | 约 0.54–0.56 ms/帧 |
| RGB 平均绝对误差（0–255） | 约 0.056 |
| 最大 RGB 误差 | 小于 1.7 |

这些结果不包含解码、模型推理或归档。合成渐变图对拍验证几何/色彩基本接口，不能代替真实图像的细节质量和模型精度验收。

CPU/GPU 对拍覆盖双线性、最近邻、补边、BT.601/709、全/有限范围、BGR 和跨 ERP 接缝；测试还将 DRM 设备路径临时指向不存在的位置，实际触发 GPU 初始化失败，验证 CPU 后备和原因报告。所有环境变量在测试结束后恢复。

复测：`python3 test/ai_port/verify_pym.py`，在板端串行运行，会保存新的独立日志。

完整 AI 通道 worker、目标截图开关与归档仍需接入；当前的库实现与测试不等同于整套服务上线。鱼眼→ERP 的已有实验尚需另行接入业务输入管线。
