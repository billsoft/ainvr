# AINVR 中文智能检索：产品与技术设计

> 2026-10-29 修订。状态：默认 SigLIP2 基础检索已部署并启用于开发测试环境；当前后门 AI 输出的实际采样、SSD 索引和 Native 中文查询已验证。独立现场效果、登录后的完整界面整链和 M4 大历史模型切换仍待验收，不将基础上线等同全部目标完成。发布与回滚见 `AI-SEARCH-RELEASE-20261029.md`。本稿继续作为验收依据，聚焦“找到并核实录像证据”，不新增一套监控工作台。
> 技术约束：复用 PG、MongoDB、现有媒体与 AI 服务；不新增 SQLite。模型生产推理使用 S100P BPU；容量与效果以实测为准。

## 0. 用户价值、重点功能与范围

用户需要的是少盯屏、少拖时间轴、少重复确认，同时不漏掉重要证据。产品首先回答三个问题：发生了什么、依据在哪里、我怎样最快核实。搜索框和模型只是实现方式。

当前优先用户假设是值班人员、事后查证人员和设备管理员。上线前用实际操作验证：值班关注少打扰且不漏重要事件；查证关注找得到、看得清、能回放；管理员关注不影响录像、范围有权限、空间可控。不能把这些假设当作已完成用户调研。

**首版主打“一句话找录像，一眼看依据，一步看前后”。** 先做好下面一条操作链，不并行开发大量新入口。

| 用户任务 | 产品响应 | 验收重点 |
|---|---|---|
| “找昨天下午背黑包经过后门的人” | 用户明确选择时间和通道，描述外观；返回目标及场景候选 | 首屏找到有效候选的比例和耗时 |
| “这条到底是不是我要找的？” | 同一详情展示大图、少量关键时刻、有来源的复核状态 | 看清目标，不需要在多个页面找证据 |
| “看他来之前和离开之后” | 一键定位正确录像，默认从证据起点前 2 秒开始，可继续前后查看 | 来源、时间、播放连续性正确 |
| “没找到，是没有还是没分析？” | 显示采样覆盖、积压、故障及录像是否存在 | 不把缺数据误导成未发生 |

演进路线为“看得见 → 看得懂 → 帮助发现 → 帮助解决”。已有规则告警已承担部分主动发现；首版文搜帮助查证，语义布控、摘要和处置协助仍独立排期，不能说主动发现全未实现。

### 首版与后续的取舍

首版必须交付：中文描述、时间／通道筛选、目标＋场景索引、结果详情、录像定位、覆盖状态、相关性反馈。大模型渐进复核独立验证后增强，暂不可用不能挡住基础搜索。

暂不加入：自由聊天助手、自动调查报告、日常摘要、处置工单、通知、一句话布控、身份认定、自动跨镜追踪、LocateAnything 模型切换框选。以当前结果搜相似留下一期：可复用同版本视觉向量，不一定需要新模型，但仍需验证图图检索、视图匹配、权限和交互；相似候选不能认定同一人。它们各有价值，但都不是本期“找录像”闭环的必要条件。

已有告警继续负责主动发现，计数负责通行事实。搜索负责查证，不能把搜索相关性结果写成告警结论，也不能把同一人真实往返折叠成一次计数。

### 竞争机会与定位

海康 AcuSeek 和大华 WizSeek 已提供自然语言检索，不能把“有搜索框”当作独有突破，也不能从厂商未公开细节推断其没有精排。相关官方资料见文末。

AINVR 应先在登船口等具体场景做得更省事：从热区计数或告警进入对应证据；多人画面中明确指定目标；上下文和前后时刻一起查看；第三方摄像头接入后的体验一致。此类入口逐步复用现有流程，不增加一套独立统计或告警页面。

真正可争取的优势是“用更少操作可靠查清一件事”。与竞品比较必须同视频、同查询、同人工标注，记录 SKU、固件和摄像头组合；未对照测试不宣称超越。

## 1. 操作界面：先找，再核实

### 1.1 默认页面

沿用现有页面框架，提供一个“智能搜索”入口。顶部为描述输入框、时间范围和通道选择，主区为结果；空态用少量真实能力示例。首版不另加仪表盘大卡片、不新增聊天窗。

时间选择复用 DateTimeRangePicker；通道支持名称搜索和已有分组能力，未实现的分组不作为首版依赖。最近使用范围可记忆，但每次都清晰显示；从告警／回放进入时继承其来源和时间，并允许清除。

默认同时搜目标和场景。本期不提供未贯穿权威召回的类别硬筛选；后续验证后可放在“更多条件”，避免用户因检测器不识别某物而把它排除。“昨晚”“西门”首版不自动理解成硬条件；明确提示通过时间／通道控件设置，不让用户误以为自然语言约束已生效。后续可增加需点击确认的时间／通道建议，但“昨晚”等词涉及时区和边界，不能假定规则解析没有歧义。

用户不选择模型、关键帧数量或 BPU 优先级。搜索页可通过滑块和数字输入设置最低相似度，范围 0～0.20、步进 0.005，默认 0.07 仅作试用起点，支持“不限”；不是置信度或概率。点击搜索后冻结门槛，服务端过滤后发布快照并分页，改变门槛须重新搜索；空结果只说明未达到门槛，不证明事件未发生。高级资源设置仅在系统配置中提供必要项目。

### 1.2 首屏与证据详情

卡片只突出图片、摄像头、发生时间和复核状态，不堆技术字段。检测目标画明确边框；场景命中只标“匹配画面区域”，不冒充精确目标定位。相似分数不包装成概率。2026-10-30 诊断增强：卡片与详情显示原始余弦相似度（四位小数），查询、分页和详情复用同一快照分数；旧接口无分数时明确不可用。说明最多返回 60 条候选、第一名也可能不匹配。不得以与第一名接近、固定差值或未经标定的 sigmoid 值标成高可信；最低相似度过滤遵循上文搜索条件约定，不改变候选排序或启用搜索大模型复核。

点击后用同页详情面板展示大图和关键时刻，保留列表滚动、筛选及选中项。目标竖图、横向场景图都自适应，不留无意义的大块空白，不裁掉证据。默认主图选质量较好的命中帧，不机械选择最早帧。

详情主操作只有“播放前后录像”；次操作为“相关／不相关”。支持键盘切换相邻结果和触屏操作；输入框中不抢快捷键。已有导出入口仅在权限和录像能力支持时复用，不为文搜另建导出器。

“匹配依据”分清来源：规则事实显示来源与时间；模型复核显示受支持的结论；没有生成能力就不编造流畅解释。单帧不能证明走入、放下、遗留等过程，必须有前后证据，否则标无法判断。

### 1.3 渐进更新与操控感

先出候选，后台补充有限的头部复核。标注“候选／复核中／符合／不符合／无法判断／暂不可用”，不要求用户理解模型分数。

后台更新不得移动用户正在点击的卡片、自动切走当前证据或重载播放器。初始结果顺序在当前浏览期间稳定；提供显式“重排已加载结果”；后续分页追加，选中证据保持，不能将已加载重排称作全历史排序。新查询取消旧的未开始任务，晚到结果不得混进新查询。

加载时有即时反馈；可以取消和修改条件；失败说明可采取的下一步。首批结果、复核、录像分别显示状态，避免一个大转圈遮住全部内容。触控目标至少 44×44；×、取消和 Esc 共用草稿保护流程。

交互预算作为待测目标：点击反馈 ≤100ms、详情先展示已有缩略图 ≤300ms、录像真实首帧 P95 ≤2 秒；分别记录网络、取段和解码耗时，不能把占位图当首帧。触屏不依赖悬停，窄屏详情优先保证大图可读，不强制挤在小型底部面板；滑动切换避开图片缩放和平移、时间轴操作，主操作保持可触达。

### 1.4 可信与少打扰

覆盖按来源和目标／场景分别显示已采样、待处理、缺口及未知；故障原因与录像可用性由各自权威接口单列，不能从覆盖gap推断无录像。已采样不代表每个瞬间都被理解，“未找到”不等于事件不存在。

录像已过期而证据图片仍在时保留图片并标明状态；不静默隐藏。模型不确定时保留候选，让人直接看证据；不通过强制确认降低表面的人工量。

## 2. 统一架构与复用边界

```text
输入媒体 ───────────────────→ 现有录像服务
   ↓
ai-service 真实检测／跟踪 → 有界关键帧与场景采样 → 硬件图像处理／BPU 编码
   ↓
Mongo 检索历史／图片／向量 → SSD 可重建索引
                                  ↑
现有控制台 → 鉴权与范围 → 文本 BPU 编码 → 检索候选
                                  ↓
                   可选 llm-service 复核 → 同页证据与现有录像回放
```

采用独立 C++ search-service 隔离检索计算和索引负载；控制台管理仍由 TypeScript／Fastify 承担。PG 配置和管理任务由后端维护，搜索服务通过版本化内部接口领取及回报，不建立第二套管理 API。文本编码复用原生 BPU 执行基础设施，图像编码扩展 ai-service 硬件能力，M1 先验证共存。

ai-service 不同步等待搜索。帧租约、硬件缓冲、异步队列都有上限；压力下丢弃检索候选并记覆盖缺口，不能堵住原有观测、告警、录像。进程隔离不等于算力隔离。

| 能力 | 唯一归属／复用入口 | 禁止重复建设 |
|---|---|---|
| UI | React／TypeScript、现有 Tailwind、lucide、日期和回放组件 | 新 UI 框架、播放器、日期转换规则 |
| 来源身份 | 后端 channelService、现有来源解析；前端 monitorSource 仅展示 | 按名称或流地址猜摄像头 |
| 跟踪与穿越 | ai-service 观测；alarm-service geometry／traversal／passage-continuity | 搜索版跟踪器、跨编号接续、穿越算法 |
| 图像与帧身份 | snapshot_plan／transform、erp_perspective、platform | 新裁剪／全景投影和录像解码链路 |
| 模型执行 | 既有 BPU 适配及 llm-service 执行、驻留、容量与错误契约 | 第二把驻留锁、CPU／GPU 模型兜底、通用新模型平台 |
| 历史与管理 | PG 管配置任务；Mongo 管历史 | SQLite、独立向量数据库、重复权威数据 |
| 录像取证 | 受控 recording-evidence 链路、录像服务接口 | 直接读取 segments.db、伪造告警身份取图 |
| 回放导航 | 现有 alarmNavigation／Playback 提取共用导航 | 搜索另写输入输出跳转逻辑 |
| 安全与运行 | serviceTokens、mediaAuth、configApply、既有健康检查 | 第二套登录、配置生效口径和运维后台 |

同一概念共用契约和测试样本。跨语言优先调用归属服务，不逐行复制；C++ 纯基础能力可抽公共 CMake target，llm-service 已复用部分 AI 图像源码，可沿此方式整理。模型专用分词器仍须正确适配，不能为了复用而产生错误编码。

告警审核与搜索相关性是不同业务状态；图片校验可共用，删除范围与 TTL 必须隔离。持久任务和执行队列分别负责恢复与背压，但只有一个权威状态、租约和代次，不引入 Redis／Kafka／新工作流平台。

新增模块须说明已有入口为何不足、最小扩展、数据归属、上限和旧调用方回归。依赖沿用现有锁文件，不借此全库升级技术栈。

录像服务独立不等于 AI 输出录像不受 AI 停止影响。可提供原始输入独立录制策略，但不自动改现有配置。保留 source_input_id、processor_id、output_channel_id、recording_channel_id，回放按实际证据映射；同源多个 AI 输出不得串图或串轨迹。

现有系统密码与会话不等于多用户 RBAC。受控单管理员环境可先验证，多用户发布须补齐通道和操作权限。

检索降级丢弃的只是派生索引候选，不能抽样删除已产生的识别存档。原存档背压和故障策略沿用现有实现并单独观测，不在方案中承诺故障下绝不丢失。

文本塔明确由 search-service 编码适配器加载与释放，复用执行基础设施，并纳入同一跨进程资源准入和驻留契约。不能预设它是常驻小模型、绕过锁或资源预算。改放 llm-service 也不会消除资源竞争；现有协调不足时扩展统一契约，不另建一套驻留控制。

## 3. 存储：只复用 PG 与 MongoDB

**不新增 SQLite，不更换现有参数库镜像，不为文搜强行安装 PG 向量扩展。**

| 载体 | 内容 | 边界 |
|---|---|---|
| PostgreSQL 参数库 | 搜索配置、模型版本登记、通道策略、索引分片目录、当前任务与检查点 | 任务有 TTL／数量上限；目录按保留期清理；不放每帧向量和图片 |
| MongoDB 历史库 | 检索关键帧元数据、图片、向量、覆盖记录、查询反馈和受控审计历史 | 独立集合与保留策略；不要继承短期识别存档 TTL；历史放外挂存储 |
| SSD 索引文件 | 分片向量检索加速结构及校验清单 | 可由保留的 Mongo 检索历史重建，不是第三套业务数据库 |
| 系统盘 | 程序、HBM、分词器、必要嵌入／归一化文件与有限运行配置 | 不存无上限历史、spool 或重建临时文件 |

图片复用现有有界 JPEG 二进制文档方式：首版每图上限沿用 EvidenceImages 的 8 MiB 约定，实现时核对 BSON 总大小余量；超限明确拒绝，不自动引入 GridFS 分流。当前告警实现是内联二进制，不把 GridFS 写成已有能力。检索集合使用普通集合和明确 TTL／配额，不照搬 capped 滚动覆盖。FP16 为向量存储实验首选，与 FP32 比较召回和排序后定案；保存 dtype、维度和归一化版本，不断言误差可忽略。向量原值按版本在历史记录保存一次；ANN 文件可保存必要的派生编码，但必须计入额外空间。

数据标识至少包含：`record_id`、`model_version`、源输入／处理器／输出、录像通道、会话代次、轨迹 ID、UTC 时间、PTS、原图尺寸、bbox／透视参数、证据角色、质量、图片引用、向量编码。

轨迹键必须包含处理器和会话，不能仅用 track_id。稳定记录 ID 在重试中复用；Mongo 唯一约束保证幂等。

跨库不假设原子事务：历史记录先持久化，再投影到索引；PG 记录已提交检查点，任务可重放。索引确认前标待索引，崩溃重启不得静默丢失或重复。索引文件原子发布；启动核对清单、记录数量和版本。

SSD／历史库缺失时搜索明确不可用，禁止把历史和队列回退写 eMMC。配置和其他可独立运行的服务继续运行。存储根路径来自系统存储配置与挂载身份，不能硬编码设备名或把空挂载目录误当 SSD。

## 4. 模型选择与部署约束

工程默认采用 `siglip2-base-full-int8`：SigLIP2 Base 256（`google/siglip2-base-patch16-256`）的配对图像／文本塔、完整词表 INT8；so400m 配对包为备选，裁词表不默认替代完整词表。默认选择不自动启用服务，不覆盖用户已有的 so400m、空值或其他显式选择。各包须锁定模型 revision、许可证、程序／张量、分词器、维度和输入规范，并记录校验和。

默认文本塔已完成 128 条板端参考对照，输出均与原交付 HBM 一致，最低浮点余弦为 0.9962289；连续 2048 次调用未观察到 ION 增长，平均 17.94 ms。隔离双进程的真实 GLES／JPU／BPU → Mongo → 中英文查询及证据返回接口也已通过，强制 ROI 不作为检测或语义准确率证明。持久索引 runtime 已接线，真实隔离 PG／Mongo／HTTP 联调已验证发布响应丢失、重启恢复、增量刷新和旧分片清理；该轮使用合成向量及普通临时目录，外置 SSD 路径另有实盘验证，不能混称生产整链通过。实际通道整链和中文监控质量仍须验收；Flickr 英文检索结果同样不能替代现场目标、场景与查询的独立评估。

- 图像塔和文本塔均须编译并验证为 S100P BPU 可部署包。不得使用 CPU ONNX Runtime 作为生产文本模型兜底。
- CPU 可做分词、业务调度和向量索引检索；模型算子、学习型嵌入及归一化等按硬件执行约定逐项检查，不用“预处理”名义隐藏 CPU 模型推理。
- PC 上 FP32／BF16 参考只用于编译、数值和效果对照，不代表板端生产路径。
- 两塔使用同一训练空间，禁止随意混搭中文文本塔和轻量视觉塔。YOLOE 提示编码器也不能未经验证直接用于中文检索；分词器能编码文本不代表语义有效。
- 量化精度、输入 batch 和向量压缩方式通过实测决定。HBM INT8 与存储向量 INT8 是两个独立误差来源，应分别评估。
- 专用 VPU／PYM／GDC／JPU 优先，剩余支持的图像操作走 GLES。编译经验不替代本模型逐算子执行位置和精度核验。
- 生产部署文件集中在 `ai-service/models/` 对应版本目录；源权重、ONNX、编译中间件、评测集留 SSD 或获准的主机工作区，不混入生产包或 Git。

任一塔不能通过 BPU 与质量门槛，就停止该选型并报告，不能默默改为 CPU 或发布只有图片编码的半成品。

M1 按包核对锁定 revision 的词表、嵌入矩阵、最大长度和算子放置。当前默认 SigLIP2 包为 256000 行嵌入表、S64 `[1,64]` 文本输入，Gemma SentencePiece 无 BOS／dummy prefix、EOS=1、PAD=0，最多 63 个正文词片；超长及不可表示输入明确拒绝。参数量必须结合实际维度计算，不能由词表行数称文本塔为小模型。so400m 等备选保留各自输入契约，不能复用默认包的特殊 token 或向量空间。

校准用代表性现场目标图、上下文、场景和中文查询，覆盖昼夜、逆光、小目标；按视频／会话与评测集隔离并记录清单。现有缩略图不足时补原始证据，不拿小裁剪图冒充完整场景。

代码核对发现 llm-service/src/engine.cpp 的 Engine::Infer 在主机侧进行嵌入查表和输入组装。此为既有实现，不是新模型 CPU 推理的批准。G2 要逐项列出查表、归一化和计算算子的执行位置，不能把查表改名“搬运”绕过约定，也不能未经验证裁剪词表。若需改变硬件执行边界，须明确提出取舍，不按全 BPU 验收。

## 5. 目标关键帧与场景索引

### 5.1 目标索引

只用真实检测帧；预测框不能作为图片证据。低置信度续跟观测须保留来源及质量，不自动等同高质量关键帧。

每轨迹初始上限 8 帧，保留首个可用帧、最佳帧和少量外观／动作变化帧。长轨迹达到上限后有界替换，不能持续追加；变化检测自身的抽样编码也计入预算。未确认的短命目标不进轨迹索引，但场景分支仍可能覆盖。

当前选择使用真实像素支持（面积、可见比例、贴边）代理，不称清晰度。后续候选质量指标包含清晰度、目标面积、边缘截断、遮挡和视角多样性，各分量先归一化再验证权重。框重叠只是遮挡代理，不能等同真实遮挡；不能把固定 3 帧当作各种 FPS 下等价的持续时间。

裁剪保留目标与上下文，尺寸门槛、外扩比例、补边和编码输入从验证集确定，不把原稿 24 像素／1.3 倍视为已验证最优值。关系查询可保留目标特写与上下文两类视图，并计入向量和图片配额。

帧身份需匹配会话、时间、尺寸及坐标变换。没有正确帧则标证据不足，不拿最近一张冒充。

### 5.2 场景索引

本期用低频整帧弥补闭集检测盲区，不只在有检测目标时采样；有限重叠分块作为待验证候选，不默认增加BPU和图片负荷。初始可试活动时 10 秒、静态时 60 秒，变化触发最短 3 秒；均为实验参数，稀疏采样可能漏掉短事件，覆盖与评测必须说明。

整帧加 2×2 分块是候选策略，按小目标效果与吞吐验证。分块命中不自动生成目标类别或轨迹身份。小目标优先评估高分辨率分块保留细节，不盲目放宽质量门槛；分块无法恢复原本缺失的像素。

全景沿用已验证的透视投影与坐标映射；无验证的全景模式显示不可用／部分覆盖，不能靠普通矩形裁图宣称解决畸变。点开的证据须保存投影参数可复现。

检测跟踪频率与建索引频率分离。检索降采样不修改当前检测 FPS、实际时间预测、计数或告警算法。

## 6. 查询、聚合与精排

1. 后端校验会话与通道权限，再规范化查询、限制字节数／实际 token 数、范围、分片和候选数。时间通道以用户显式选择为准。
2. 文本 BPU 编码并按模型／分词器版本缓存。单模板先建立基线；模板集平均仅在改善中文评测后启用，不能假定必然提高效果。
3. 先过滤授权范围，再执行有界向量召回与重算。先采用可验证的精确检索基线；是否启用 Faiss ANN、IVF-PQ 及分片大小由数据量和召回实测决定。
4. 同一会话同一轨迹聚合；对关键帧数设置上限，验证最高分是否偏爱长轨迹，可比较有限 top-m 聚合。场景按事件候选展示相邻采样，但不与独立目标合并为同一审核身份。
5. 禁止凭“同通道 10 秒且相似度 0.95”合并不同人的结果。展示折叠不改变原始事实、计数或告警审核。
6. 跨通道分数和不同视图须评估可比性。背景 z 分数、阈值均是候选方法，不自动赋予概率含义；低分结果可标低相关，不靠未经验证的阈值制造“确定没有”。
7. 返回稳定分页游标和查询版本。延迟复核更新不引起漏项／重复翻页；显式重新排序与当前交互保持一致。

关系、否定、遗留、追逐等描述不能凭关键词就保证单帧判对。提示需要更充分证据；能用验证过的多帧模板才复核时间关系，否则保留候选／无法判断。

精排采用独立模板版本，例如 `search-verify-zh-v1`，描述中明确指定目标／场景和可见证据。目标框、上下文及时间角色保持一致；用户查询是待判断文本，不能覆盖系统判定指令。保存实际输入与输出引用用于追溯。

复用 llm-service 容量校验、错误分类、有限重试和人工优先原则。模型、模板、构图变化后重新标定，告警模板阈值不能直接挪用。缓存键包含模型 SHA、模板、预处理版本、全部证据内容哈希和规范化查询，防止证据更新后沿用旧结论。

现有 image_pipeline.hpp 的预处理目标为宽 896、高 448；实施时核对实际模型包清单，不能由旧包名推断当前模型。尺寸匹配不代表新任务准确：模板、拼图和多帧组织改变仍要做容量校验与独立标定。是否重编取决于模型接口和能力，不只取决于宽高比。

否定／关系关键词可标“建议复核”并在预算内优先处理，但规则只是路由提示，不能保证理解全部表达或免除时间证据要求。

## 7. 保留、删除与重建

检索历史集合与现有逐帧识别历史分开保留；不能因后者短 TTL 使索引立即失去图片。策略同时约束录像、证据保留、索引配额与临时空间。

通过录像服务接口／事件查询分段和删除状态，不直接读写其私有 `segments.db`。只读业务接口也须带授权与边界，不能跨服务绕过管理。

删除采用幂等任务：先使记录对查询不可见，再清理索引投影和历史数据，失败可续跑；保护中的证据按既有保护政策处理。定期对账缺失引用，不能依赖单次事件必达。

索引损坏可从 Mongo 中尚存向量重建；更换模型需要重新编码原图。图片已删除时才按录像身份和时间映射回读；缩略图重编码不等于原始图质量，必须区分数据代次。无法恢复的时段显示缺口，不能标完整重建。

**滚动保留（2026-10-29）**：证据配额（条数／字节）写满时，不再拒绝新样本，而是按采集时间从最旧开始提前淘汰（与到期清理同一删除路径，不写删除意图，不占删除意图上限），直到降到配额的 95% 以下再写入。最近 10 分钟（`evict_min_age_ms`）内的证据永不淘汰；若配额放不下这段时间，仍返回容量不足（硬上限，诚实暴露）。淘汰后同步：投影修订号递增（索引完整性证明失效）、被淘汰通道时段的覆盖记录删除（该时段显示为未确认，不能继续标“已采样”）、已打开的候选列表按到期证据同样处理。模型迁移写入不参与淘汰（仍受硬上限约束）。容量接口新增 `evicted_samples`、`evicted_bytes`、`eviction_runs`、`oldest_retained_captured_ms`，界面据此显示实际回看时长。

旧模型继续服务，新模型在 SSD 配额内重建；不同特征空间不得混排。切换要求目标范围覆盖与质量达标；双版本占用受限，不默认常驻两套 BPU。回滚用已验证模型／索引清单，部署备份遵循每服务最多 3 份和仅 SSD 的规范。

## 8. 资源调度与容量

```text
每天向量数 = Σ(轨迹数 × 平均保留视图数 + 场景采样数 × 分块数)
平均编码需求 = 每天向量数 / 86400
总空间 = Mongo 元数据、图片、向量、索引及存储开销
       + ANN 派生文件 + spool + 重建临时文件 + 允许保留的旧版本
```

峰值按短窗口实测，不把一小时样本外推为可靠全天容量，也不把历史 2.9 秒复核耗时当并发生产保证。量化向量尺度、压缩索引与 Mongo 索引开销都必须计入。

- 分别设置 BPU／ION、CPU、内存、磁盘、每通道队列、全局队列、并发查询和任务 TTL 上限。
- 实时检测和录像受保护；告警复核具有高优先级。文本查询安排有限交互预算；背景图像编码与重建先降级。使用配额与老化避免无限饥饿，不假定跨进程已有统一调度器。
- 非抢占推理仅在任务边界调度。检索请求不能触发无限模型切换；启动前检查模型驻留和剩余内存，不把编码器塞进未经实测的固定 1GiB 预算。
- 超载先暂停重建和额外场景采样，再减少补帧；连首帧／最佳帧也无法保存时如实标缺口，不承诺有限内存下永不丢检索帧。
- 队列、缓存、日志、PG 任务状态、SSD 临时文件均有上限。历史存储不可用不回退 eMMC。
- 遵守已有板级诊断约束，不读取曾触发故障的 `/sys/kernel/debug/ion`；采用已验证的资源观测路径。

硬件优化优先复用已解码帧，减少重复复制和 JPEG 编解码；是否零拷贝以测量为准。批处理设置最大等待时间，不为凑 batch 增加无界延迟。先建立精确检索基线，只有实测瓶颈才引入 ANN；CPU 普通向量检索不必为了“全硬件”搬上 BPU。

容量按“已测试的通道数、分辨率、目标密度、模型组合、检索范围和并发”发布，不预填 32 路所有功能。上线说明同时报告首批结果与精排延迟，不能只报孤立模型速度。

## 11. 验证门槛与实施顺序

### 11.1 评测方式

选独立现场片段，覆盖人员／车辆、颜色、携带物、长尾物体、关系／否定、昼夜、小目标、遮挡、无匹配和全景。先以小而完整的标注集验证可行性，再扩大到数百条查询；无法取得的场景明确列缺口。

按事件标注查询对应的所有正例，标注分歧保留并复核，不只保留容易一致的样本。数据划分防止同视频近邻帧泄漏。

基线 B1：现有类别筛选；B2：低频整帧图文检索；B3：目标＋场景索引但不精排。分别测检测漏失、选帧漏失、向量召回和精排错误，不能只在“已经检出的对象”上报总体召回。

报告事件 Recall@K、nDCG@K、无匹配误返回、时间定位误差，以及首批结果／精排 P50、P95。同时测相关性、量化前后损失与向量压缩损失；前 20 名重合率只是辅助指标，排名稳定也可能同样错误。


### 11.2 用户效果优先于模型跑分

技术门槛之外，增加固定任务的可用性对照：人工拖录像、现有类别筛选、文搜三种方式完成同一查证任务。记录找到有效证据的时间、点击次数、错误目标次数、任务完成率，以及用户是否理解“未找到”和“未分析”的区别。

以“正确完成一次查证所需时间”为主要产品指标，以漏掉关键事件、错误确认、录像影响为约束；不能用搜索次数、复核完成数量或强制自动确认比例代表成功。未经真实使用验证，不称功能为“爆款”。
值班侧测已标注事件漏检和每通道打扰量；管理侧测新增录像缺口、空间增长和清理滞后。它们是共存约束，不把搜索采样漏检与告警漏报混为一项。覆盖透明是可验证的体验目标之一，不是唯一可测优势。
