# 告警证据 MongoDB 存储重构（2026-10-26）

## 设计与边界

告警记录及图片统一由历史 MongoDB 管理，数据库数据目录仍位于外挂存储。录像继续使用录像服务文件。参数库、模型和程序的系统盘部署不变。

`alarm_evidence_images` 每个文档保存一张 JPEG 的 BSON Binary、SHA-256、字节数、发生时间和过期时间。单张上限 8 MiB，避免把多张原图塞入同一个告警文档；告警保存稳定图片引用。列表不加载图片二进制，打开图片才读取并验证内容。无需副本集或跨文档事务。

池分为 crop（告警裁图）、context（关键帧和实际模型输入）、candidate（尚未成立候选）、reference（参考分析输入）。候选不能挤占已成立告警的池配额。沿用现有证据/审核配额；候选默认 128 MiB / 24 小时，参考输入 128 MiB / 7 天。Mongo TTL 与主动清理同时执行；过期图片即使尚未被 TTL 删除也不能读取。

这些是逻辑图片容量限制，不代表 WiredTiger 数据文件立即缩小或数据库总占用上限。日志、索引、数据库自身空间仍需已有存储监视。并发写入可能短暂超出逻辑配额，周期清理会收敛。不能将这些限制宣称为文件系统硬配额。

行为成立、告警持久化不等待截图和审核；图片错误由异步任务处理。写入图片后才发布引用，内容损坏和缺图明确返回不可用。未发布的孤立图片受 TTL 和池容量约束。

## 兼容与迁移

- 新运行入口使用 MongoDB 图片存储；原文件实现保留用于旧证据兼容和回归测试。
- 旧图片按需校验并迁移，成功后标记 storage=mongodb。已经标记的图片丢失时不回退旧文件，防止清理后复活。
- 迁移工具每次最多处理各类 1000 条记录，可重复运行。旧文件不由迁移工具删除。
- 使用与告警服务相同的 bootstrap：

```sh
node alarm-service/src/migrate-evidence-images.mjs <bootstrap.json> --inspect
node alarm-service/src/migrate-evidence-images.mjs <bootstrap.json> --apply
```

inspect 只读；apply 必须在切换到兼容新格式的服务后执行，避免旧进程读不到新引用。迁移遇到过期/缺失图片保留不可用状态，不伪造补图。旧参考分析目录目前保留为回滚资料，不属于此工具迁移范围。

清空告警同时删除截止时间内的图片；写入前后均检查持久化清理水位，阻止并发写入使旧证据复活。行为事实仍遵循原清空契约保留。

## 录像精确补证（已部署）

- 缺少关键帧时，由告警服务异步调用后台内部接口，再由录像服务查找已完成的 AI 输出录像。优先按处理器的输出映射缩小范围；映射未知时有界搜索，不使用原始输入代替 AI 输出。
- 用 SEI 中的处理器、原始 PTS、完整跟踪编号（包含会话）匹配真实观测。零匹配、多匹配、推算和低置信度观测均不能作为补证。录像墙上时间仅用于缩小检索范围，不是身份依据。
- 原始 MP4 包位置传入 VPU 解码作为标识，仅导出相同标识的解码帧；GPU 缩放、JPU 编码。未启用 CPU 解码/图像缩放兜底。恢复全景原帧后沿用事件冻结的热区、框及几何证据生成标注图和模型输入。
- 原帧缓存仍限制 128 MiB；收到关键帧保留请求时优先保护，最长 60 秒，容量满时仍可能淘汰。候选与正式证据使用独立配额。
- 每次最多 8 段、每段 18,000 个视频包；单进程补帧，28 秒总超时，JPEG 1 MiB，上游响应 2 MiB。超时清理进程组及内存盘临时目录；未退出的子进程阻止新任务。
- 只尝试最近 24 小时未审核、证据不完整的告警，每条最多 6 次，退避不超过 5 分钟。补齐且几何证据有效后重新进入原 AI 队列，不直接改成确认。部分成功帧保存在 MongoDB，来源记录保留至下次重试。
- 人工决定、阶段代次、清空水位均校验；旧任务不能覆盖人工决定或复活已清空告警。用户手工清理的残留未恢复。
- 没有录像、没有对应 SEI、录像已循环删除、轨迹证据本身不完整时仍保留人工审核。补证失败不阻止告警生成。
