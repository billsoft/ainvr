## 用户操作与边界

系统配置 → 告警微服务配置 → 告警截图独立保存：

- 显式开启保存新告警的原帧目标裁剪图；不修改 AI 的识别历史保留策略。
- 保留 1–3650 天，容量上限 0.125–1024 GiB；表单初始建议 30 天、2 GiB，未配置时不会自动启用。
- 截图过期或达到容量时，优先清理最早事件的图片；不删除告警、行为事实、确认和审计。
- 关闭后不再入队新图片，已有图片仍按当前策略维护并可读取。等待保存的图片显示暂停，不声称已保存。
- 仅统计的规则不入队独立截图。旧行为不会自动批量补存；仍能精确查询 AI 历史的旧图显示“尚未独立保存”。

行为详情与告警阶段详情显示保存中、独立保存成功、未取得、到期、容量清理或存储异常。保存中自动更新；暂停时停止自动轮询。切换事件或图片版本时，不显示上一次事件/版本的对象 URL。

成功独立保存后，普通识别历史消失不影响这份复制；容量上限仍可能使其提前清理。因此“已独立保存”不表示永久保存。当前都是目标裁剪，不是整幅原图或录像片段。

仪表盘展示独立图片集的已保存、待保存、未取得数量及已用 MiB。这些来自持久化存储，与服务重启后清零的输入计数区分。

## 分工与链路

1. AI 只提供通用原帧身份与图像接口，不新增告警规则或保留策略。
2. 告警消费端完成行为事实和合并告警写入后，按不可变 behavior event ID 幂等入队；故障重放不会重复排队。
3. 告警后台单独取证，核对 channel/session/track/精确 PTS/原帧编号及画面尺寸，只复制该帧声明的 processed/original JPEG。
4. Web 后端保管 AI 凭据。告警服务使用自己的配置服务身份访问只读 `/api/internal/alarm-evidence/:id[/image]`，不持有控制台密码，也不取得其他管理接口权限。
5. 浏览器始终经 BFF 访问行为 ID 对应的图片，优先读取独立保存版本。已独立保存但过期、缺失或未取得时，不用实时画面或附近帧替换。

公开接口继续使用 `/api/alarms/behavior-events/:id/evidence[/image]`。告警内部新增 `/v1/behavior-events/:id/evidence[/image]`。图片需管理接口凭据，生产者凭据无读取权限；BFF 内部源接口只接受 alarm-service 身份的精确 GET 路由，其他服务和已登录用户均无此服务接口权限。

`state=available` 的独立引用携带 pinned=true、retention=alarm、saved_at、expires_at；回退读取识别历史时明确 pinned=false、retention=ai_history。pending/暂停、capacity、retention、capture_timeout、frame_identity_unavailable、stored_file_missing 均独立呈现，不冒充空告警或成功保存。

## 配置、存储与恢复

告警服务参数增加非敏感策略，沿用参数库发布和服务应用确认：

```json
{"evidence":{"enabled":true,"retention_days":30,"max_bytes":2147483648}}
```

`--config-center` 启动方式自动建立专用取证传输。独立私有配置启动若开启此策略却没有受信任的 source transport，会拒绝启动；不静默忽略保存功能。

默认 SSD 目录 `/mnt/ainvr-ssd/ainvr-alarm-evidence/<database>`，只允许部署侧用 AINVR_ALARM_EVIDENCE_ROOT 改为 SSD 下的规范路径。表单和请求不能指定任意路径。根目录须私有、无符号链接，首次须为空；Mongo 持久化存储身份和目录标记必须一致，切换到另一数据库不能接管或清理旧库文件。

Mongo 的 alarm_evidence 保存队列、状态、文件引用与 SHA256；JPEG 为独立 0600 文件。后台串行处理，逐图上限 8 MiB；一组原始/处理后图片全部校验、文件与目录 fsync，再发布 stored 元数据。读取时检查事件/版本文件绑定、常规文件类型、长度和哈希。发布结果不确定时先通过捕获 token 的 CAS 确认归属，不能因响应丢失而删除已经提交的图片。

同目录单写者使用 Linux 抽象域套接字持有权，进程 SIGKILL 后由内核释放；本期部署要求主机服务进程，或使用相同主机网络命名空间，不能把同一目录分配给不同网络命名空间的并发写者。[Node 官方 IPC 说明](https://nodejs.org/docs/latest-v24.x/api/net.html#ipc-support)记录了抽象套接字支持。

重启确认单写者后，将未完成 capture 恢复为 pending，清理仅符合自身文件命名且无已发布引用的孤儿图。陌生文件、符号链接、硬链接或存储身份冲突会报错，不能递归删除目录或接管数据。删除中断可以再次执行。每次清理有数量上限，SSD 余量不足时不继续写满磁盘。

取证队列以最多约 10000 个等待/处理中项目限流（并发入队时可能有少量超出）；超量记录显示未取得，不阻断行为事实的保留。单项最多 20 次尝试、15 分钟取证窗口，失败逐步退避。源归档还没落盘时可重试；超过窗口明确失败。保留期限基于事件时间，积压旧事件不会额外延长图像保留期。
