# AINVR search-service

开发状态（2026-10-28）：配置、持久存储、受限传输和搜索页面已实现；真实采样、配对 BPU 编码器及持久索引仍在开发。尚未部署生产检索服务。

设计依据为 `../docs/AI-TEXT-SEARCH-DESIGN.md`。本目录使用 C++17／CMake，
复用现有原生服务路线，不引入新的数据库或推理框架。

## 已实现

- `src/vector_index.hpp`：有界、同模型版本的精确余弦检索基线；
  先过滤通道和半开时间范围，再按通道、处理器、会话、轨迹聚合。
  不同目标不能因时间接近或外观相似合并，场景记录独立。
- 控制台 `/api/search/status`、`/channels`、`/text`、`/coverage` 的鉴权与
  请求范围校验；尚无真实 worker 时查询和覆盖返回 503，不返回虚构空结果。
- 控制台搜索条件、结果网格、证据详情、关键帧切换、反馈和分页接口；
  复用 AuthImage 与共用录像导航。取消后的迟到结果不会覆盖新查询；
  复核更新保持卡片顺序，已有结果后收起范围设置。
- 结果和图片接口在每次访问时核对范围与图片归属；缺图、覆盖未知和
  无录像分别提示，不伪造空结果。
- Mongo 原生存储 `history_mongo.*`：普通集合、单文档图片／向量／元数据提交、
  哈希校验、到期与配额、稳定增量序号、覆盖记录及持久删除意图。
- `index_projection.hpp`：从历史恢复有界内存投影；重建失败保留旧状态，
  过期或已删除的证据不能继续从内存结果返回。
- 帧身份复用 `observation_evidence.hpp` 的校验和原字段（会话、PTS、帧号、原图尺寸），
  同时明确保留原始输入、AI 输出和录像通道。
- `http_service.*`：原生内部接口库，包含受鉴权的状态、样本提交、图片、覆盖区间、
  范围删除及文本匹配计算端口；新增 `ainvr_search_service --managed-config <私有配置文件>` 启动入口，安装与部署仍待完成。
  未绑定编码器／索引未加载／历史库不可用分别返回真实未就绪状态。
- `searchNativeClient.ts`：控制台到原生接口的传输适配，复用抽出的
  `internalServiceHttp.ts`（原告警代理的本地地址与响应限制）；校验模型、
  通道、时间、帧身份及图片大小。
- Mongo 查询快照：短期 TTL、有界数量、首个发布顺序固定、反馈独立更新，
  取消早于提交也会阻止迟到发布；随机代次拒绝过期查询的旧写入。
  槽位绑定完整证据指纹，缺图／过期后 ID 复用不会把新图挂到旧结果。
  分页按原始槽位推进；删除证据后整条查询保持部分覆盖。
- `persistentSearchWorker.ts`：真实快照查询、稳定分页、详情、图片、反馈及取消适配；
  每次访问复查权限，图片由快照归属在原生侧原子校验。
  `searchRecordingAvailability.ts` 复用录像服务业务接口核对分段与实际可读性，
  未闭合段与探测失败保留待确认，不将“有分段元数据”当成一定可播放。
- `model_package.*` 统一候选包、明确 program/tensor 契约、流式文件校验、分词器／映射版本与持有文件身份。
  加载边界还会复核内容摘要，不能仅凭 inode／大小／时间戳判断原地改写；摘要不放进逐帧或查询路径。
  元数据批准声明不是 G1／BPU／ION 验证；目录不会因为文件存在就报告就绪。
- AI 的 `SearchSamplingPolicy` 复用已有 analytics session，显式绑定后拒绝旧帧／旧 ACK；
  首帧、最佳帧和变化槽仅在存储 ACK 后更新，场景分支独立于目标确认状态。
  当前是有界纯策略，还未接入生产原帧、硬件编码和 producer 提交。
- AI 既有 `ArchiveExecutor` 新增非阻塞 `TrySubmit`，搜索后台工作拒绝时不等待实时线程；
  仍须接入采样策略与全局帧引用／BPU 预算，不能据此宣称采样链路已完成。
- PG 迁移 `017_search.sql` 与 `SearchJobs`：有界幂等准入、租约、重试上限、
  取消和完成代次校验。仅在隔离测试库执行，尚未应用生产。

## 当前存储实现边界

- 同一历史命名空间只允许一个拥有写入权的 search-service 进程；进程内串行保护配额与写入顺序。
  生产启动与部署必须保持此约束，当前不支持多个搜索实例并发写同一命名空间。
- 原始向量暂存 `f32le`，用于保真基线。FP16 编码要通过模型任务指标验证后单独切换版本；
  不因模型权重 INT8 就把存储向量也当作已验证 INT8。
- `max_bytes` 限制 BSON 记录体积，Mongo 索引、日志和文件系统开销须在外部存储配额另留余量。
  图片、覆盖、删除意图均有保留期或数量边界；不使用 capped 集合悄悄覆盖证据。
- 投影当前是可恢复的内存实现，不代表 SSD 分片索引已经完成；未加载窗口与资源降级如实标部分覆盖。
- 查询快照只保存请求、最多 60 个引用槽位和反馈；不复制图片或向量，不替代 PG 后台任务。
  默认请求快照保留一小时，存储强制最长一天；默认 1000 份，取消占位也计入配额。
  正式启动配置和受限 producer 权限已接入；部署服务、AI 实际采样和模型执行仍待完成。
- HTTP 使用锁定的官方 cpp-httplib v0.63.0 header-only，SHA 和许可证见 `../third_party/cpp-httplib/README.AINVR.md`。
  系统旧 0.10.3 的 multipart 拆包缺陷已有严格同体对照复现；新搜索目标不再链接该旧 `.so`，不全局升级其他服务。
  复用上游有界工作池，删除原型 `BoundedHttpQueue`；四个线程＋最多四个排队连接，队列满由上游关闭未接受连接。
  报文／读写均有上限，匹配计算只允许一个执行者，忙时 429；Web 查询默认全局 2、同用户 1，超限直接拒绝。
  持久任务排队仍归 PG 管理，不在 HTTP 内另建任务权威。
- 原生测试脚本只在回环端口 25440 启动临时 Mongo，结束清理容器及其匿名数据卷；
  测试使用独立数据库，不访问生产历史数据。普通 CTest 未设置测试标志时会 SKIP 历史测试，不能算已通过。

## 采样接线约束

- 最小钩子在 `ReusedChannelWorker::InferOneFrame` 的 `FrameAnalytics::Apply` 之后；
  复用原 `FrameRef`，只选本帧 confirmed／detected 跟踪与真实 detections 的交集，不拿推算框充证据。
- `FrameResult.channel_id` 是处理器 ID；来源 UUID 复用后端现有来源解析并随配置版本冻结下发。
  时间取 `CapturedFrame.captured_wall`／原始 PTS，不把推理结束时间当成帧获取时间。
- 搜索使用共用执行器的非阻塞入口；`SearchWorkBudget` 在跨通道共享 owner 上限制排队及运行任务总数和保留字节。
  在保留原帧前取得 RAII 票据，降限／禁用不遗忘旧代任务仍持有的字节；8K 帧引用不能无限排队。
  预算组件通过并发和 sanitizers 软件验证，worker 的真实投递接线仍待完成。
  场景采样独立于检测目标数量；投递失败记录覆盖缺口，不消耗已保存的首帧名额。
- 裁剪／透视复用 SnapshotPlan、坐标变换及既有硬件预处理；`SnapshotRenderer::RenderOriginal`
  仍有 CPU JPEG 回退，不能直接作为搜索的全硬件路径使用，须明确 fail-closed。
- 模型加载扩展既有驻留契约；现有 LLM reservation 不是完整跨进程优先级调度器，不另建一套无关锁。

## 配置与采样权限

- 系统配置增加“智能搜索”，复用既有保存、发布、应用确认、草稿保护及外挂存储选择。
  默认关闭，首次保存由后端生成独立 console／producer 密钥；模型候选不会自动获得生产批准。
- native 复用 `shared/cpp/config_center_client.hpp`；LLM 也使用同一传输，保留原有模型配置规范。
  bootstrap 必须为私有普通文件，管理连接仅本机，响应／层级／读写有界。
- `/api/internal/search/runtime-config` 仅搜索配置身份可读；依赖取自已应用的 AI 历史配置。
  ACK 同时核验 desired version 与 dependency revision；监听器就绪后、ACK 成功前不开放业务请求。
  ACK 失败立即关闭该代；配置中心长期失联时撤销旧映射，不无限接受过期配置。
- AI 已复用配置轮询读取专属 `/api/internal/search/producer-config`，23 项客户端测试通过。
  授权从请求起点最多有效 30 秒，关闭、失效、同版本内容变更和 Stop 会撤销旧 lease；
  同版本正常续期保留采样状态，准备和提交前须各检查一次 `lease.IsCurrent()`。采样请求绑定配置 revision，
  console 不能提交样本，producer 不能查询、删除或读取管理元数据；管理身份仅可读模型目录。
- 对象通过 `/v1/samples/slot` 单文档 CAS 替换固定 0–7 槽，丢 ACK 重试幂等。
  来源、会话和轨迹身份不可更换，帧号／PTS 必须前进；过期和删除墓碑阻止重放。
  分数、短名单和图片绑定 fingerprint；证据替换后旧结果明确变为部分覆盖，不能串成新图。
- 槽位存储不等于采样已经接入：AI 还须核对实际 FrameResult 源／输出配置与既有源代次，
  冻结原帧身份，并在数据库确认后才更新采样名额；不直接复制旧 grant 的 UUID。
- 外置磁盘配置当前是目录定位契约；安全打开、实际 SSD 分片索引与恢复仍待完成。
  证据容量限制针对 Mongo 的图片、向量和元数据，不包含数据库索引、日志或原录像。
- 两个原生测试入口共享构建／端口锁，防止并行重写静态库或抢占测试 Mongo。

本轮验证：原生 9 组（含真实 Mongo、8 槽 CAS、HTTP 权限、查询代次、配置传输、模型包、分词金标与 Unicode）全部通过，无跳过；
后端搜索专项此前 62 项通过，新增动态准入修复后 worker 专项 28 项及类型检查通过；配置／权限／PG 迁移另有专项回归。
采样策略一个测试程序通过 671 条状态断言；字节布局 13 项通过（含完整词表 S64 与原 CLIP S32 兼容）。
测试使用合成编码器，未操作 BPU、未修改 ION 规程、未执行生产迁移或提交代码。

## 完整词表默认档的分词验证

- 默认 so400m 文本塔使用真实 SentencePiece、HF 4.46.3 导出语义和 Unicode 13 大小写规则。
  原 128 条评测加 39 条边界输入中，162 条可编码输入逐 ID 一致，另 5 条按明确原因拒绝；
  有效 Unicode 标量的大小写与空白规则另作全量一致性核对。
- 原始词表有 250100 个词片，HBM 嵌入表只有 250000 行；尾部特殊词片不能输入 HBM。
  超范围词片、超过 63 个正文词片等情况明确拒绝，不换成 unk、不静默截断。
  这些输入错误经原生 HTTP／后端传递为 400 和明确改写提示；运行错误仍为 503，不暴露底层异常。
- tokenizer 软件构建固定依赖提交及许可证，运行链接使用系统 ICU 70；
  只读参考源码位于 SSD 不代表运行库依赖 SSD。上述验证没有加载 BPU 模型。
- ION 结论以用户最新实测为准：文本塔可与 Qwen 常驻；完整双塔组合未通过 512 MiB
  试分配余量。物理加载成功与现有静态登记准入不同，尚未修改生产排他锁或预算规则。
