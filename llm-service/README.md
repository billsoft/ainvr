# AINVR 图片复审服务

当前状态：2026-10-22 已发布图片复审基础服务，模型常驻就绪；已验证单路检测共存，双路及截图归档负载未验证。完整范围与发布条件见
`../docs/S100P-LLM-SERVICE-DESIGN.md`，进度和内核事故见
`../docs/S100P-LLM-SERVICE-PROGRESS-20261022.md`。

## 服务边界

本服务只提供固定模板 `alarm-review-zh-v1` 的图片复审分数，不读写告警、
计数器或录像记录。调用方决定复审阈值、失败处理和告警生命周期。
调用方以独立名称与密钥鉴权，不限定只能由告警服务调用。

模型包当前不具备自由对话、生成式流式输出、工具调用能力；请求这些能力
必须明确失败。未来增加模型适配器及经过验证的能力后，才可扩展接口。
当前 OpenAI 兼容范围是模型列表、错误格式及决策扩展，不代表完整 Chat API。

## 调用约定

- 地址：`http://127.0.0.1:8300`，不对外监听。浏览器使用控制台代理。
- 认证：`Authorization: Bearer <调用方密钥>`。管理与推理密钥分开。
- 主接口：`POST /v1/ainvr/tasks/alarm-review-zh-v1`。
- 图片：base64 编码的 baseline 8-bit 4:2:0 JPEG，宽高比 2:1，偶数尺寸，
  最小高度 64、最大 8192×4096；不静默裁剪、旋转或拉伸不合规格的图像。
- 请求包含 `image.jpeg_base64`、`alarm.kind`、`alarm.description`，可带
  `request_id`。编号用于关联结果，**不是服务端幂等键**；调用方自行避免重复业务入库。
- `real_score` 是是/否两个决策 token 的条件分数，不是校准概率。
  告警服务不得直接采用通用 0.5 阈值而不验证自己的业务样本。
- 响应包含模板、模型包 SHA256、校准温度和耗时。当前 `validated=false`，
  独立集质量通过不等于现场业务阈值获批，本期不自动处理生产告警。

Python OpenAI SDK 的决策扩展调用形式（3.36.1 已实测；Node SDK 7.42.0 亦已实测）：

```python
result = client.chat.completions.create(
    model="qwen3vl-4b-review-v3",
    messages=[],
    extra_body={"ainvr": {"decision": review_request}},
)
review = result.model_extra["ainvr"]
```

不要发送 `stream`、生成温度、`top_p`、生成长度、`tools`、`logprobs` 等
生成式参数。配置中的温度仅改变两侧决策分数的校准，不是采样温度。

## 状态与失败

`/health` 用于采集助手；管理密钥可读 `/v1/status`。进程启动不等于模型就绪。
状态接口报告模型状态、已应用配置版本、活动请求、队列、按调用方结果计数及
最近 256 个已结束任务的端到端耗时分位；耗时包含排队，不能当成纯 BPU 时间。
未进入工作线程的鉴权失败、队列拒绝和已取消排队请求不计入完成任务统计。

配置在模型达到要求状态后确认；失败保留此前已应用版本。管理卸载在有活动
请求或排队请求时返回 busy。禁用配置与服务停止会取消排队任务，并在硬件调用
间隙取消当前任务，不会中途释放硬件正在使用的内存。

大模型使用共同的驻留排他锁：Qwen 与 LocateAnything 不同时加载。预算采用官方接口查询的专用池总量，扣除固定 1 GiB 其他服务预算与 512 MiB 余量；加载后再试分配余量。试分配不是实时剩余量测量，也不能代替视频通道共存测试。失败时释放本次资源，保持原服务；可在配置页重试加载。
禁止读取 ION debugfs 诊断目录；fdinfo 仅是进程持有量下限。

## 验证与发布

构建产物、中间数据、模型包均放 SSD；仓库只保留源码、测试、文档和清单。
`tests/test_http_control.py` 与 `tests/test_config_roundtrip.py` 不加载模型，
仅启动有限时间的隔离 HTTP 进程。`tests/test_tokenizer_corpus.py` 验证
10 万条完整模板分词，不加载 BPU 模型。

硬件测试必须串行、有时限、在 finally 中恢复原服务状态。已通过跨语言互斥、
加载/卸载/重新加载、559 张独立 JPEG 质量验收、Python/Node SDK 任务调用、
断连后有界清理与恢复、有界队列拒绝与超时恢复。559 张与 BF16 判定一致率
97.67%；其中有业务标签的 408 张准确率 89.22%，两者不可混称。
一小时稳定性与视频共存正在复测，完整部署和浏览器验收以进度文档为准。
不得以单元测试通过代替这些发布条件。

服务单元设置 `MALLOC_ARENA_MAX=2`，限制多线程分配缓存膨胀；这不限制
BPU 专用内存，也不改变模型。原默认分配器压力实验的内存持续增长记录保留。
模型专用内存与进程 RSS 是不同口径，不可把 RSS 当作模型总内存。
配额表示十秒窗口内硬件任务提交/等待时间占比，不是硬件隔离承诺。
持续复审会影响实时检测速度；调用方应限制请求频率，并处理 429/504。
运行期必须同时观察检测实际帧率，不得仅凭大模型 ready 判断整机容量达标。

## 后续微服务接入

每个调用方单独配置推理密钥，管理密钥不提供给业务调用方。不将密钥放进
URL、前端代码、请求日志或 Git；控制台试用通过后端代理使用 console-try。
模型包由设备管理员安装并校验，本期不接受调用方指定任意模型路径。

最小任务请求（JPEG 字节由调用方按上述规格准备）：

```json
{
  "request_id": "业务请求关联编号",
  "image": {"jpeg_base64": "JPEG 文件的 base64 内容"},
  "alarm": {"kind": "火情", "description": "检测模型认为画面中出现明火"}
}
```

调用方应保留原始证据和本次结果，包括模型包 SHA、模板、校准温度与分数。
超时或失败属于“未取得复审结论”，不得解释为“没有风险”，也不得自动删除
已有告警。服务不保存图片、业务记录或调用内容，不提供 exactly-once 业务语义。

| 返回 | 调用方处理 |
|---|---|
| 200 | 读取任务结果；由业务侧采用经过独立验证的阈值 |
| 400 | 修正图片/文本/能力参数，不原样无限重试 |
| 401 | 检查调用方密钥，避免在日志里输出密钥 |
| 429 | 队列已满；有界退避，业务截止时间到达后报告未复审 |
| 503 | 模型未就绪或推理失败；保留原证据和原业务状态 |
| 504 | 已超过排队/执行期限；不能当作否定结论 |

调用方超时应覆盖配置的排队时间、执行时间与传输余量；服务有界执行，
客户端断开后仍可能完成已提交的硬件工作，不能将断开连接等同于立即释放 BPU。
集成告警业务前先测真实截图规格、误报/漏报阈值、请求峰值及视频共存负载。
先限制请求频率，再按检测帧率与队列指标调整提交配额，避免持续压满单核 BPU。

## 运维入口

- 配置：系统配置 → 大模型微服务；保存后等待版本应用确认。
- 观察：仪表盘 → 大模型监视；进程在线但模型未加载仍不可执行任务。
- 恢复：解决与开放词汇试用模型的驻留冲突后，使用“重试加载”。
- 卸载：取消启用并保存，等模型状态为未加载；不要凭页面提交成功就假定内存已释放。
- 发布：首次安装与后续更新脚本分别位于 deploy-package/install-llm-console-s100p.py
  和 deploy-package/update-llm-s100p.py；后者检查独立集、长测证据及候选哈希。
  不绕过验收断言，不把旧二进制的报告套用到新二进制。
