# AINVR 国标外置网关部署边界

同机安装是默认拓扑。外置部署仍使用相同网关、媒体组件与控制台接口，
不把参数库、录像服务或另一套 SRS 搬到网关，也不修改已有摄像头输入。
本文描述部署要求；仓库中的模拟验收不等于两台物理设备或公网穿透验收。

## 两条独立连接

```text
AINVR Web 后端 ── 已验证 HTTPS + 服务令牌 ──> 外置网关控制接口
外置网关/媒体桥接 ── 受限加密转发 ──> AINVR SRS 的发布和状态接口
摄像头 ── 可路由 SIP/RTP ──> 外置网关/媒体接收器
```

系统配置中的网关地址只改变第一条连接。网关运行配置中的 ZLM、RTMP 和
SRS 查询地址继续限定为本机回环；外置主机必须由部署层提供下面两条转发：

| 外置主机监听 | 加密转发目标（AINVR 主机） | 用途 |
|---|---|---|
| `127.0.0.1:1935` | `127.0.0.1:1935` | 媒体桥接向现有 SRS 发布 |
| `127.0.0.1:1985` | `127.0.0.1:1985` | 核对真实发布状态与帧推进 |

这些外置回环端口须未被其他服务占用。禁止为方便外置部署而放宽面向摄像头
的 RTSP 地址校验，或直接向外网暴露 SRS API、ZLM API 和参数数据库。

## 管理连接

- 外置代理用 HTTPS 反向代理到网关的回环管理接口；校验证书链和主机名。
- 公有可信证书可直接使用；私有 CA 应安装为后端受信 CA，或通过该后端
  服务专用的 `NODE_EXTRA_CA_CERTS` 配置，不修改所有程序的 TLS 校验行为。
- 保留 `X-Service-Token` 验证。TLS 失败和令牌错误分别诊断；不在 URL、
  普通日志、截图或导出配置中包含令牌。
- 外置 SIP 标识、SIP 公告地址和媒体公告地址应填写摄像头能访问的外置
  网关地址，不填写 AINVR Web 地址，也不把 HTTPS 地址误当 RTP 地址。

## 受限 SSH 转发

AINVR 主机使用独立转发账号及独立公钥，不复用管理员 SSH 身份。私钥仅在
外置网关保管；公钥目录按 OpenSSH 权限要求归属，不关闭 `StrictModes`。
该账号仅允许公钥认证、本地转发及上述两个目的地址；禁用会话、终端、
代理转发和 X11。可在专用 `Match User` 中限制：

```text
AuthenticationMethods publickey
AllowTcpForwarding local
PermitOpen 127.0.0.1:1935 127.0.0.1:1985
MaxSessions 0
PermitTTY no
AllowAgentForwarding no
X11Forwarding no
```

账号及密钥配置还应按现场 OpenSSH 版本验证。客户端使用固定的受信
`known_hosts`、`StrictHostKeyChecking=yes`、`IdentitiesOnly=yes`，通过
`-L` 建立两个仅监听回环的转发。配置 `ExitOnForwardFailure=yes`、保活和
有界重连；以独立服务托管，停止时回收转发进程，不写无限增长日志。

`ExitOnForwardFailure` 只证明本地转发监听建立，不证明远端 SRS 工作。
健康检查仍核对 SRS API、实际发布和媒体帧，不能仅检查 SSH 进程存活。
`MaxSessions 0` 可拒绝 shell/exec 会话并保留受限转发；不要用正常 shell
账号代替这项限制，也不要使用 `StrictHostKeyChecking=no`。

摄像头到外置网关的 SIP 与 RTP 网络须另行可达，包含实际选择的 UDP、
TCP 主动或 TCP 被动角色。本方案不承诺任意公网 NAT 穿透。

## 配置、恢复与回滚

设备、目录映射和凭据仍由 AINVR 参数库管理，外置网关仅保留运行会话。
配置保存经版本核对后应用；关闭网页不停止取流。管理断开与媒体断开分别
显示，恢复连接保留原输入 UUID；媒体会话变化继续重置既有轨迹连续性。

先建立受信 HTTPS 和两个转发，再保存全局外置地址和设备配置；先启用一条
测试输入，验证带声音录像及恢复后再增加通道。迁移已有国标会话要安排
明确停启，避免旧、新网关同时点播或争用同一发布流。回滚恢复原网关设置，
只停止新增组件，不删除映射或历史、不重启现有 SRS 来掩盖接入失败。

## 可复现验收

`test/gb28181/external_acceptance.py` 建立真实隔离网络空间、独立 HTTPS
代理和临时受限 SSH 服务。它使用已编译的生产后端配置映射器、真实 Go
网关/ZLM/媒体桥接/隔离 SRS，以及现有录像命令；参数库使用假适配器，
不读取或修改生产设备。测试 CA 仅注入该子进程，不改变主机信任设置。

两组场景为 2016 TCP 信令/H264/AAC 和 2022 UDP 信令/H265/G711 A-law，
媒体均为网关被动 TCP。检查错误令牌、真实证书拒绝、禁止 shell、禁止
未授权转发地址；中断媒体转发后确认 SRS 确实失去发布，同时 HTTPS 可用，
重建后须在 60 秒内恢复。恢复前后各录制 8 秒，验证压缩视频身份和真实
声音，偏移不超过 200ms、有界片段漂移不超过 50ms。

测试 SSH 的固定公钥命令仅用于隔离夹具目录的权限安排，不能作为生产
root 登录配置示例。测试只创建自有网络空间和隔离容器，不修改物理网卡、
现有 SSH、防火墙或生产 SRS。完整复现命令见 `test/gb28181/README-SIMULATOR.md`。

可选 `--network-profile bounded-lan` 对隔离媒体链路设置丢包率 0.001、
单向延迟 150ms、抖动 ±25ms。每个版本都必须实际观察到丢包，并在受损
阶段另外录制八秒，使用相同内容判据。R12 两版已通过；各观察到一次
注入丢包，恢复分别约 23.625/23.016 秒。此项是有限模拟链路恢复测试，
没有测得物理网络质量或采集至屏幕显示的完整延迟，不作为 §5.3/§5.5 认证。

这证明受保护外置拓扑的模拟链路，不证明全部媒体角色、真机厂商兼容、
物理外置主机容量、长期 WAN 网络或国标全标准认证。

连接限制依据 [OpenSSH sshd_config](https://man.openbsd.org/sshd_config) 与
[ssh_config](https://man.openbsd.org/ssh_config)；HTTPS代理按
[Nginx SSL模块](https://nginx.org/en/docs/http/ngx_http_ssl_module.html)
配置。部署时仍须核对现场实际版本，不复制滚动文档中的过时密码套件。
